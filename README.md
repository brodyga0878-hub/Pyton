# Звёздный рубеж — восстановление StarFrontier

Ветка `development/starfrontier-rebuild` содержит **новую запускаемую основу** нативного Android-проекта на Godot 4.6.3. Она собрана из частично восстановленных исторических модулей, повторно извлечённых исходных данных FFE и заново написанного недостающего кода. Полный прежний проект и APK версии 0.10.8 не найдены.


Текущий кандидат — **0.18.0-landing-gear-alpha1 / code 43**:
[управляемое шасси, консоль и посадочный контакт](docs/RELEASE_0_18_0_RU.md).
Исходные F1008 и выбранная ветвь F1056 управляют раздельными запросом
и физическим положением шасси. Добавлены сохраняемая сессия механизма,
центральная кнопка классической консоли и связь трёх стоек корабля
с фактической долей выпуска. Атмосферный F1014 получает исходный бит
запроса; полная готовность к посадке проверяется отдельно.

Для исходного мира посадка требует полного выпуска и запроса «выпущено».
У поверхности действует явно указанное мобильное правило ожидания,
сохраняющее возможность подняться и уйти в сторону; полным F575 оно
не объявляется. Старое сохранение без шасси получает безопасное начальное
состояние по контексту, а уже сохранённое промежуточное положение
проверяется строго. Финальный функциональный итог — **51 431 условие
в 28 уникальных группах, 0 ошибок**. Отдельно прошли **189 Python-тестов**
(179 упаковки и десять извлечения). Восемь настоящих кадров Main сняты
и осмотрены: **196 условий захвата, 0 ошибок**, desktop GLES/Mesa

## Запуск и проверка

Открыть `project.godot` в обычном Godot 4.6.3 и запустить сцену. На машине с недоступным домашним каталогом задайте доступные `XDG_DATA_HOME` и `XDG_CACHE_HOME`.

```sh
python3 tools/validate_rebuild.py
godot --headless --audio-driver Dummy --path . -- --rebuild-smoke
python3 tools/setup_android_toolchain.py
sh tools/build_android.sh --candidate
python3 tools/verify_rebuilt_android.py build/starfrontier-rebuild-arm64-alpha.apk build/android-verification.json
```

Встроенная сквозная проверка не читает и не перезаписывает пользовательский прогресс. Тесты математики и таблиц используют независимые контроли исполнения исходных процедур; это не доказательство готовности всей игры. Аппаратные FPS и нагрев нельзя определить по этим проверкам.

Сохранения этой сборки используют `starfrontier-rebuild-game-v1`. Старый полный формат и оригинальный COMMANDR пока не импортируются. В меню есть резервная копия в виде кода для сохранения вне приложения. Пакет `org.starfrontier.rebuild` устанавливается рядом с прежней версией; подпись пока тестовая.

Исторический план содержит пять крупных блоков: **9 → 11 → 12 → 13 → 14**.
Это номера направлений работы, а не срок или процент готовности 100% клона;
дальнейшая приёмка следует реестру исходного поведения в новом аудите.

Радиусы, массы, гравитация и вращение поверхности продолжают использовать явный SI-адаптер. ZIP-отчёт содержит выбранный расчёт орбит и по галочке — полное сохранение нового мира. [Изменения, проверки и границы](docs/ORBIT_0_11_10_RU.md).

В0.11.11: исходные положения всех 17 орбитальных портов подключены к новым полётам через отдельный кадр мира v3. Цель дока, автопилот, столкновения, стыковка и вылет используют одну локальную точку, а планета расположена относительно исходной орбиты порта. Исправлены сохранения после спуска с орбитального порта и последующего перелёта. Старые v1/v2 сохраняют свои параметры и кадры. Исходная F603 и F1511/F1512 проверены отдельно; живая гравитация пока использует прежний SI-адаптер из-за доказанных особенностей исходного расчёта. [Границы и проверки](docs/PORTS_0_11_11_RU.md).
