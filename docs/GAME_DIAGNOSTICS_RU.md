# Локальный архив отчёта об ошибке

`scripts/game_diagnostics.gd` собирает диагностический ZIP без сетевой отправки. Пользователь сам сохраняет/передаёт получившийся файл через отдельный экспортёр и может прикрепить его к чату. `scripts/diagnostics_logger.gd` подключается через настоящие `OS.add_logger`/`OS.remove_logger` Godot4.6.

## API и подключение

```gdscript
var diagnostics = preload("res://scripts/game_diagnostics.gd").new()
add_child(diagnostics)
diagnostics.initialize(build_version)
diagnostics.record("jump_started", {"destination": destination_id})
diagnostics.lifecycle("paused")
var report = diagnostics.build_report(description, diagnostic_context,
    include_save_checkbox.button_pressed, current_game_payload)
# report.ok, report.path, report.absolute_path, report.filename,
# report.report_bytes, report.included_save, report.error
```

Инициализация только явная: `add_child` не начинает сбор и не меняет пользовательские файлы. Главный контроллер запускает её до построения мира и отключает для автоматических тестов/съёмки. `shutdown(true)` и выход узла штатно закрывают сеанс и снимают logger. События пишутся на диск раз в5 секунд, а также при паузе, сборке отчёта и завершении. `build_report` вызывают в главном потоке: чтение сведений рендера не предназначено для произвольного worker-thread.

Параметры каталогов для изолированных тестов: `directory`, `reports_directory`, `engine_logs_directory`. Все должны находиться внутри `user://`; `..`, абсолютные пути и каталоги ресурсов отклоняются. По умолчанию это `user://diagnostics`, `user://bug_reports`, `user://logs`.

## Что попадает в ZIP

- `report.json`: версия сборки, версия Godot/ОС, модель устройства, драйвер/метод отрисовки, GPU, размер окна, использование статической памяти, диагностический контекст и сведения о сеансе.
- `description.txt`: введённое описание ошибки, до8000 символов.
- `settings.json`: только разрешённые настройки графики и управления.
- `events/current-events.jsonl` и, при наличии, предыдущий сеанс: сообщения, игровые события, настоящие ошибки движка/GDScript и имена функций/файлы/строки стека.
- До3 последних `godot*.log` из фиксированного каталога, если такие журналы остались от предыдущей сборки или специально включены разработчиком.
- `game-save.json` появляется **только при явном включении снимка полёта**. Переданный словарь не изменяется; неполный, неподдерживаемый или слишком большой снимок отклоняется.
- `manifest.json`: размер и SHA-256 каждого содержательного файла. После закрытия ZIP все записи снова читаются и сравниваются с исходными байтами до атомарной публикации архива.

Сборщик не читает всё файловое дерево, окружение процесса, аккаунты, уникальный идентификатор устройства или значения переменных стека. Ключи учётных данных исключаются из контекста и событий; известные пути приложения заменяются `user://`/`res://`. Полный игровой прогресс передают отдельно от диагностического контекста и только по выбранной пользователем опции. Снимки экрана автоматически не собираются.

## Ограничения размера и сбои

В памяти и в текущем собственном журнале сохраняются максимум256 записей/256KiB. При переполнении отбрасываются старейшие; счётчик потерь включается в отчёт. Предыдущий собственный журнал также ограничен256KiB; каждый доступный нативный лог берётся только хвостом до256KiB. Повреждённый UTF-8 исправляется до декодирования, без порождения новых ошибок Unicode во время сборки.

Снимок игры ограничен2MiB, весь несжатый отчёт —4MiB, итоговый ZIP —8MiB. Сохраняются5 последних собственных ZIP; посторонние файлы не удаляются, новый отчёт защищён от удаления даже при изменившихся системных часах. Временный файл не выдаётся за успешно созданный отчёт. Ошибки записи не затирают предыдущие архивы.

Маркер сеанса заранее содержит `clean_exit=false`. Следующий запуск сообщает о незакрытом сеансе. **Это не диагноз аварии:** причиной могли быть сбой, принудительная остановка, выключение или обычное завершение фонового приложения Android. Повреждённый маркер отмечается как неизвестный, а не как выдуманная авария.

Нативный файловый лог Godot по умолчанию следует отключить: в официальном [Godot4.6.3 `RotatedFileLogger::logv`](https://github.com/godotengine/godot/blob/4.6.3-stable/core/io/logger.cpp) нет ограничения размера активного файла, а `max_log_files` ограничивает только число резервных файлов. Собственные журналы сборщика ограничены и захватывают ошибки после его инициализации. Вывод до инициализации, native tombstone, системный logcat и ошибки после жёсткого завершения процесса могут быть недоступны. Для строк GDScript-стека в release-сборке существует `debug/settings/gdscript/always_track_call_stacks`; это отдельная настройка контроллера сборки.

## Фактическая проверка

`tests/test_game_diagnostics.gd` выполнил **71 проверку без ошибок и утечек**. Проверены содержание и хеши настоящего ZIP, русский текст, повреждённые/крупные логи, размер/число записей и архивов, приватные пути, сохранность посторонних файлов, явное включение прогресса, отказы записи, предыдущий сеанс и повреждённый маркер.

Особая проверка запускает отдельный минимальный Godot-проект, вызывает настоящий `push_error` и настоящий ошибочный доступ к ключу GDScript, затем проверяет их присутствие в созданном ZIP. Вывод дочернего процесса перехватывается: намеренные ошибки не маскируются под чистый вывод основной группы и не становятся ложными ошибками общего валидатора. Значения локальных/глобальных переменных сборщик не запрашивает.

```sh
XDG_DATA_HOME=/workspace/rebuild-test-state/data \
XDG_CACHE_HOME=/workspace/rebuild-test-state/cache \
godot --headless --path . --script tests/test_game_diagnostics.gd
```

Это проверка сборщика и реальных callback-ошибок в desktop Godot. Передача файла через Android SAF, интерфейс и физический S23 Ultra проверяются отдельно.
