# Полный исходный конструктор звёздных систем F877/F878/F896/F897

Реализован отдельный `SourceSystemBuilder` для нового семейства мира. Он создаёт исходную иерархию одиночных и кратных звёзд, барицентров, планет, лун и портов, включая населённые ветки F883–F887, процедурные имена F893 и поселения F891/F892. Старые `SourceBodyFactory.construct()` и шестидесятизаписный конструктор сохранены; новое поведение включается только через `construct_full()` или новый модуль.

## API

```gdscript
const Builder = preload("res://scripts/source_system_builder.gd")
var result = Builder.new().build({
    "seed_a": source_seed,
    "mass": source_mass,
    "num_stars": source_star_count_code,
    "system_id": source_id,
    "population_raw": source_population,
    "system_name": "System"
})
```

Вместо `system_name` можно передать `system_name_bytes: PackedByteArray`, включая конечный NUL. Это сохраняет исходную однобайтовую кодировку имён. Заголовок F878 содержит `seed_a`, затем `mass`: именно масса является начальным вторым словом глобального генератора случайных чисел в процедурной ветке. Отдельного входного `seed_b` у этого заголовка нет.

Результат содержит:

- `ok`, `source_variant`, `metadata`;
- `records`: массив **128** записей `PackedByteArray` по **68** байт, уже в упакованном выходном формате F878;
- `record_count` и `index`: индекс завершающей записи с нулевым первым DWORD;
- `body_count_byte`, `star_count_byte`, `port_count_byte`, `orbital_count_byte`;
- `seed_a`, `seed_b`, `depth`, `counter`, `language`, `star_quota`, `largest_mass`.

Повторно преобразовывать эти записи через `HandcraftedRuntimeBuilder` нельзя: такое преобразование выполняется внутри F878 только для исходных шаблонов ручных систем.

`seed_a == 0` выбирает оригинальную таблицу DATA7133: все 11 заданных систем и исходный запасной Riedquat для неизвестного идентификатора. `construct_binary(records,request)` и `construct_children(records,request)` предоставляют самостоятельные F877/F897 для воспроизводимой проверки. `orbit_lookup(value)` повторяет F896. Полный строитель возвращает кандидат, не меняя переданный банк или запрос; неверный ввод отвергается целиком.

## Сохранённые особенности алгоритма

Лимит **60** в начале F881 сохранён точно. При этом реальные F891/F892 могут добавить порты после тела в позиции 59, получив больше 60 действующих записей. Поэтому новый банк имеет 128 мест, а старые API продолжают принимать 60. Нативные полные системы действительно дали до **61** действующей записи; прямые контрольные случаи достигли индекса **64**. Лимит 128 не служит искусственным увеличением исходного числа планет.

F897 передаёт три счётчика имён по значению в рекурсивный вызов, сохраняет и восстанавливает оба глобальных слова RNG и глубину после дочерней системы. При этом глобальный порядковый счётчик тел, счётчики портов и остаток квоты звёзд продолжают изменяться. Увеличение индекса после обратного вызова F881 выполняется после последнего реально добавленного поселения.

F896 принимает только AX. Включённая граница `0x4000` обращается к слову сразу после исходной таблицы из 256 DWORD — первому значению DATA7130, **11945**. Это исходное соседнее значение извлечено и проверено, а не заменено интерполяцией.

Барицентр F877 сохраняет исходное сокращение имени, фазы 0/0x7fff и точные индексные записи. Используется явно обозначенная поправка яркости двойных звёзд из JJFFE, которой нет в DOS-исполняемом файле.

Защита от некорректного нулевого начального радиуса F897, глубины свыше 64 и миллиона итераций отвергает весь кандидат. Она не изменяет поведение прошедших исходных контрольных случаев. Неподдерживаемые входные значения не подменяются выдуманными результатами.

## Метаданные F868/F869/F871

`SourceSystemMetadata.query(id, first_value=0, second_value=0)` возвращает настоящий индекс исходной политики, восемь полей F869, нибблы F871, язык и перестановку двух переданных значений. Поиск включает таблицу заданных систем, четыре исключения и все восемь исходных дистанционных зон.

`data/ffe_system_metadata.json` содержит обе числовые таблицы:

- закреплённая JJFFE: SHA-256 `615c5b340073e5addfada00bc7db12c9511ed7ab39c4ac652445252aed851d46`;
- исходная DOS: SHA-256 `3d49f71bfb2de5842d1639346d6a164fb4e21f9f15012c1eb8511c920ae556e0`.

Первые 18198 байт совпадают. JJFFE добавляет **10 строк по 54 байта** перед нулевым ограничителем; нельзя утверждать, что вся таблица целиком совпадает с DOS. Выполняемый вариант явно указан в `source_variant`. Символьные указатели DATA7117 не выдаются за числовые DOS-адреса: ресурс хранит номера реальных меток для связывания исходной таблицы имён.

## Независимая проверка

`tools/rebuild_source_system_native.py` собирает и запускает действительные процедуры исходного ассемблера, включая F868/F869/F871/F877/F878/F881–F894/F896/F897 и необходимые реальные именующие, поселенческие и арифметические процедуры. Ожидаемые записи получены этим исполняемым оракулом; генератор ожидаемых результатов не вызывает GDScript и не повторяет алгоритм конструктора на Python.

Закреплены:

- исходный EXE: `d919566140abfc298bc9929bc9141d92526586821f017be1336253a04bca1e72`;
- JJFFE commit: `7e540341d4e09aa3c92877b87d49e7f2c143ad8d`;
- исходный `ffe.asm`: `d4f1b76aa78895d3634b182428e14f36ac57b304e56fedb67a89ee39b5f6873a`;
- исходный `ffedat.asm`: `34219c91c5d019440ebf4fc707711a32c5080123ede05cf4d10a27d41f770850`.

Переход нативного оракула на x86-64 меняет только размещение указателей/стека и адаптирует CRT-копирование строк; исходные 32/16/8-битные арифметика, таблицы и ветвления сохраняются. Неиспользуемые пути имён, обращающиеся к журналу/глобальному состоянию вне этого конструктора, имеют аварийные заглушки без возвращаемого вымышленного значения; в покрываемых фабричных категориях они не вызываются.

В `tests/fixtures/source_system_native.json` записаны **5829** независимых полных случая: 2497 F881, 3060 прямых F883–F887, 36 двойных звёзд, 27 рекурсивных иерархий, 209 полных систем (включая 42 настоящих заголовка F860, отдельную исходную Polaris и четыре эффективных заголовка явно исправленных нулевых корневых радиусов). Дополнительно есть **1145** прямых контекстов метаданных. Все полные банки сверяются в трёх новых процессах и в обратном порядке, с охранными значениями до и после банка. Сжатое разреженное представление JSON хранит исходные и изменившиеся записи; SHA-256 относится ко всем 8704 байтам банка.

Проверки:

```sh
python3 tools/rebuild_source_system_native.py
godot --headless --path . --script tests/test_source_system_builder.gd
godot --headless --path . --script tests/test_source_body_classifier_full.gd
godot --headless --path . --script tests/test_source_body_factory.gd
```

Текущее соответствие полному банку, всем возвращаемым словам RNG/счётчикам и метаданным: **113101 проверка, 0 ошибок**. Отдельный полный классификатор: **44823, 0 ошибок**. Регрессия старого фабричного API: **35979, 0 ошибок**, включая его прежние отказы на не включённых в старый контракт именующих/поселенческих помощниках.

В единственном исходном заголовке Beta Lyrae (ID `0x02af3686`) F860 возвращает массу `0xffffffff`. Подтверждённый вызывающий F461 передаёт этот заголовок прямо в F878. F881 выбирает за пределами 23 определённых классов индекс 23 и читает DATA7126=`0x1234` как адрес обратного вызова. Этот исходный неопределённый путь **атомарно отвергается** строгим строителем. Его нельзя выдавать за проверенную исходную систему; отдельная явно описанная поправка вызывающего мира может выбрать последний определённый класс `0xfffffffe`.

Четыре других настоящих заголовка F860 (`1919437698`, `44586598`, `44578542`, `111736477`) дают нулевой младший WORD начального радиуса F897. Независимый `tools/rebuild_zero_orbit_native.py` исполняет настоящий F878/F897 с безопасным наблюдателем: 65 границ после 64 полных итераций, нулевые радиус/шаг/масса, неизменный банк, оба RNG и охранные значения, три новых процесса и обратный порядок. Это доказательство исходного бесконечного цикла, а не притворный завершённый результат.

Строгий строитель заранее отвергает такие заголовки с `last_failure.reason == "nonterminating_source_root_radius"`. Публичная политика вызывающего `World.normalize_source_parameters()` открыто сдвигает исходный seed до первого положительного корневого радиуса, сохраняет исходный/эффективный заголовки и метку `zero-root-orbit-radius-seed-step-v1`. Четыре эффективных входа отдельно исполняются **неизменённым** нативным F878 и дают банки из 41/22/28/31 записей. Исправления исходных дефектов не изменяют обычные исходные ветви и старые API.

## Граница готовности

Этот модуль закрывает исходный конструктор и метаданные. Его подключение к живому `World` описано отдельно в `SOURCE_GENERATED_WORLDS_RU.md`. Сам по себе этот модуль не доказывает физический масштаб SI, столкновения исходного рельефа, маршруты подземного порта, переходы/сохранения v4 или Android-производительность. Для закрытия блока нужны отдельные интеграционные проверки этих потребителей. Старый опубликованный контрольный мир 0.11.11 остаётся в отдельном неизменяемом эталоне.
