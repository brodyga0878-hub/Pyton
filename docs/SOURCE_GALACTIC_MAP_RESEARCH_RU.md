# Исходная галактическая карта: проекция, координаты и плотность

Исследование 7 ноября 2026 года. Оно служит новой карте мобильной версии.
Полный старый renderer, вся F840 и обработчик мыши здесь не исполнялись.
Собственные ожидания координат/проекции не выдаются за исходные кадры.

Исходные файлы:

- Пользовательский `FIRSTENC.EXE`, SHA256

## Обработчики и реальная композиция

| Область | Источник | Установленное поведение |
|---|---|---|
| Секторный экран | F840, `ffe.asm:57123–58049` | Собственный центр Q16, глубина камеры, поворот мышью, несколько соседних секторов |
| Содержимое сектора | F841, `58052–58244` | Исходные 6-байтные положения/типы, вызов F1684 при включённом рисовании |
| Сведения о системе | F842/F843, `58248–58991` | Переключение страниц, сведения, исходные подписи координат |
| Обзор галактики | F844/F845, `58995–59211` | Включение двумерного обзора, выбор масштаба 1…255 |
| Подписи рукавов/объектов | F846, `59215–59282` | Таблица DATA6812…6815, пороги масштаба и реальные положения |
| Плотностная картинка | F847/F848/F849, `59286–59482` | Точный, 2×2 и 4×4 варианты отрисовки через F853 |
| Плотность | F853, `59754–59870` | Bilinear-поле и зависимое от масштаба сглаживание; отличается от режима генерации звёзд |
| Положение звезды | F856, `59922–59959` | Исходный перевод байтов в Q16 |
| Секторный renderer | F1684, `102296`; F1774, `111234` | Матрица и положение передаются в обычный исходный графический pipeline; здесь полное исполнение не заявлено |

Реальный F840 сам рисует соседние секторы вызовами F841. Поэтому ограничение
одного подробного кадра девятью секторами допустимо. Для полноценной карты
нужны свободное перемещение центра, выбор и отдельный обзор галактики.

F840 работает с полями игрока `+0x23a/+0x23e` — центр карты в Q16,
`+0x242` — глубина. Команда `c` в ветви `JUMP_003432` возвращает центр
к текущей системе, сбрасывает накопление мыши и ставит глубину `0x30d40`.
Статический анализ не доказывает независимую от FPS скорость старого
клавиатурного повтора; мобильный ввод должен иметь свой явный контракт.

Поворот использует `GuiGetXYAccum`, компоненты `<<7`, затем
`F1675_MatBuildYZT`. После этого F840 переставляет девять компонентов:
`[m5,m2,m8,m3,m0,m6,m4,m1,m7]`. Это реальный поворачиваемый пространственный
вид, а не неподвижный случайный фон. Точная пиксельная идентичность требует
контроля последующего F1684/F1774/проекционного pipeline и масштаба окна.

## Координаты относительно Sol

F843 отображает:

```text
sector_x = (system_id & 0x1fff) - 0x1718
sector_y = ((system_id >> 13) & 0x1fff) - 0x1524
```

Таким образом, **raw-начало (5912,5412) отображается как (0,0)**.
Polaris (5912,5488) отображается как (0,76). Сдвиг 4096 вместо этих
исходных значений дал бы неверную карту.

Raw-запросы звёздных секторов ограничены `0…8191` по каждой оси.
Отрицательные отображаемые координаты нормальны после вычитания Sol.
Их нельзя молча оборачивать, передавая отрицательный raw-сектор в каталог.
F853 возвращает нулевую плотность вне допустимой области. Отдельные
декоративные подписи рукавов имеют отрицательную raw-координату: это
текстовая метка обзора, а не звёздный сектор.

## Точная схема обзора

F847 рисует **320×158** точек. При raw-центре `(cx,cy)` и масштабе `s`:

```text
start_x = cx - (s >> 1) + 160*s
start_y = cy + (s >> 1) - 79*s
screen_y = 157…0: world_y = start_y, затем +s
screen_x = 319…0: world_x = start_x, затем -s
palette_index = DATA6821[F853(world_x,world_y,s) >> 10]
```

F848 и F849 используют соответственно шаг `2*s`/`4*s` и блоки 2×2/4×4.
Следовательно, грубый промежуточный обзор имеет исходный аналог.

**Третий параметр F853 — настоящий масштаб, а не bool.** При `s=0`
применяется override числа звёзд ручных секторов и полный случайный
множитель. При `1…15` override пропускается, а множитель плавно ослабляется:

```text
factor = 65535 - (((16-s) * random_multiplier) >> 5)
result = unsigned32(bilinear_field * factor) >> 16
```

При `16…255` возвращается непосредственно bilinear-поле. Поэтому обычный
`SourceGalaxy.density(x,y)` с семантикой `s=0` нельзя использовать для
плотностной картинки без отдельной scale-ветви.

## Извлечённые данные и подтверждение

`tools/extract_galactic_map_data.py` создал `data/ffe_galactic_map.json`.
Все три блока найдены **однозначным совпадением байтов** и сверены
с проверенным EXE:

| Блок | Offset EXE | Размер | Назначение |
|---|---:|---:|---|
| DATA6821 | 849020 | 256 | 64 dword индекса палитры для плотности |
| DATA7769 | 963984 | 384 | 128 низких RGB6 цветов; обзор использует первые 16 |
| DATA6812…6815 | 848544 | 240 | 14 подписей с порогом масштаба, X/Y и FF-кодом плюс sentinel |

Низкие цвета 0…15 — `[4*i,4*i,4*i]` в RGB6. SDL при единичной gamma
переводит компоненты через `<<2`, максимум 240. F1448 записи BMP использует
репликацию битов и даёт максимум 243. Обе политики сохранены раздельно;
мониторная гамма не восстановлена по предположению.

Только шесть буквальных названий рукавов/туманностей декодированы в JSON.
Прочие FF-коды должны получать имена из исходного имени системы.

Опция `--native` действительно выполнила исходные инструкции F853 в
имеющемся host-native harness F841/F856/F861 с выключенным рисованием.
Проверены **4536 входов**: 504 координаты для масштабов
`1,2,4,8,15,16,17,64,255`; каждый масштаб — три свежих процесса и
обратный порядок. Защитные слова не изменились. Ожидания не вычислялись
Python-моделью плотности. Результат хранится в
`tests/fixtures/source_galactic_map_native.json` и может проверять новый
GDScript-потребитель. Это подтверждает плотность/таблицы, но не всё
исходное меню или полный кадр старого renderer.
