# Подключение закрытого ангара к поверхности v4

`source_underground_controller.gd` связывает проверенную модель96 с текущей системой координат планеты и физическим циклом. Контроллер включается только для `sphere-source-ground-v4` и профиля порта с той же ревизией. Якорь, его матрица и высота поступают из отдельного проверенного F879 через `SourceSurfaceTerrain`; старые поверхности v1–v3 не получают новую геометрию автоматически.

## Кэширование исходной программы

При конфигурации выполняется фактическая программа96. Локальный подкласс компилятора запоминает точный исходный кадр вызова `96/237@20` и позицию этого поддерева в треугольниках, событиях и экземплярах. Остальная часть города неизменяема. Для очередного положения двери выполняется **вся реальная программа237 со всеми дочерними вызовами**, сохранёнными матрицей, локальными параметрами, масштабом, цветом и RNG. Готовое поддерево вставляется на исходное место, после чего применяется исходное глобальное устранение одинаковых треугольников. Неизвестные команды не подменяются заглушками.

Такой результат проверен против обычной полной компиляции96: совпадают все исходные треугольные записи, события, экземпляры, границы, число инструкций/экземпляров/треугольников и исходные метаданные RNG. Контексты включают обе реальные угловые матрицы Apollonius City/Factory Central, полюс, UID=0xffffffff и положения двери0,16384,32768,65535.

`data.compiled` остаётся полноценной совместимой компиляцией города. Дополнительно возвращаются `static_compiled`, `dynamic_compiled`, `static_key`, `dynamic_subtree`. Визуализатор может один раз построить статический город и перестраивать только фактическое поддерево237. Оба используют тот же `conversion_basis` и размещение корня. Исходная геометрия и точное положение крышки не квантованы.

## Контракт Surface/Main

| Вызов | Назначение |
|---|---|
| `configure(site,globe,saved={},radii)` | Атомарно подготовить реальный v4-профиль, дверь и исходные ресурсы; при ошибке сохранить действующий контроллер |
| `current_route(globe,radii)` | Вернуть внешнюю, входную и внутреннюю точки в **текущем** касательном кадре планеты |
| `root_position(globe,position)` | Перевести текущее положение в метры у исходного корня города |
| `request("dock"/"launch")` | Запросить заход или выход через крышку |
| `step_source(source_step,globe,position,radii,contact_ok=false)` | Вычислить следующий исходный шаг двери и состояния |
| `step_seconds(dt,...)` | Явный адаптер реального времени:49710 календарных тиков/с с сохранением дробного остатка; не утверждение о темпе старого рендера |
| `capture_job()` | Быстро получить неизменяемое задание для подготовки геометрии |
| `Controller.prepare_job(job)` | Выполнить задание в отдельном рабочем потоке без доступа к изменяемому живому контроллеру |
| `prepare_pending()` | Безопасный сокращённый вариант `prepare_job(capture_job())` для Main-worker |
| `publish_prepared(bundle,globe,position,radii)` | На основном потоке атомарно опубликовать совпадающие состояние и коллизию |
| `snapshot()` | JSON-совместимое сохранение опубликованного состояния и дробного остатка тика |

Живые поля: `configured_ok`, `last_error`, `profile`, `data`, `route`, `state`, `dirty`. Эти структуры читаются Surface/Main; менять исходные массивы или присваивать поля состояния напрямую не следует. `prepare_pose()` — низкоуровневый метод для изолированной подготовки/тестов; для общего worker используется `capture_job/prepare_job` либо `prepare_pending`.

Изменение двери ставит `dirty=true`, но оставляет прежнее состояние и прежний физический меш согласованными. Переход к проходу через крышу не публикуется, пока соответствующий открытый меш не готов. При ожидающем задании новые шаги не компилируют город в фиксированном цикле. До успешной публикации управление продолжает использовать прежнюю точную позу.

Короткая блокировка защищает захват задания, запросы, публикацию и сохранение. Трудоёмкая работа идёт на изолированном экземпляре со снимком профиля/кадра и неизменяемыми ресурсами. Пакет несёт идентификатор контроллера и поколение; результат старого захода, повторной конфигурации или прежней поверхности отвергается. Перед публикацией повторно проверяется фактическое положение корпуса: крышка не может появиться внутри корабля, который сдвинулся после запуска worker.

При успешной публикации Surface присваивает `city_data=controller.data`. Удобные обёртки для Main: `Surface.prepare_underground_update()` и `Surface.publish_underground_update(bundle,ship)`. Root/Main отвечает за кнопки, запуск/опрос потока и UI; Surface — за реальное ускорение корабля к путевым точкам, контакт с полом, гравитацию и общий цикл посадки/взлёта. Контроллер не включает услуги порта без `contact_ok` от этого физического слоя.

## Сохранения и проверки

Снимок контроллера: `{revision,state,fractional_tick}`. Ожидающий, ещё не опубликованный меш не сохраняется как физическая реальность. Восстановление заново готовит геометрию именно сохранённого исходного слова двери; закрытый пристыкованный корабль сохраняет явный путь `launch → opening → departing`.

```sh
godot --headless --path . --script res://tests/test_source_underground_controller.gd
```

Результат: **197 проверок,0 ошибок**. Помимо сравнения с полной VM проверены привязка после смены касательного кадра, сохранение во время подготовки, атомарные публикации, весь цикл посадки/взлёта, отказ при пересечении корпуса, отклонение старых/повреждённых данных и реальный Godot-worker с одновременной повторной конфигурацией. Оболочка не заявляет о проверенном FPS на Samsung S23 Ultra; производительность и полный игровой путь проверяются общим интеграционным блоком.
