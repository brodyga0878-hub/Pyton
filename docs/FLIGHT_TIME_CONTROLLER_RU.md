# Ограниченный контроллер игрового времени

7 ноября 2026 года, Москва. Новый `scripts/flight_time_controller.gd`
предназначен для общего шага Main. Он не меняет Navigation/World самостоятельно
и не выдаётся за полный исходный интегратор FFE.

## Три разных величины времени

Исследована закреплённая JJFFE-версия
`7e540341d4e09aa3c92877b87d49e7f2c143ad8d`, `ffe.asm` SHA-256
`d4f1b76aa78895d3634b182428e14f36ac57b304e56fedb67a89ee39b5f6873a`.

| Величина | Значение и потребитель |
|---|---|
| Исходный обычный таймер | F1418 получает `floor(real_ms*994/20)`: 49700 ticks за 1000 мс |
| Исходная экранная секунда | F1363 делит tick-word на 49710; сам формат календаря уже проверен в `source_clock.gd` |
| Действующий SI-мост полёта | `2^32/86400 = 49710.2696…` ticks на секунду; это явно выбранный контракт современных координат/ускорения, а не восстановленный F1418 |

В F208 (`ffe.asm:17066–17196`) пять исходных подписанных ступеней
×1/×10/×100/×1000/×10000 имеют следующие реальные параметры:

| Подпись | D9012, timer | D9013, shift |
|---|---:|---:|
| ×1 | 994 | 0 |
| ×10 | 9942 | 3 |
| ×100 | 99420 | 7 |
| ×1000 | 994200 | 10 |
| ×10000 | 9942000 | 12 |

В гиперпространственном состоянии F208 и F908 используют отдельные значения
`0x0f880000 / 0x12`. Их нельзя применять как обычный коэффициент `Godot dt`.
F207 копирует временные параметры в рабочие. F217 возвращает нормальное время
и сбрасывает связанные счётчики при смене режима; F220 останавливает время.
У F208 также сохранены реальные различия клавиши `0`, действия `0x3a`
и GUI-команд `0xc1…0xc5`.

Просмотрены связанные сбросы и потребители: F349/F360 возвращают нормальный
режим при сообщениях/действиях; F908/F909 и последующий выход из перехода
имеют отдельное управление таймером; исходный автопилот F746 и динамика F593
используют параметры ускорения в своих вычислениях. Полный набор всех
оригинальных ограничителей и исходный цикл объектов здесь не объявляются
перенесёнными.

## Что независимо исполнено

`tools/rebuild_source_time_native.py` исполняет настоящие инструкции
F207/F208/F217/F220/F1418 в отдельном host ELF. Ввод GUI заменён записью
аргументов, timestamp задаётся тестом, несвязанный 50 Hz callback удерживается
впереди timestamp и аварийно завершает контроль, если неожиданно вызван.
F207 исполняется через F220; все остальные пути вызываются отдельно.

Проверены **1736 входов**, три свежих процесса, обратный порядок и защитные
слова. Выборка F208 проходит все 256 команд в шести режимах игрока; F217/F220
проверяют разные начальные таймеры; F1418 проверяет целочисленное деление
и переполнение 32-битных накопителей на допустимых входах.

Фикстура `tests/fixtures/source_time_controls_native.json`, SHA-256
`f5d812f399f24490580f1907cbf4e9c78b71c39949203c57e2228128abea571b`.
Host-адаптация сохраняет исходную арифметику и индексы, расширяя только
стек/указатели обратных вызовов и таблицу переходов с 4 до 8 байт.
Никакой host ELF/x86-код не включается в Android runtime.

`source_control()` и `source_timer_delta()` дают узкие GDScript-потребители
этого контроля. Область 32-битного переполнения частного `DIV` явно
отклоняется до умножения. Системный Timer50Hz, сон, полный вызов игрового
кадра и весь диапазон исходных timestamp-wraps не проверены этим оракулом.

## Современный безопасный профиль

Контракт `bounded-nominal-si-flight-time-v1` использует секунды действующего
SI-моста. Игровые часы остаются `Navigation.elapsed_days`; контроллер не
вводит конкурирующий календарь и не перемещает тела независимо от Main.

Поддерживаются **×1, ×10 и ×100**. Исходные ступени ×1000/×10000 выдаются
в списке с настоящими исходными параметрами и явной причиной недоступности:
проверенного дальнего интегратора для них пока нет.

- В одном плане максимум **32 подшага**, каждый не больше **0,1 с**.
- Обычный кадр ×1 с `dt <= 0,1` сохраняет точный входной `dt` одним шагом.
- При нехватке бюджета выбирается меньшая поддержанная ступень. Например,
  ×100 при входном кадре 1/30 с ограничивается ×10, а при 1/60 с укладывается
  в бюджет. Интерфейс должен показывать **effective_rate**, а не обещанные ×100.
- Необработанное обычное время хранится одним числом `pending_real_seconds`,
  без неограниченных массивов подшагов. Максимальный принимаемый долг — час;
  чрезмерный/нечисловой интервал отклоняется явно.
- Меню, пауза, фон и подготовка мира не дают шагов. Старый долг явно
  отменяется, поэтому возврат в игру не запускает скрытую перемотку.
- Ручной ввод, автопилот, док, посадка/взлёт, поверхность, бой и переходы
  требуют обычного времени. Новое управление также отменяет старый долг:
  свежий стик не применяется задним числом к прошлым секундам.
- Для ускорения нужны действительные расстояния/скорость/гравитация.
  Минимальные зазоры: грунт 10/100 км, станция 20/200 км для ×10/×100 плюс
  консервативный десятисекундный путь `speed*10 + gravity*50`.
  Это отдельная современная политика, не исходные границы F208.
- Для станции вызывающий код должен передавать расстояние до её внешнего
  габарита. Для несферического тела нужен проверенный зазор или консервативная
  внешняя граница. Неизвестное расстояние ограничивает время до ×1.
- После опасного сближения требуется новая явная команда ускорения;
  автоматического возврата к прежним ×100 нет.

Сам контроллер не доказывает все возможные столкновения. Корректные данные
опасности, актуальный кадр, проверка подшага и остановка при потере корабля
остаются обязанностью вызывающего Main/физического backend.

## Контракт интеграции

```gdscript
var plan = time_controller.plan_frame(real_dt, current_context)
var executed = 0
var interrupted = false
for step in plan.steps:
    if not time_controller.can_continue(plan.effective_rate, fresh_context()):
        interrupted = true
        break
    _tick(step, steering, roll, lift)
    executed += 1
time_controller.finish_frame(plan.token, executed, interrupted)
```

Для изменения условий в последнем выполненном подшаге Main снова проверяет
контекст и завершает план прерыванием; смена моделей/кадра также завершает
текущий план. После гибели корабля `_tick()` ничего не делает, поэтому
дальнейшие невыполненные шаги нельзя записывать как исполненные.

`plan_frame` выдаёт транзакцию и копию массива шагов. Следующий план запрещён
до `finish_frame`; неверный token или число шагов отвергается атомарно.
`finish_frame` учитывает только реально исполненные шаги и явно сообщает
`discarded_pending_real_seconds` при остановке. Пустой план token=0 можно
безопасно завершить с нулём шагов. Token остаётся монотонным при reset/restore:
позднее завершение старого плана не может подтвердить другой новый план.

Контекст: `active`, `menu_open`, `busy`, `paused`, `source_world`,
`manual_input`, `autopilot`, `landing`, `taking_off`, `docked`, `surface_active`,
`combat_active`, `jump_remaining`, `transfer_remaining`, `station_available`,
`station_distance_m`, `body_clearance_m`, `speed_mps`, `gravity_mps2`.
Отсутствующие данные дают обычное время; некорректные числа блокируют шаг.

`rate_options(context)` выдаёт все пять ступеней с `enabled/reason`.
`request_rate(rate)` принимает только реализованные ступени.
`can_continue(rate, context)` проверяется между подшагами.
`interrupt(reason)` сбрасывает долг вне активного плана.
`reset()` нужен для нового полёта/восстановления игры. Session snapshot хранит
только выбранную ступень, без долга, плана и новых физических полей сохранения.
Main может использовать существующий `instruments.paused` как единственный
источник состояния паузы.

## Проверки

`tests/test_flight_time_controller.gd`: **36926 проверок, 0 ошибок**.
Проверены все независимые исходные входы, частоты 30/60/120 Гц, фактическое
время и исходный календарь, смена суток, ограничение бюджета, защита от
дублирования/подмены плана, частичное исполнение, смена опасности, сброс
долга на паузе/ручном вводе, запрет скрытой перемотки, строгий session restore
и отклонение старых token после reset/restore. Независимый review выявил
и повторным probe подтвердил исправление повторного использования token.
Эти результаты не заменяют сквозные проверки Main, вращающегося дока,
сохранений на ускорении и измерения FPS/нагрева S23 Ultra.
