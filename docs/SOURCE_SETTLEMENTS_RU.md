# Исходные конструкторы поселений F891/F892

`scripts/source_settlement_builder.gd` переносит два исходных помощника,
которые добавляют наземные и орбитальные порты после текущей записи тела.
Они используют четыре точных шаблона F875 из
`data/ffe_settlement_rules.json`, исходные таблицы координат и моделей,
упакованную арифметику и отдельный проверяемый модуль F893/F791 именования.
Это построение исходных записей, а не само размещение рельефа или доков.

Источник: пользовательский EXE с SHA-256
`d919566140abfc298bc9929bc9141d92526586821f017be1336253a04bca1e72`
и JJFFE commit `7e540341d4e09aa3c92877b87d49e7f2c143ad8d`.
Вариант модуля: `jjffe-7e54034-settlements-v1`.

## API и состояние

```gdscript
var builder = preload("res://scripts/source_settlement_builder.gd").new()
var result = builder.construct_ground(records, request)
var orbital = builder.construct_orbital(records, orbital_request)
# Explicit larger bank for the complete source system constructor:
var full = builder.construct_ground_full(records128, request)
var full_orbital = builder.construct_orbital_full(records128, orbital_request)
```

`records` — массив из 60 `PackedByteArray` по 68 байт. Это исходный буфер
построения системы; входные записи и запрос не изменяются.
Общие поля `request`:

| Поле | Значение |
|---|---|
| `index` | Нулевой индекс текущей записи тела; новые записи следуют после неё |
| `seed_a`, `seed_b` | Исходные глобальные слова F894 `DATA8843/8844` |
| `population_raw` | Исходный параметр заселённости `DATA8854` |
| `ordinal_counter` | Счётчик `DATA8846` |
| `port_count_byte` | Исходный байтовый счётчик всех портов `DATA8855` |
| `orbital_count_byte` | Исходный байтовый счётчик орбитальных портов `DATA8856` |
| `language` | Исходный численный языковой флаг; значение 3 меняет категории имён |

Все поля принимаются как точные u32, два байтовых счётчика ограничены
0–255, `index` — 0–59. Наземный запрос дополнительно содержит
`model_offset` и `count_scale`, орбитальный — `port_type` и
`parent_index` (однобазовый родитель).

Отдельные методы с суффиксом `_full` принимают ровно 128 записей и
`index` 0–127. Они выполняют те же исходные помощники без искусственного
ограничения добавленных портов слотом 59. Ограничение F881 на 60 тел
проверяется самой вызывающей фабрикой **до** её callback: помощники
F891/F892 затем могут законно добавить записи после 59. Расширенный
буфер сохраняет эти исходные записи и место для завершающего элемента.
Прежний 60-слотовый API не меняется и не принимает другой размер молча.

При успехе возвращаются `ok=true`, полный кандидат `records`, конечный
`index`, обновлённые счётчики, прежние глобальные seeds и
`appended_count`. Конечный `index` указывает на **последнюю добавленную
запись**, а не следующий свободный слот: вызывающая F881 затем отдельно
увеличивает свой индекс. Поля запроса сохраняются в результате явно.

Некорректный вход возвращает `{}`. Если источник попытался бы записать
за пределами предоставленного 60-слотового буфера, API возвращает
`ok=false`, `reason="capacity"`, `helper_id=891/892` без частичных записей
или промежуточного состояния. Это явная безопасная граница нового API:
в самих исходных помощниках отдельной проверки размера буфера нет.
Такая же граница действует в конце явно выбранного 128-слотового банка.

## Наземные порты

F891 проверяет счётчик портов как **знаковый байт**, а не обычное число
0–255. Поэтому значения 18–127 блокируют добавление, а 128–255 следуют
исходному пути отрицательного байта. Это поведение сохранено и проверяется
отдельно; оно не заменяется удобной современной трактовкой счётчика.

Количество новых записей равно 1–4. Оно получается из младших 16 бит
`seed_b`, низшего DWORD исходного `IMUL count_scale` и `SHR16`, с
ограничением промежуточного результата числом 3. При достижении счётчиком
18 исходный цикл прекращается раньше. Локальные копии seeds обновляются
через исходные вращения 5/16 бит и сложения с переполнением. Глобальные
`seed_a/seed_b` помощник не изменяет.

Для каждой записи копируется исходный шаблон Apollonius City
`DATA8796`, затем записываются нулевая масса с исходной экспонентой,
UID, родитель текущего тела, пара исходных углов из 16-элементного цикла,
имя категории 6 и номер модели из исходной таблицы. Счётчик имени
переполняется как u32. Модели 91–96, включая подземную 96, сохраняются;
они не подменяются открытыми городами.

## Орбитальные порты

F892 добавляет одну запись и увеличивает оба байтовых счётчика портов.
Типы 0/1/2 используют соответственно шаблоны Daedalus, Galileo и
Abraham Lincoln, а модель выбирается по двум битам `seed_a` из исходных
таблиц 7136/7137/7138. Типы 3/4 используют исходные специальные модели
69/79 и пятибайтовое имя `????\0`. При этом остаток прежнего поля имени
сохраняется как в оригинале; флаг именованной записи не придумывается.

Ветвь для остальных u32 `port_type` также сохранена: источник пропускает
копирование шаблона и меняет определённые поля уже имеющегося целевого
слота. Это диагностическая регистровая область, а не заявление о новых
допустимых игровых типах портов.

Орбита задаётся исходным packed `0x00227fff`, период вычисляется через
реальную цепочку F1482/F1483/F1463/F1467 и множитель мантиссы `0x5edb`
из упакованной массы указанного родителя. Перевода в SI здесь нет.
Обычные типы получают имя категории 7 через исходную F893/F791.

## Полные байты имени важны

В исходной таблице есть строка `M[nich`. При некоторых именах языка 3
она проходит через F77/F76 и превращается в `M[ch`. Сначала источник
пишет длинную промежуточную строку, затем переписывает её укороченным
результатом; байты за новым NUL могут остаться от промежуточной записи.
Простое копирование финального видимого имени не воспроизводит все
68 байт записи. Именно полный банк сравнивается с независимым эталоном,
включая эти хвосты, флаги и неизменённые поля шаблонов.

## Независимые проверки

`tools/rebuild_source_settlement_native.py` связывает настоящие исходные
F891/F892, F893/F791 и общие текстовые/математические процедуры в
исследовательский host ELF. Имена, модели и периоды не вычисляются
в Python как ожидаемые результаты. ABI меняется только для стека,
указателей и таблицы переходов host x86_64.

Fixture `tests/fixtures/source_settlements_native.json` содержит
1326 контекстов и 2060 добавленных записей. В нём есть границы количества,
знакового байта, переполнения счётчика координат, все нормальные типы
орбитальных портов и их специальные/диагностические ветви, исходные
подземные модели, разные массы родителей и языковые имена.
Три свежих процесса и обратный порядок дают одинаковые полные банки.
Оба защитных участка, все нецелевые записи и глобальные RNG-слова
сохраняются. Полный SHA-256 каждого банка закреплён в fixture.

Дополнительные 173 native-контекста выполняют те же реальные процедуры
в 128-слотовом банке, включая добавление после слотов 59/60/63 и около
конца расширенного буфера. В них добавлены ещё 163 записи; итог —
1499 контекстов и 2223 добавленных записи. Они также проходят три свежих
процесса, обратный порядок, защитные участки и побайтовую проверку
нецелевых слотов. Godot: **16 627 проверок, 0 ошибок**.

```sh
python3 tools/rebuild_source_settlement_native.py
godot --headless --path . --script tests/test_source_settlement_builder.gd
```

Для связывания полного исходного генератора инструмент предоставляет
`settlement_library_assembly(source, rules=None)`: реальные F891/F892
и их константы без собственного `_start`, общих helpers и глобальных
переменных. Вызывающий native-генератор связывает те же настоящие
процедуры именования, packed math и счётчики один раз.

Эти проверки не подтверждают всю рекурсивную иерархию F877/F878/F897,
исходный рельеф F879/F574, открытые и подземные маршруты доков,
экономику портов, физику полёта или испытания телефона. Эти интеграции
требуют самостоятельных проверок.
