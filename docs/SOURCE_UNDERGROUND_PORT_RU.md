# Закрытый наземный порт: исходная модель96

Ревизия `source-enclosed-ground-hangar-v1` добавляет исходную модель96, которую используют Apollonius City на Луне в Sol и Factory Central на Lucifer в Sirius. Это **ангар с вертикальным входом через крышу**, а не открытая площадка и не придуманный горизонтальный тоннель. Пол находится на исходной плоскости Y=0, крышка — на Y=65535 исходных единиц, приблизительно65,565м над полом. Дополнительную вырезанную пещеру в рельефе модуль не создаёт.

## Происхождение геометрии

- `FIRSTENC.EXE`: SHA256 `d919566140abfc298bc9929bc9141d92526586821f017be1336253a04bca1e72`.
- JJFFE: коммит `7e540341d4e09aa3c92877b87d49e7f2c143ad8d`, SHA256 `ffe.asm` `d4f1b76aa78895d3634b182428e14f36ac57b304e56fedb67a89ee39b5f6873a`.
- `tools/rebuild_underground_models.py` читает фактические дескрипторы, команды и вершины загруженного EXE через сохранённый экстрактор. Результат — отдельный `data/ffe_underground_models.json`: 36 достижимых моделей, из них только96,162,237,267,301 отсутствовали в основном ресурсе. Остальные31 записи побайтно/структурно совпадают с уже восстановленными данными.
- Основной `ffe_world_models.json` не изменён. `SourceModelVM.model()` сначала возвращает основной ресурс, затем под блокировкой загружает дополнительный ресурс с проверкой схемы и SHA исходного EXE. Дополнение не может подменить существующую модель.
- Модель96 непосредственно размещает ангар237 в начале координат. Семь его исходных треугольников на смещениях272,280,288,296,304,312,320 формируют изменяемую крышку. Пол, стены, крыша и соседние здания строятся исходным VM. Невидимого заменяющего куба нет.
- При `entity_variables_u16[1]=0` крышка открыта, при65535 закрыта; промежуточные значения действительно меняют её вершины. Это поле объекта+0x9e при базе параметров+0x9c. Поле объекта+0xd8 — таймер резервации, а не положение двери.

Исходные треугольники используются для визуализации и современных непрерывных проверок столкновения эллипсоида. Это адаптер коллизии для телефона, а не утверждение о переносе всего исходного F582/F575. Освещение, прорисовка и декоративные события не создают дополнительных физических стен.

## Исходные решения F650/F741/F865

`rebuild_underground_port_native.py` исполняет фактические инструкции полного неигрокового пути F650, F1674/F1669/F1521/F1914 и ограниченные исходные фрагменты выбора флагов/числа мест F880 и путевой точки F741. Не вызываемые колбэки интерфейса игрока завершают процесс ошибкой; результаты колбэков не подставляются. Контроллер движения F742 в этот тест не входит.

480 контекстов покрывают обе именованные площадки, полюса/границы углов, произвольные знаковые Q31-матрицы, все шесть свободных/занятых мест, отрицательные идентификаторы, отсутствие места и повторное резервирование. Три новых процесса и обратный порядок дают идентичный результат. Дополнительно результат сравнивается с независимым скалярным разбором исходных решений.

- F880 оставляет у96 флаги станции/поверхности0x30. Флаг открытой площадки0x40 ставится только моделям81..90.
- F880 задаёт CE=5: шесть **мест резервирования трафика**, не шесть придуманных открытых посадочных площадок.
- F650 проверяет занятость в порядке5..0 и сравнивает байт занятости как знаковое число. При новом резервировании возвращает статус−1, при существующем0. При отсутствии места не записывает выходные координаты и статус.
- Для96 успешный F650 выдаёт исходный Vec64 `[0,0,-1]`. Этот закрытый путь пропускает умножение F1669 и сдвиг, применяемые открытым площадкам; нельзя поворачивать sentinel как геометрическую площадку.
- Наземная ветка F741 поворачивает вектор `[0,6000,0]` точной матрицей F1674, сохраняет компоненты как signed16. Навигация разворачивает их в исходные смещения `<<10`. Получается внешняя точка приблизительно6,15км над ангаром.
- Анимация крышки вызывает общий точный `SourceStationGeometry.advance_door`, уже проверенный360 отдельными нативными контекстами полного F865. Открытие задаёт C9=0xff, закрытие C9=3; учитываются знаковые значения и переполнение исходного ADD. Положение0 означает открыто,65535 закрыто.

## API и встраивание

`scripts/source_underground_port.gd` не редактирует `SurfaceModel`, `Main` или сохранения общей игры самостоятельно. Его подключение выполняет основной интеграционный блок.

| Метод | Назначение |
|---|---|
| `describe(site,radius,elevation=0)` | Профиль реального города96: координаты/матрица F1674, исходная плоскость, границы выравнивания рельефа, `pad_count=0`, `reservation_count=6` |
| `prepare(profile,door=0)` | Совместимые с `SourceCityRuntime`/`SourceCityView` компиляция, реальные треугольники, пространственный индекс и профиль; точное положение крышки входит в ключ |
| `approach_raw(matrix)` | Исходная путевая точка F741 с точным signed16 и `<<10` |
| `reserve(identifier,occupancy,matrix,last_slot=5)` | Проверенный неигроковый путь F650 закрытого порта; без колбэков разрешения игрока |
| `route(profile,radii)` | Внешняя, надкрышная и внутренняя точки, нормаль, габариты корабля, результат проверки размера входа |
| `classify(profile,position,radii)` | Корабль над крышей, под крышей, внутри или пересекает уровень крышки |
| `sweep(data,start,finish,radii)` | Непрерывное столкновение в локальных метрах города; в текущей системе планеты можно использовать существующий `SourceCityRuntime.sweep(data,globe,...)` |
| `new_state(site_id,docked=false)` | Состояние крышки и захода/выхода |
| `command(state,"dock"/"launch")` | Запрос открытия для входа либо взлёта |
| `advance(state,source_step,profile,position,radii,contact_ok=false)` | Один шаг F865 и переходов; `source_step` — исходное целое значение D9155, не секунды |
| `snapshot(state)` / `restore(value,site_id)` | Проверенная JSON-совместимая копия состояния; неверная ревизия, порт или несовместимая фаза отклоняются |

`prepare` передаёт опубликованную геометрию для чтения. Присвоение полей возвращённого профиля не меняет кэш. Массивы исходных треугольников считаются неизменяемыми. Кэш ограничен тремя **точными** позами, без квантования положения двери. Полная компиляция96 содержит более10тысяч треугольников; вызывающая сторона должна публиковать новые позы через загрузочный поток/ограничивать частоту, а при проходе корабля держать крышку полностью открытой. Вся анимация физически точных промежуточных поз доступна API, но это не обещание компилировать целый город каждый кадр телефона.

`route` — явно обозначенная современная помощь управлению, а не трансплантация всего оригинального автопилота. Она использует настоящий вертикальный шестигранный вход и пол. Учитывается эллипсоид корабля; чрезмерно большой корабль получает `fits=false`. Дополнительные15м перед входом и0,25м над полом — открыто указанные запасы мобильного управления. Окончательное препятствие проверяется против фактических треугольников, включая промежуточное положение крышки.

## Переходы и безопасный взлёт

Маршрут состояний: `closed → opening → approach → inside → docked → opening → departing → closing → closed`. Сервисное состояние `docked` возникает только после отдельного `contact_ok=true` от физического контакта с полом, допустимой скорости/шасси/ориентации, проверяемых вызывающей поверхностной системой. Простое нахождение внутри не включает услуги порта.

Вход и выход разрешаются после достижения фактического положения двери0. Крышка закрывается над приземлившимся кораблём или после полного выхода корабля над её плоскостью. Если корабль занимает отверстие при закрытии, включая пересечение края отверстия, включается открытие. После ухода корабля закрытие возобновляется. Ручной выход обратно через крышу завершает отменённую посадку. Запрос взлёта из закрытого `docked` явно открывает крышку и переводит систему в `departing`; сохранённый закрытый ангар не должен оставлять кнопки без доступного пути взлёта.

Состояние содержит только ревизию, идентификатор порта, фазу, намерение и исходные слова двери/статуса. Геометрия и матрица заново строятся из подтверждённых данных порта. Каждая достижимая переходная фаза проверена после JSON save/restore. Общий модуль сохранений игры должен отдельно хранить это вложенное состояние при интеграции.

```sh
python3 tools/rebuild_underground_models.py
python3 tools/rebuild_underground_port_native.py
godot --headless --path . --script res://tests/test_source_underground_port.gd
```

Итоговая проверка после независимого ревью: **4335 проверок,0 ошибок**. Проверены обе реальные матрицы именованных портов,31 общий ресурс и модели81..90, открытый проход, закрытая и промежуточная крышка, пол и стены, совместимость с существующей планетарной CCD, цикл посадки/взлёта, защитное открытие у края, возобновление закрытия, ручная отмена захода, ограничения высоты корабля, некорректные сохранения и смена параметров кэшируемого профиля. Отдельный старый `test_source_model_mesh.gd` не запускался до завершения: в текущем восстановленном дереве отсутствует его `tests/fixtures/model_vertices_reference.json`; его отсутствие не заменяется выдуманным эталоном. Проверки устройства Samsung S23 Ultra и FPS выполняются отдельно в общем выпускном блоке.
