# Исходная орбитальная арифметика

`scripts/source_orbit.gd` переносит целочисленные процедуры вычисления орбитальной позиции в Godot. Вариант обозначен строкой `jjffe-7e54034-q31-orbit`: это процедуры F1507/F1508 из JJFFE, commit `7e540341d4e09aa3c92877b87d49e7f2c143ad8d`. В JJFFE эти две процедуры изменены по сравнению с загруженным `FIRSTENC.EXE`; поэтому результат не обозначается как точная позиционная арифметика DOS. F1506 с Q31-синусом, F1509/F1510 и используемые общие арифметические процедуры сопоставлены с DOS отдельно.

Это вычислительное ядро относительных координат. Оно не переносит целиком создание объектов F880, политику иерархии F866, гравитацию, радиусы, столкновения или движение корабля. Исторические сохранения с прежним законом движения должны выбирать прежнюю версию модели в вызывающем коде.

## Вход и результат

```gdscript
var state = SourceOrbit.evaluate_from_epoch(record68, tick_u32, day_u32)
```

`record68` — исходная 68-байтовая запись после формирования системы и применения исходных поправок. Ядро читает следующие поля, не меняя запись:

| Смещение | Поле |
| --- | --- |
| `+0x0a` | Тип объекта, `u16` |
| `+0x0e` | Упакованный радиус орбиты, `u32` |
| `+0x12` | Начальная фаза, `u16` |
| `+0x14` | Упакованный период, `u32` |
| `+0x22` | Наклонение, знаковое `s16` |

Часы состоят из двух исходных слов: `tick_u32` — младшее, `day_u32` — старшее. Это исходные слова часов, не секунды и не Unix-время. Вызывающий код отвечает за перевод времени своего мира в эту шкалу. Значения принимаются только как точные целые в диапазоне `0…0xffffffff`; JSON-числа с таким значением допустимы.

Результат содержит:

- `rate_u32` — исходную скорость изменения фазы;
- `phase_words` — два слова полной фазы `[lo, hi]`;
- `position_words` — три пары `[lo, hi]` исходных 64-битных координат;
- `position_raw` — те же три координаты в `PackedInt64Array`, с сохранением всех битов;
- `increment_words` — три 32-битных приращения интерполяции F1507;
- `base_position_words` и `coarse_angle` — состояние до дробной поправки;
- `orbit_packed`, `inclination_s16`, `source_variant` — параметры и явную версию алгоритма.
- `clock_tick_u32`, `clock_day_u32`, `anchor_tick_u32`, `anchor_day_u32`, `clock_policy` — текущие часы, неизменную точку исходной инициализации и способ расчёта.

Неверные данные дают пустой словарь. Тип 35 исключён: для наземного порта исходная игра использует другую ветвь F879 и вращение поверхности. Период с отрицательной мантиссой также исключён из проверенного физического диапазона. Мантисса `0x8000` отклоняется до вызова нормализации: исходная F1496 на ней зацикливается. Нулевой период не заменяется искусственной константой — сохраняется исходное поведение F1494/F1496 и деления, включая необычную скорость корневых записей с нулевой орбитой.

## Сохраняемая арифметика

Скорость получается через исходную нормализацию F1496, `Math.divide(0xffee5460, normalized_period)`, увеличение упакованной экспоненты на 64 и преобразование F1494. Полная фаза вычисляется как `rate × (new_clock − old_clock) << 3` по модулю `2^64`. Начальная фаза записи прибавляется как `record_phase_u16 << 16` к **старшему** слову, а не к младшему.

В исходном вызове F880 есть существенная особенность: процедура сохраняет время объекта как обычные `a8=tick`, `ac=day`, но в первичный вызов F1510 передаёт **day как младшее слово, tick как старшее**. Последующие обновления F866 используют обычный порядок `tick`/`day`. Это подтверждено вызывающими F905/F972, самим F880 и соответствующим фрагментом DOS. Поэтому повторять F880 заново на каждом кадре нельзя: это не воспроизводит движение уже созданного объекта.

Для этого API разделено явно:

```gdscript
var initial = SourceOrbit.initialize(record68, epoch_tick, epoch_day)
var updated = SourceOrbit.advance(initial, current_tick, current_day)
var rebuilt = SourceOrbit.evaluate_from_epoch(record68, current_tick, current_day)
```

`initialize` повторяет исходный F880, включая указанную перестановку только в первичном расчёте фазы. `advance` прибавляет обычную дельту времени по орбитальной ветви F866. Закреплённый JJFFE при изменении старшего слова фазы всегда пересчитывает F1507; при неизменном слове оставляет позицию прежней. Ускоренный старый путь DOS здесь не заявляется как воспроизведённый.

`evaluate_from_epoch` объединяет эти операции с фиксированной начальной точкой исходных часов: `tick=0x80000000`, `day=0x121cf7`, начало игры в 3250 году. Явные четвёртый и пятый параметры позволяют задать другую пару `epoch_tick`, `epoch_day`. Это политика привязки нашего мира: любой вход в систему или восстановление сохранения использует ту же точку, а не новую инициализацию в момент загрузки. Поэтому разбиение времени на кадры и время повторного входа не меняют орбиту. Прежний краткий вызов `evaluate(record, tick, day)` оставлен как совместимый расчёт **из нулевой точки `0,0`**; он не означает F880 на текущем времени. Игровой мир должен выбирать `evaluate_from_epoch`.

`advance` переносит только фазу и относительную позицию обычного орбитального объекта. Полные флаги F866, поворот поверхности, ориентация и прочая физика остаются вне этого API.

F1507 берёт грубый угол из старшего слова фазы, получает два Q31-вектора через исходную таблицу синуса и интерполирует между ними. F1508 отдельно обрабатывает старшую и младшую 16-битные части дробного приращения. Сохраняются знаковость мантиссы, усечения промежуточных 32-битных произведений, переносы между словами и переполнение координат по модулю `2^64`. Процедура сдвига F1341 сохраняет исходное маскирование x86-счётчика даже для величин за пределами 63 бит. Замены на постоянную угловую скорость с `float`, `sin()` или обычный 64-битный сдвиг здесь нет.

Оси F1506 остаются исходными: при нулевой фазе радиус направлен вдоль `+Z`, при четверти оборота и нулевом наклонении — вдоль `−X`, верх — `+Y`. Перестановка координат локального городского профиля к этим глобальным векторам неприменима.

Дополнительные чистые операции:

```gdscript
var phase_change = SourceOrbit.phase_delta(rate, old_tick, old_day, new_tick, new_day)
var advanced = SourceOrbit.interpolate(position_words, increment_words, orbit_packed, delta_u32)
var absolute_raw = SourceOrbit.add_positions(parent_raw, relative_raw)
```

`interpolate` возвращает новое состояние, оставляя входные массивы без изменений. `add_positions` требует два `PackedInt64Array` длины 3 и воспроизводит F1661: складывает каждую координату по модулю `2^64`. Это соответствует обычной цепочке орбитальных родителей F1677, без дополнительного вращения дочерней луны матрицей вращения планеты. Порты на поверхности обрабатываются отдельно. Сначала следует суммировать исходные целые координаты всей цепочки, затем преобразовывать в метры и вычитать положение наблюдателя; раннее преобразование больших абсолютных координат в `Vector3` теряет точность.

Перевод исходной длины в метры, установленный отдельной проверкой: `metres = raw × 16785 / 2^24`. Для орбит нужно использовать упакованную запись после исходного кодирования, а не исходный десятичный аргумент её конструктора. Само это ядро единицы не переводит.

## Независимая проверка

`tests/fixtures/source_orbit_native.json` строится инструментом `tools/rebuild_source_orbit_native.py`, который выполняет извлечённые процедуры закреплённой версии JJFFE. Контроль F880 включает 112 реальных записей объектов исходных систем, исключая наземные порты, в десяти состояниях часов и 640 граничных наборов, итого 1760 инициализаций. В каждом случае сравниваются скорость, оба слова фазы, все шесть слов координат, три приращения, дополнительный вызов F1508 и отдельный F1510.

Отдельные 560 случаев выполняют настоящий фрагмент F880 в фиксированной начальной точке игры, затем настоящий фрагмент орбитального обновления F866. Сравниваются начальная фаза, последующая фаза, полные координаты и приращения. Нативное выполнение одним шагом сопоставляется с выполнением через промежуточное обновление на 0,125 суток; полный итоговый буфер объекта должен совпасть. Тест Godot дополнительно проверяет тот же путь через `advance` и `evaluate_from_epoch`, включая сохранение исходного состояния.

Ещё 50 нативных вызовов F1661 проверяют сложение относительной и родительской позиции: Луна, Фобос, Харон и случаи переноса/переполнения полного 64-битного слова. Полные знаковые 64-битные значения сохраняются в JSON десятичными строками, чтобы избежать округления JSON-чисел. Память объекта проверяется с контрольными байтами; выполнение повторяется в трёх новых процессах и в обратном порядке.

Тест Godot: `godot --headless --path . --script tests/test_source_orbit.gd`. Результат текущей проверки: **24 528 проверок, 0 ошибок**. Он проверяет результаты с независимыми нативными контрольными данными и неизменность входов. Это проверка указанного арифметического ядра; она не подтверждает полноту всей симуляции оригинальной игры или производительность Android.
