# Исходные орбиты в восстановленной игре

В новых полётах версии 0.11.10 центры небесных тел одиннадцати восстановленных систем рассчитываются по упакованным исходным записям FFE. Эта смена относится к орбитам; она не заменяет текстуры, управление или весь физический движок игры.

## Какие данные используются

Конструкторные записи F873/F874 сначала проходят восстановленное преобразование F878. Расчёт получает именно полученные 68-байтовые записи `runtime_record_hex`. Исходные шаблоны `record_hex` сохраняются отдельно. В каталоге имеются 130 объектов: 92 небесных тела, 17 орбитальных портов и 21 наземный порт.

Для положений используется явно обозначенный вариант `jjffe-7e54034-q31-orbit`, закреплённый за коммитом JJFFE `7e540341d4e09aa3c92877b87d49e7f2c143ad8d`. Его процедуры F1507/F1508 отличаются от загруженной DOS-версии. F1506, F1509 и F1510 сохраняют исходные алгоритмы. Поэтому результат нельзя называть полным побитовым воспроизведением всех орбит DOS-игры.

F880 первоначально передаёт слова времени в F1510 в особом порядке. Для нового полёта применяется этот исходный порядок при фиксированной начальной дате: полдень 1 января 3250 года (`tick=0x80000000`, `day=0x121cf7`). Дальнейшие положения вычисляются из начального состояния с обычным приращением времени F866. Начальная дата остаётся постоянной при переходах между системами и загрузке сохранения. Повторная инициализация F880 на каждой запрошенной дате дала бы другую, неверную для этой схемы траекторию.

## Координаты и локальный полёт

Компоненты положения тела и его родителей складываются в исходном целочисленном пространстве signed64 с переносами. Обычные небесные тела не получают вращение поверхности родителя. Затем применяется установленный масштаб `16785 / 2^24` метра на исходную единицу, а компоненты XYZ переводятся в астрономические единицы с двойной точностью. Дополнительного отражения оси Z нет.

Локальный `Vector3` создаётся после вычитания начала отсчёта выбранного тела. Это сохраняет точность манёвров около планеты при большом расстоянии от звезды. Вращение поверхности, широта и долгота продолжают использовать существующий сферический модуль; его соглашение о долготе уже учитывает знак Z.

Радиусы, массы, вращение поверхности, гравитация, столкновения и параметры корабля пока остаются явно обозначенным адаптером `analytic_si_rebuild_v1`. Изменение центров не означает восстановления оригинальной физики FFE. Данные орбитальных портов проверяются в отдельном исходном расчётном модуле; текущий мировой рендерер и стыковка ещё не размещают настоящие станции по этим исходным орбитам. Наземный путь F879 также требует отдельной работы.

## Старые и новые сохранения

- Обычный вызов `PlanetarySystem.configure(star, "current")` сохраняет прежнее поведение. Новая игра в `Main` явно выбирает `handcrafted_jjffe_orbits_v2`.
- Старые сохранения `starfrontier-rebuild-world-v1` загружаются с прежними аналитическими положениями. Их формат, идентификатор набора данных и содержимое снимка не изменяются.
- Новый снимок `starfrontier-rebuild-world-v2` хранит выбранное семейство в `preferred_layout`. Даже если для посещённой системы доступны только звезда и пустой резервный мир, возвращение в известную систему восстанавливает исходные орбиты.
- Переход между системами сохраняет выбор новых исходных орбит. Старые полёты используют прежний выбор текущего аналитического адаптера; исторический Solar при последующем переходе также возвращается к этому правилу. Загрузка старого полёта не переводит его автоматически на новые орбиты.
- Орбитальные кэши являются производными данными и не записываются в сохранение. Неудачная загрузка сохраняет прежнее состояние и кэши целиком; успешная пересоздаёт соответствующий набор данных.

Кэш привязан к двум исходным словам времени. Запросы положения, гравитации и локальных координат при той же паре слов используют один расчёт всех тел. Смена выбранного тела меняет локальное начало отсчёта без повторного расчёта орбит. Полученные массивы координат можно изменять без повреждения кэша.

## Независимая проверка

`tests/test_source_orbit_integration.gd` содержит неизменяемые контрольные значения из опубликованного коммита 0.11.9 `c0d6f0153994ce1bd94eae441a4007ab0c6ac33d`. Они сняты с отдельной копии проекта до изменения реализации. SHA-256 старого `planetary_system.gd`: `6c4b6f4fc8018261740c586762a21c38f5275185a532a3677da1a51cfcddc1ca`.

Контроль сохраняет полные описания тел и портов, старый снимок, идентификаторы данных и относительные, абсолютные и локальные положения в дни 0, 0.25, 365.25 и 100000 для всех одиннадцати систем. Отдельно закреплены старые резервные миры Solar и Empty.

Новые положения сравниваются с `tests/fixtures/source_orbit_native.json`: исходные процедуры запускаются отдельным нативным инструментом, без получения ожидаемого результата из проверяемого GDScript. Интеграционная проверка использует случаи жизненного цикла `epoch_update_cases`: исходная инициализация на фиксированной эпохе и обновление до нужной даты. Проверяются исходные записи, направления осей, иерархия звезда–планета–спутник, сохранение локальных параметров, кэши и атомарный отказ загрузки.

Также запускается настоящая сцена Main: первый полёт, кнопка новой игры, гиперпереходы, переход через пустую систему, запись и чтение полной игры, загрузка старого формата, ручная посадка вне площадки исходного города и автоматический выход на орбиту с повторной загрузкой во время подъёма.

Запуск без графического ускорителя:

```sh
godot --headless --audio-driver Dummy --path . \
  --script tests/test_source_orbit_integration.gd -- --rebuild-capture
```

Флаг `--rebuild-capture` обязателен. Тест использует настройки в памяти и отдельный временный каталог сохранений, затем удаляет только созданные им файлы. Файлы пользовательского прогресса и исходные JSON-данные не изменяются. Проверка подтверждает вычисления и переходы состояний; изображение, производительность и нагрев телефона требуют самостоятельной проверки Android-сборки.
