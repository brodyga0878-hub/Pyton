# Проверка реального Main в полном исходном мире

`tests/test_source_main_full.gd` запускает настоящую сцену `scenes/main.tscn` и явно переключает её на `World.FULL_LAYOUT` после `_ready`. Это проверка взаимодействия готовых модулей через Main, а не дополнительный самодельный контроллер полёта.

Запуск разрешён только с `--rebuild-capture`. Настройки подменяются памятью, качество для теста ставится0; хранилище прогресса также подменяется памятью. Проверяется, что за весь тест не произошло ни одной записи. `_process` и `_physics_process` сцены отключены, затем используется реальный `_tick` с управляемым шагом. Подготовка крышки проходит через настоящий Main `_pump_underground_geometry` и Godot Thread. При ожидании готовой геометрии тест пропускает кадры основного потока, не прокручивая искусственно минуты физики за время одного worker.

Проверяемые пути:

1. Исходный каталог Navigationv2: выбор доступной соседней системы, заряд гиперперехода, сохранение/восстановление ожидающего перехода, отмена кнопкой торможения без расхода топлива, завершённый прыжок и построение настоящей системы Worldv4.
2. Внутрисистемный перелёт к реальной орбитальной станции72: сохранение/отмена ожидающего перелёта, повторный перелёт и привязка исходного Flightv5.
3. Физический автозаход Main: подлёт к исходной внешней точке, выравнивание, вход в действительный проём и стыковка без повреждений. Ограниченная начальная тестовая позиция находится снаружи реального входа; дальнейший путь исполняется физическими шагами, без переноса корабля сквозь стены.
4. Сохранение настоящего пристыкованного Flightv5. Поддельные скорость пристыкованного корабля и ненулевой target_speed отвергаются атомарно без замены живых моделей. Отдельный допустимый начальный снимок задаёт уже закрытые ворота: реальное касание нижней консоли запрашивает открытие, вылет ожидает в ангаре, это ожидание сохраняется/загружается, торможение отменяет заявку, повторное касание восстанавливает заявку, F865 открывает ворота и Main выполняет физический вылет. Тест не перескакивает через закрытую стену и проверяет сброс сохранённой заявки.
5. Настоящий экран служб выбранного исходного порта: сигнал кнопки заправки расходует20 кредитов на две единицы топлива. После физического вылета команды обслуживания отвергаются. Рыночная экономика исходной FFE этим тестом не объявляется реализованной.
6. Новая Москва84: вход через Main, исходный рельеф v4, проверенный свободный вертикальный коридор вне площадки, физическое касание здоровым кораблём, сохранение/восстановление и взлёт положительным телефонным lift. Начальная позиция задаёт только посадочный тестовый район; касание и подъём проходят через Main `_tick` и реальные коллизии/гравитацию. Время намеренно начинается с3,75суток; на каждом восстановлении поверхности проверяются сохранённое неравное нулю время и точное сохранение всех Q31-матриц вращения тел без возврата к начальной эпохе.
7. Лунный закрытый ангар96: обычный наземный перелёт Main, открытие исходной крышки через worker, полный физический автозаход через крышу к полу, закрытие над кораблём, сохранение/загрузка, проверка повреждённого состояния крышки и вылет через действительную геометрию с последующим закрытием. Взлёт запускается настоящей парой событий `InputEventScreenTouch` на кнопке нижней консоли: это проверяет путь телефона до действия Main, а не только прямой вызов функции. Дополнительно проверяется совпадение показанной крышки с физическим состоянием и сохранение одного статического меша города при открытии.
8. Настоящий Main-экран отчёта: в уникальном временном приватном каталоге создаётся реальный Diagnostics ZIP с явным включением полного текущего сохранения. Проверяются JSON-совместимость фактического `_payload`, побайтовое совпадение `game-save.json`, восстановление извлечённого сохранения через Main, исходный контракт мира/текущее время в метаданных и SHA/размер каждого файла по манифесту. Системный SAF picker не открывается; временные файлы удаляются после остановки коллектора.

Старые режимы/сохранения по умолчанию теста не модифицируются. Производительность на настоящем Samsung S23 Ultra, APK-установка и проверки сенсорного ввода устройства остаются отдельными выпускными проверками. После завершения правок физического отображения исходной поверхности: **117 проверок,0 ошибок,90,671с**. Повторяющиеся кадры без задания worker не увеличивают число проверок.
