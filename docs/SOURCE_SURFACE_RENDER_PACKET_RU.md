# Подготовка геометрии исходной поверхности на рабочем потоке

`scripts/source_surface_render_packet.gd` создаёт только CPU-массивы для
`sphere-source-ground-v4`. `prepare(globe,options)` получает отдельный,
уже настроенный рабочий экземпляр `SourceSurfaceTerrain`. Она не создаёт
`Node`, `ArrayMesh`, материалы или другие объекты публикации в сцене.
Рабочий поток не должен использовать живой физический экземпляр поверхности.

Каждая высота берётся из `globe.sample(x,z)`: сохраняются исходное поле
F574/F581/F1876, непрерывное направлениеQ31, общая интерполяция и объявленное
выравнивание города. Отдельных придуманных высот или таблицы готовых ответов
в этом модуле нет.

По умолчанию центральная область имеет ширину4000м и64×64ячейки:
4225вершин,24576индексов. Для центральных нормалей запрашивается сетка с
одним дополнительным рядом с каждой стороны; используются действительные
центральные разности высот. Диагональ и порядок центральных треугольников
совпадают с физической сеткой `SurfaceModel`.

Дальние кольца8/32/128км имеют16отрезков на сторону и2радиальных полосы —
204вершины на кольцо. Они ограничены `globe.maximum_patch_extent()`, чтобы
локальная высотная сетка не переходила через край несферического тела.
Расширенный полёт может добавить кольцо до512км с тем же ограничением.
Нормали колец усредняются по действительным подготовленным треугольникам;
дополнительных запросов рельефа для них нет. Цвета и координаты материалов
сохраняют правила существующего визуализатора.

## Контракт пакета

`prepare` возвращает `ok`, ревизию `source-surface-render-packet-v1` и:

- `frame`: скалярные `latitude`, `longitude`, `radius`, SHA256полной68байтной
  исходной записи в `record_hash`, ревизию рельефа и домен исходной записи;
- `meshes`: первый элемент с `role=core`, затем кольца с `role=ring`;
  каждый содержит `vertices`, `normals`, `colors`, `uv`, `uv2`, `indices`,
  конечный `bounds:AABB`, имя и внутреннюю/внешнюю границы;
- `material_origin`: тело-фиксированное начало, округлённое до1024м;
- размеры сетки, `kind`, `extended_flight` и непрозрачную строку `source_key`
  вызывающего контроллера;
- количество `sample`-вызовов, статистику кэша до/после, затраченное время
  и `source_query_count` — прирост счётчика `cache_stats().source_samples`.

Последний счётчик считает исходные направленные пробы: обычная сферическая
модель выполняет внутри такой пробы дваF574, исправленный вызывающий контекст
модели117 — один. Он не называется количеством кадров или FPS телефона.

`valid(packet)` проверяет типы/размеры всех упакованных массивов, конечность
вершин/UV/нормалей/цветов/рамки, границы индексов, нормализацию нормалей,
границы мешей и точную центральную топологию/размещение ячеек. Публикация
пакета и проверка текущего тела/поколения остаются обязанностью контроллера.

## Быстрое перемещение центральной сетки

`core_offset:Vector2` по умолчанию нулевой. Он задаёт смещение центральной
сетки внутри неизменной региональной касательной рамки. Вершины и запросы
высот получают это смещение, а `frame` остаётся прежней. При
`include_rings=false` подготавливается только центральная сетка.

Для шага62,5м смещение выбирается целым числом ячеек. В перекрывающейся
области координаты запросов, высоты и нормали совпадают побитно. Можно
повторно использовать кэш исходного поля и сохранять постоянные начальную
центральную сетку/дальние кольца, пока готовится новая центральная область.
У актуального центрального меша начало определяется его первой вершиной;
оно не обязано равняться`−width/2` в региональных координатах.

## Проверка

`tests/test_source_surface_render_packet.gd` запускает настоящий рабочий
поток. Синтетический пробник используется только для контроля геометрического
контракта. Отдельно проверяются настоящие Земля129 и Hyperion117 исходной
системыSol: вершины равны прямым запросам общего исходного поля, а
перекрывающиеся центральные сетки при смещении на ячейку совпадают побитно.
Повреждённые индексы, нечисловые вершины, неверная топология/рамка и
вырожденные нормали отвергаются.

Обычный набор:4222проверки,0ошибок скриптов. Дополнительный флаг
`--render-packet-benchmark` измеряет полные размеры и последовательные
центральные смещения на рабочем потоке. Это измерение облачного CPU,
не проверка плавности на SamsungS23Ultra.

Измерение в облачной среде6ноября2026года:

| Тело | Начальный пакет | Пробы поля | Следующее ядро62,5м | Пробы поля | Ещё одно ядро125м | Пробы поля |
|---|---:|---:|---:|---:|---:|---:|
| Земля129 |1182,756мс |667 |48,870мс |0 |49,229мс |0 |
| Hyperion117 |7191,636мс |14603 |193,601мс |158 |184,866мс |142 |

Все эти вычисления выполнены на рабочем потоке. Счётчики показывают пользу
постоянной региональной рамки: центральные сетки повторно используют
исходные узлы, а дальние кольца не строятся при каждом смещении.
Расширенный набор вместе с измерениями:4240проверок,0ошибок скриптов.
