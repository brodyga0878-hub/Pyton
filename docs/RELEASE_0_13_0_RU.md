# Карты, время и полёт — 0.13.0

Кандидат **0.13.0-navigation-alpha1 / Android code 36** продолжает
блок 9 на основе принятого Worldv4. Runtime зафиксирован после итоговых
функциональных проверок; настоящий ARM64 APK собран и технически проверен.
Точный source ZIP опубликован; неизменяемые HTTPS-ссылки проверены скачиванием. Исходники и артефакты
0.12.0/0.12.1 остаются неизменёнными контрольными точками.

## Галактическая карта

Вместо прежнего списка систем подключены `galactic_map_model.gd` и
`galactic_map_view.gd`. Экран работает с настоящими исходными секторами,
координатами и названиями: перемещение по секторам, изменение масштаба,
выбор звезды, её сведения, отображение текущей системы и доступной
дальности, передача выбранной системы существующей навигации.

Обзор использует извлечённые исходные данные FFE: плотность, таблицу
перехода к палитре, низкую RGB6-палитру и исходные ориентиры.
`data/ffe_galactic_map.json` имеет проверенное происхождение из EXE и
закреплённого JJFFE. Для плотности использованы независимые исходные
контроли F853 при настоящих масштабах обзора. Рендер и сенсорная проекция
написаны заново; это **не пиксельная копия полного исходного renderer**.

Поиск ограничен ближайшим окном и исходным каталогом именованных систем.
Это не глобальный индекс всех процедурных названий. Для построения всего
каталога галактики и всех оригинальных поисковых инструментов готовность
не заявляется. Расстояния исходные; дальность трёх корабельных профилей,
расход топлива и время гиперперехода по-прежнему адаптированы. Полный F903
остаётся отдельным результатом блока 9.

## Карта системы

`system_map_model.gd` и `system_map_view.gd` отображают иерархию настоящих
тел и портов, исходные орбитальные положения, выбор цели, масштаб и
центрирование. Выбранные тело и космопорт передаются существующим
действиям Main. Предпросмотр орбит по времени является состоянием карты,
а не изменением времени настоящего полёта или сохранения.

В карту передаётся снимок действующего мира; его подготовка не подменяет
игровую систему другой генерацией. Открытие карты освобождает удержанные
пальцы и блокирует полётный ввод. Закрытие возвращает управление.

## Ускорение времени и крен

Подключены настоящий `flight_time_controller.gd`, его сенсорная панель
`flight_time_controls.gd` и аналоговый `roll_control.gd`.

- Рабочие ступени времени: **×1, ×10, ×100**. **×1000 и ×10000 отключены**
  с объяснением в интерфейсе.
- Планировщик выполняет до 32 подшагов по не более 0,1 секунды. После
  каждого исполненного шага заново проверяются условия безопасности;
  учитываются только действительно выполненные шаги.
- Поверхность, док, сближение, ручной ввод, автоматический полёт, переходы,
  меню, пауза и фон ограничивают или останавливают ускорение. Это явная
  мобильная политика, а не заявление о полном переносе исходного scheduler.
- Две сенсорные области дают дозируемый крен. Отпускание, пауза, потеря
  фокуса и переходы освобождают их указатели.

Исходные F207/F208/F217/F220/F1418 отдельно проверены настоящим host-native
исполнением. Это независимые контроли исходных таймерных примитивов;
текущий ограниченный планировщик Main остаётся новой реализацией.

## Вращающийся док и исходное движение

`rotating_dock_dynamics.gd` связывает измеренные позы станции, её угловую
скорость и относительную скорость контакта `ω×r`. Flight получает
интервал через координатор станции и проверяет консервативный проход
между позами. Корабль ручного управления не выравнивается автоматически
по станции. Контакт использует современную аппроксимацию; **полный
исходный F582 и угловой rigid-body интегратор не заявлены**.

`source_motion_pipeline.gd` переносит исходную композицию
F603 → F607/F599 → F601/F602 → F1512 с целыми скоростями, дробными
остатками и raw64-положением. `source_motion_bridge.gd` подключает её
к настоящему Main в узкой области:

- новые Full-сеансы могут использовать этот путь для Cobra вокруг одного
  фиксированного естественного фокусного тела;
- порты, поверхность, вертикальная помощь, другие корпуса и случаи вне
  контракта сохраняют существующий путь движения;
- оси телефона и шкала номинальных дней описаны отдельными политиками;
  это не скрытая замена исходных единиц;
- состояние хранится в необязательном `motion_session`; старые сохранения
  без этого поля продолжают прежний расчёт, а не переключаются молча.

Активный source-motion снимок хранит точные IEEE64-биты дней вместе с
дробным остатком ticks. После проверки снимка Main восстанавливает точные
часы через `elapsed_days()`, сохраняя продолжение после JSON. Для новых
сеансов с включённым source-motion время зарядки перехода учитывается
через `dt` на общих часах; старые payload сохраняют прежний контракт.

`source_frame_kinematics.gd` отдельно содержит проверенные F572/F573.
Автоматический выбор родителя/системы отсчёта F570/F606, перенос начала
координат и полный исходный покадровый player pipeline ещё не подключены.
Наличие этих примитивов не закрывает все исходные динамику, атмосферу,
топливо, столкновения и взаимодействия корабля.

## Проверка и границы готовности

Проверяющий инструмент APK для code 36 требует все **11 новых модулей**,
исходный JSON карты и реальные связи с Main. Старые проверки исходных
миров, орбит, портов, консоли, MB4 и ресурсов сохраняются. В актуальном
пакете проверяется 22 JSON основного набора вместо 21; новый map JSON
проверяется также по происхождению, палитре и независимому native fixture.
Фикстуры и host-native инструменты в APK не включаются.

сенсорного управления; **28 проверок** точного продолжения source-motion
