# Проверка действий служб через настоящий контроллер

`tests/test_dock_service_actions.gd` проверяет связку настоящего `Main`,
`DockServicesView`, сенсорных кнопок, учебных транзакций, навигации и вида корабля.
Это интеграционные условия сверх отдельных тестов котировок и интерфейса.
Проверка не означает восстановления оригинальной экономики FFE.

## Сценарий обслуживания

Корабль действительно стыкуется с доступным учебным узлом через `Flight.dock()`.
Кнопка нижней панели «Службы» открывает страницу настоящим сенсорным событием.
Покупка еды проходит через `Input.parse_input_event`, включая эмуляцию мыши
первого пальца. Затем кнопки страницы передают остальные команды контроллеру.

Проверяемые результаты учебных операций заданы независимо от вывода страницы:

| Действие | Ожидаемый результат |
| --- | --- |
| Покупка 1 т еды | −30 кр., +1 т груза |
| Продажа этой еды | +24 кр., груз возвращён к исходному |
| Ремонт корпуса с 75,25% | 100% корпуса, −50 кр. |
| Заправка с 9/12 | 12/12, −30 кр. |
| Доставка 2 т лекарств | лекарства списаны, +800 кр., заказ завершён |
| Обмен исправной Cobra на Eagle | +4000 кр. по учебным ценам, выбран Eagle |

После обмена проверяются профиль визуального корабля и его размер 26 м.
Ссылки на четыре игровые модели и сам вид служб сохраняются. Страница
обновляет название, баланс и трюм; её экземпляр и ненулевая позиция прокрутки
не меняются после выполнения команды и пересчёта разметки.

## Сохранение и ограничения

Основной запуск использует `--rebuild-capture`: запись игрового прогресса
отключена, успешные операции не создают поколений сохранения. Отдельно
включается политика сохранения и проверяется ровно один вызов записи на
принятую команду. Вместо файлового хранилища внедрён совместимый `MemoryStore`:
он считает поколения и сохраняет копии данных только в памяти. Содержимое
записи сверяется с полным результатом настоящего контроллера.

Отказанные команды при отсутствии стыковки, разрушенном корпусе, нехватке
средств и в исходном космопорту не меняют полный игровой payload и не создают
поколений. Исходный порт выбран из настоящих восстановленных орбитальных
поселений; у него нет кнопок учебной торговли. Прямой вызов `Navigation.refuel`
также отклоняется без списания кредитов или пополнения топлива.

## Жизненный цикл интерфейса

Проверяются захват пальца и его освобождение при потере фокуса, закрытии
служб и переходе на другую страницу. Невидимая или отсоединённая старая кнопка
не выполняет транзакцию на отпускании. После возвращения фокуса действующая
страница снова принимает ввод. Настройки загружаются из внедрённой памяти;
пользовательские настройки и сохранения не читаются и не перезаписываются.

## Ошибка, обнаруженная интеграционной проверкой

Первый сенсорный запуск покупки успешно изменил груз и баланс, но создал
ошибку движка: после испускания `pressed` страница обновила котировки,
отсоединив старую кнопку. Её обработчик затем обращался к уже отсутствующему
viewport, чтобы отметить событие обработанным. Отдельные тесты модели и вида
такой путь не исполняли.

Первичный журнал: `/workspace/recovery/dock-service-action-tests-red.log`.
В нём 58 проверочных условий формально проходят, но присутствует `SCRIPT ERROR`;
такой запуск не считается успешным. После изменения порядка обработки событие
поглощается до вызова обработчика, способного заменить страницу.

В `tests/test_touch_action_button.gd` добавлены проверки отсоединения кнопки
во время `pressed` для настоящего touch и мыши. Проверяются ровно одно действие,
освобождённый захват, отсутствие узла в дереве и поглощённое событие.
Набор кнопки после расширения: **34 проверки, 0 ошибок**, чистый журнал
`/workspace/recovery/touch-action-button-tests.log`.

Итог связки контроллера: **63 проверки, 0 ошибок**; журнал без ошибок движка,
скриптов и утечек: `/workspace/recovery/dock-service-action-tests.log`.
После исправления проверка покупки проходит именно настоящим сенсорным путём,
поэтому отсутствие ошибки отсоединённой кнопки проверяется повторно.
Это desktop Godot 4.6.3; нативный Android и физический телефон здесь не проверены.
