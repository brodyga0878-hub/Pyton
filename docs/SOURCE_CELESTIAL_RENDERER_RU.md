# Небесные тела полного исходного мира v4

Новые ветви `celestial_renderer.gd` действуют только для
`source_jjffe_systems_v4`. Старые миры, их SphereMesh, освещение,
аналитическое вращение и переходы поверхности сохраняют прежний путь.
Независимые контрольные снимки0.11.7 продолжают совпадать.

## Исходный кадр и настоящий источник света

Полный мир задаёт ориентацию тела через
`World.body_rotation_basis(id,days)`: это существующий перенос исходной
Q31-матрицы F880/F866/F1675 с сохраняемым состоянием. Renderer не делит
дни на `rotation_hours`. Нулевой исходный период вращения поэтому не
создаёт NaN в преобразовании видимого тела.

Свет выбирается среди действительных исходных строк `kind=star`,
type17…30. Для каждого тела используется ближайшая такая звезда.
Барицентр не является светилом, даже если его ID буквально равен `star`.
Это особенно важно для двойных и тройных систем. Применяется настоящий
вектор между текущими исходными центрами, переведённый в глобальный кадр
renderer. Это явно современная политика ближайшего светила, а не полный
многозвёздный расчёт яркости/спектра и затмений оригинала.

Публичный `source_light(body_id,days)` возвращает ID выбранной звезды,
направление и обозначение политики. Его может использовать вызывающий
контроллер для согласования собственных световых узлов. Небесные
материалы получают это направление непосредственно.

## Настоящие высоты, ограниченный глобальный LOD

Выбранное пригодное для посадки тело получает глобальную mesh из
`source_global_body_mesh.gd`. Источник высот — тот же
`SourceSurfaceTerrain.elevation(lat,lon)` с той же исходной68-байтной
записью, политикой непрерывной Q31-сетки и реальными профилями городов,
который использует поверхность v4. Авторское синусоидальное поднятие
для новой mesh не добавляется.

Для ограниченной стоимости берутся24×12интервалов исходных высот:
325сохранённых узлов с повтором шва и полюсов. Более плотная mesh64×32
содержит2145вершин и интерполирует эту глобальную сетку. На исходных
узлах высота совпадает с поверхностью; между ними это **приближённый
глобальный LOD**, а не точный локальный рельеф и не исходный адаптивный
planet painter. Геометрия использует исходные XYZ непосредственно и
поворачивается той же матрицей тела. Современное окрашивание, облака и
карты отделки остаются художественными материалами, а не восстановленной
исходной цветовой VM.

Самплер создаётся целиком в отдельном worker на неизменяемой копии
записи тела и относящихся к нему поселений. Worker не получает живой
World или самплер физики и не создаёт узлы сцены. Главный поток только
устанавливает готовые массивы в ArrayMesh. Отмена проверяется до работы
и между исходными узлами. Одновременно работает не больше одного worker;
следующий выбранный объект заменяет ожидаемую задачу.

Renderer хранит максимум4готовых результата. Активная исходная глобальная
mesh назначена только текущему фокусу; прежнее тело возвращается к
своей дальней сфере. При возврате готовая mesh берётся из кэша. Ключ
включает ревизии, исходную запись и записи поселений. Качество материала
не меняет высоты, а `update_view()` не выполняет F603 и не опрашивает
рельеф. В native-переходе применяется настоящий опорный радиус без
старого художественного уменьшения на350м.

Проверка настоящего Sol-тела117 обнаружила, что интерполяция глобального
LOD в одной точке находится примерно на10903,43м **выше** точного поля.
Чтобы такая поверхность не закрывала подробную землю при снижении,
контроллер передаёт текущий самплер через
`set_source_ground_patch(globe_or_null)`. Это только производный контекст
показа, без запроса высот и без сохранения ссылки на живой самплер.

Опциональная маска `source-ground-angular-cap-v1` использует фактический
`maximum_patch_extent()` поверхности, включая меньшую ось117. Её круг
занимает90% от вписанного радиуса реально нарисованного участка;
угол дополнительно ограничен консервативным внешним радиусом тела.
Внутри этого круга глобальная поверхность полностью убирается при низком
полёте и возвращается экранными долями вместе с космическим слоем.
За кругом исходный глобальный горизонт остаётся. Готовая mesh и временная
SphereMesh используют одну маску в мировых координатах, независимо от UV.
Vertex, исходные ветви окраски/освещения и прежний выход shader сохранены
побайтово; новый shader-uniform по умолчанию выключен.

Камера полного мира переводится из локального поверхностного кадра обратно
в инерциальный кадр перед вычислением дальних центров. Это сохраняет
положение маски и остальных тел при высоком поверхностном полёте.

`source_mesh_state()` показывает `pending/building/ready/failed/unsupported`,
фокус и лимит кэша. Пока worker готовит данные, видна обычная дальняя
сфера; неподдерживаемая звезда не получает вымышленного рельефа.
При сборке контрольного скриншота нового рельефа следует дождаться `ready`.

## Проверка и пределы

`test_source_celestial_renderer.gd`:150условий без ошибок. Проверены
действительные source-Earth высоты против отдельного поверхностного
самплера, шов, конечные нормали, границы массивов/кэша, отмена, реальный
асинхронный worker source-Moon, возврат кэша, независимость геометрии от
качества и кадрового обновления. Отдельная двойная система проверяет
барицентр с ID `star`, выбор ближайшего светила и нулевой период
вращения без NaN.

`test_world_surface_invariants.gd` также проходит681условие с прежними
независимыми0.11.7контрольными mesh/физикой и actual Main. Native-арифметика
самих исходных высот и вращения проверяется соответствующими отдельными
эталонами; этот renderer-тест подтверждает их связь с новой mesh.

`test_source_surface_cap.gd`:86условий headless и88с настоящим GLES
renderer. Воспроизведён указанный117выступ, проверены Earth, фактический
размер близкого участка, сохранность дальнего горизонта и переходы0/0,5/1.
В GLES-контроле настоящий coarse117закрывал красный контроль точной земли
(пиксель≈`[0.2353,0.2157,0.1882]`); после маски видна земля
(≈`[0.9020,0.0039,0]`). Это специальный тест материала, не игровой скриншот.
Прежние `test_world_planet_shader.gd`29контролей байтовых разделов и
`test_world_surface_colour_render.gd`48GLES-контролей также проходят без
изменения эталонов. GLES проверен через llvmpipe, а не GPU телефона.

Глобальный LOD не доказывает точный бесшовный локальный треугольник на
каждом расстоянии. Полный исходный adaptive renderer, все исходные
цветовые команды и FPS на Samsung S23 Ultra здесь не объявлены
завершёнными. Изменения относятся к показу полного мира и не меняют
записи тел, радиусы физики или столкновения поверхности.
