# Исходный календарь и отображение времени FFE

`scripts/source_clock.gd` воспроизводит две исходные процедуры:
**F1357** переводит unsigned32-счётчик дней в числовую дату, **F1363**
переводит unsigned32-слово внутрисуточных тиков в `HH:MM:SS`.
Русские сокращения месяцев добавлены в интерфейсном адаптере.

Это завершённый примитив календаря и отображения. Он не объявляет
перенесёнными исходный накопитель времени, ускорение времени, планировщик,
эфемериды, анимацию, вращение или физику тел.

## Начальная дата

В исходном F147 стоят два слова:

- `DATA_008807 = 0x00121cf7` — номер дня;
- `DATA_008804 = 0x80000000` — внутрисуточное слово времени.

В пользовательском `FIRSTENC.EXE` эти две соседние инструкции подтверждены
по смещению `0xa1da`. Применение настоящих F1357/F1363 даёт
**12:00:00, 1 января 3250 года**. Год 3200 из показанного пользователем
старого скриншота не подставляется вместо подтверждённой начальной даты FFE.

Календарь использует циклы **1461 день**. Первый год каждого четырёхлетия
високосный, включая год 0; исключений для столетий по григорианскому правилу
нет. Обычная библиотека календаря Python или системная дата Android не
является заменой этому алгоритму.

## Исходное округление времени

F1363 сначала делит слово тиков на **49710 (`0xc22e`)** целочисленно,
затем выделяет часы, минуты и секунды. Это исходная константа отображения,
а не точное отношение `2^32 / 86400`.

`49710 × 86400 = 4294944000`, что на 23 296 меньше `2^32`. Поэтому самые
последние 23 296 значений слова времени исходная процедура отображает как
**`24:00:00`**, пока слово дней ещё не увеличилось. Модуль сохраняет этот
результат. Он не исправляет его на `00:00:00` и не меняет дату за вызывающую
сторону.

## API и связь с нынешней игрой

```gdscript
const Clock = preload("res://scripts/source_clock.gd")
var original = Clock.decode(0x121cf7, 0x80000000)
var display = Clock.from_elapsed_days(navigation.elapsed_days)
```

`decode` принимает целые значения unsigned32, включая точно представимые
числовые значения из JSON. Он возвращает `day_u32`, `tick_u32`, `year`,
`month`, `day`, `hour`, `minute`, `second`, `date_ru`, `time_ru`, `label_ru`.
Для начальных слов `label_ru` равен `12:00:00 1-янв-3250`.
Неверные типы, дробные слова, отрицательные значения, переполнение,
`NaN` и бесконечности дают пустой словарь.

`from_elapsed_days` — **явный интерфейсный мост** от существующего
`Navigation.elapsed_days`. Диапазон 0–1 000 000 000 суток совпадает с
нынешней валидацией навигации. Начальный полуденный сдвиг учитывается
переносом слова тиков; целая и дробная части разделяются до прибавления
сдвига, чтобы сохранить доступную точность дроби. Результат дополнительно
содержит `elapsed_days`.

Мост использует уже имеющийся `float` дней: он не восстанавливает точность,
потерянную раньше в этом значении, и не заменяет исходным счётчиком
нынешний таймер игры. Модуль не читает и не меняет навигацию, сохранения,
параметры ускорения, системные часы или координаты. Исходное слово суток
и представление календаря подготовлены для дальнейшей согласованной
интеграции орбит, но сами по себе эту интеграцию не доказывают.

## Независимый native-контроль

`tools/rebuild_source_clock_native.py` выполняет целые исходные F1357/F1363
из закреплённого `ffe.asm` в исследовательском host x86_64 ELF.
Адаптированы ширина стековых аргументов/сохранённых регистров, резерв
локальных слотов для двух host-POP, синтаксис адресных immediate и вызов
стандартного `sprintf`. Целочисленные операции календаря и времени не
заменены Python-формулами. Настоящий F1363 передаёт свои вычисленные часы,
минуты и секунды в libc с исходной строкой `%02i:%02i:%02i`.
Эквивалентный `strlen` только считает уже полученные байты.

Подтверждённые источники:

- `FIRSTENC.EXE`: SHA-256
  `d919566140abfc298bc9929bc9141d92526586821f017be1336253a04bca1e72`.
- JJFFE `videogamepreservation/jjffe`, commit
  `7e540341d4e09aa3c92877b87d49e7f2c143ad8d`.
- `ffe.asm`: SHA-256
  `d4f1b76aa78895d3634b182428e14f36ac57b304e56fedb67a89ee39b5f6873a`.
- `ffedat.asm`: SHA-256
  `34219c91c5d019440ebf4fc707711a32c5080123ede05cf4d10a27d41f770850`.

По пользовательскому EXE отдельно сверены уникальные префиксы календаря
(`0x3fa96`) и времени (`0x3fc3b`), таблица длин месяцев (`0xe9aec`), строка
формата времени и начальная пара слов. Это не утверждение о побайтовом
совпадении всей 64-битной host-сборки с 32-битным исполняемым файлом.

Выборка содержит **1453 независимых контекста**: границы месяцев,
четырёхлетий и столетий, год 0, начальный 3250 год, края unsigned32,
секундные границы, `24:00:00` и закреплённые случайные значения. Три
свежих процесса совпали. Повтор в обратном порядке в том же процессе
подтвердил отсутствие влияния изменяемой февральской ячейки на результаты
последующих вызовов. В Android не включаются host ELF, x86-код или эмулятор.

```sh
python3 tools/rebuild_source_clock_native.py
godot --headless --path . --script tests/test_source_clock.gd
```

Godot 4.6.3: **7312 проверок, 0 ошибок**. Сравнены даты и точные строки
времени с native-выходом. Отдельно проверены русские подписи, интерфейсный
мост, перенос полудня, границы года/месяца/високосного дня, одноквантовая
дробь и атомарный отказ на неверных входах.
