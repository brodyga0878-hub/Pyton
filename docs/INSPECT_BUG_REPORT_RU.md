# Чтение присланных ZIP-отчётов

`tools/inspect_bug_report.py` читает архив диагностики как данные, без распаковки на диск, запуска вложений или исполнения текста описания.

```sh
python3 tools/inspect_bug_report.py /path/to/StarFrontier-report.zip
python3 tools/inspect_bug_report.py /path/to/StarFrontier-report.zip --json
```

Проверяются схема `starfrontier-diagnostics-v1`, CRC ZIP, состав файлов, размеры и SHA-256 каждого элемента манифеста. Допустимы только фиксированные файлы отчёта, события, необязательный снимок полёта и `engine/godot*.log`. Пределы:8МиБ ZIP,4МиБ распакованных данных и20 записей. Повторяющиеся пути/ключи JSON, ссылки, каталоги, чужие схемы, несогласованные флаги сохранения и повреждённые данные отклоняются с кодом выхода2; успех —0.

Сводка показывает сборку, устройство, движок, настройки, контекст полёта, описание, последние события/ошибки и наличие сохранения. JSON дополнительно содержит ограниченные хвосты старых журналов. Неполная первая строка обрезанного журнала событий учитывается отдельно, не блокируя целый корректный архив. Незакрытый предыдущий сеанс не объявляется подтверждённым аварийным завершением.

Проверка:

```sh
python3 -m unittest discover -s tests -p test_inspect_bug_report.py -v
```

Пройдены16 тестов. Основной вход создаётся настоящим Godot4.6.3 и текущим `game_diagnostics.gd`: выполняется намеренная ошибка движка, собирается ZIP с описанием/сохранением, затем независимый Python-инспектор проверяет содержимое. В отдельном процессе ожидаемая ошибка перехватывается; неожиданные ошибки/утечки проваливают fixture. Проверены повреждённые CRC/SHA, подмена схемы, дубликаты, ссылки/пути, лимиты и UTF-8. Пользовательские данные не используются и не публикуются.
