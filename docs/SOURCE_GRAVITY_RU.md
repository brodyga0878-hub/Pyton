# Исходный импульс гравитации и интегратор

`scripts/source_gravity.gd` переносит полную процедуру F603 изменения
скоростей, исходную подготовку её коэффициента `a4` из F880 и интеграторы
положения F1511/F1512. Это целочисленное ядро в исходных единицах.
Оно не выбирает систему отсчёта, не восстанавливает всю физику корабля
и не подменяет текущую SI-гравитацию в игровом полёте.

Вариант явно обозначен `jjffe-7e54034-gravity`; закреплённый исходник
JJFFE — `7e540341d4e09aa3c92877b87d49e7f2c143ad8d`. Процедуры и
их DOS-контроли имеют отдельные хеши в независимом native fixture.

## Вход и результат

```gdscript
var mass = SourceGravity.coefficient(runtime_record68)
var kick = SourceGravity.update(body338, parent338, step_s32)
var drift = SourceGravity.integrate(kick.body, [step_low_u32, step_high_u32])
```

Все операции возвращают новые данные. Переданные массивы тела,
родителя, времени и отладочного вектора не изменяются. Некорректная
длина, тип или численный диапазон дают пустой словарь до изменения
каких-либо входов.

`coefficient` принимает именно 68-байтовую упакованную запись после F878.
Она читает packed mass по смещению 0 и возвращает `a4_u32`:

```
a4 = F1496(F1482(record.packed_mass, 0xffd54082))
```

Значение остаётся исходным упакованным коэффициентом. Оно не обозначает
килограммы или м³/с². В эту цепочку не включаются двоичные поправки
поля `da`: исходная F880 меняет ими выбор системы отсчёта, а не `a4`.

`update` получает полные 338-байтовые тела исходного runtime-формата:

| Поле | Смещение | Представление |
| --- | --- | --- |
| Относительная позиция | `+0x3e` | Три signed64 |
| Идентификатор родителя | `+0x56` | Один байт |
| Скорость | `+0x8c`, `+0x90`, `+0x94` | Три signed32 |
| Коэффициент родителя | `parent+0xa4` | Packed signed16 mantissa/exponent |
| Дробные части скорости | `+0xec`, `+0xee`, `+0xf0` | Три unsigned16 |

Аргумент `step_s32` повторяет третий аргумент F603. Исходные вызывающие
пути передают в него `DATA_009155`, квант шага исходных часов. При
`body.parent_id=0` или нулевой мантиссе `parent.a4` процедура оставляет
тело неизменным. Вызывающий код передаёт родительское тело отдельно;
самостоятельный выбор активной системы отсчёта остаётся его задачей.

Результат содержит независимую копию `body`, массивы `velocity_s32`,
`fraction_u16`, `scratch_s32`, разбор ветви в `trace` и `source_variant`.
Необязательный четвёртый аргумент `initial_scratch_s32` задаёт начальные
значения отладочных глобальных слов. По умолчанию это три нуля.
Ранние выходы сохраняют эти значения, как исходник. Они не являются
входом физического расчёта.

## Сохраняемая арифметика F603

Три координаты усекутся через F1657/F1658/F1660 до исходного 13-битного
диапазона. Сохраняются исходное исследование старших слов, знаковые
сдвиги и особенности переноса при отрицательных 64-битных значениях.
Длину определяет F1466 с точной битовой процедурой F1502. Это отдельный
алгоритм: таблица приближённого корня F1467 и `sqrt()` его не заменяют.

Длина кодируется с экспонентой усечения и нормализуется F1496.
После квадрата F1482 следующая мантисса умножается ещё раз на мантиссу
длины, но экспонента копируется **из квадрата**, без третьего сложения.
Это связано с тем, что в окончательном произведении остаётся усечённый
вектор позиции. Замена этой последовательности на обычное вычисление
`mu / r³` с вещественной арифметикой не воспроизводит исходный результат.

Мантисса шага сдвигается до диапазона `−32767…32767`, причём каждый
сдвиг увеличивает упакованную экспоненту по модулю 16 бит. Сохраняются
отдельные ветви целого и дробного изменения скорости, 32-битные
усечения произведений, знаковые сдвиги и перенос от трёх дробных слов.
При слишком малой экспоненте скорость не меняется.

Мантисса `0x8000` перед F1496 отклоняется: исходный цикл на таком входе
не завершается. Такой отказ не изменяет переданные объекты.

## Интегратор положения

`integrate` повторяет F1512: читает скорость из тела и передаёт её вместе
с положением в F1511. Пара времени в API имеет обычный порядок
`[low, high]`; исходный стековый вызов F1511 передаёт `high` первым
аргументом времени, `low` вторым. Эта разница проверена нативно.

F1511 берёт модуль signed64 шага, сдвигает его на 7 бит, сжимает
мантиссу, выполняет signed64 произведение скорости и сдвиг ещё на 2 бита,
восстанавливает экспоненту и знак, затем складывает смещение с позицией.
В формальном приближении:

```
displacement_raw ≈ velocity_s32 × timestep_s64 / 512
```

Точное ядро сохраняет исходное квантование. В том числе сохраняются
маски счётчиков ручных SHL/SHR для искусственных полных 64-битных шагов;
обычный универсальный сдвиг signed64 даёт другой ответ на таких входах.
Дробные слова скорости F1511 не использует.

Возвращаются новая копия `body`, шесть координатных слов в
`position_words` и три полных signed64 в `position_raw`. В JSON-эталоне
полные signed64 хранятся десятичными строками, чтобы не терять биты.

## Почему SI-переход пока отдельный

Калибровка геометрии `16785/2^24` метра на raw-единицу уже установлена.
Шкала секунд требует явной политики:

- настоящий JJFFE таймер нормального хода использует 49700 tick/с;
- исходное отображение времени делит на 49710 tick/с;
- текущий мост `elapsed_days` раскладывает сутки в `2^32` tick.

Эти шкалы близки, но не равны. Поэтому нельзя объявлять уникальный
SI-коэффициент скорости по одному HUD или автоматически подставлять
`real(a4)` вместо ньютоновского параметра. Текущий рабочий SI-полёт,
радиусы, поверхность и правила выбора системы отсчёта должны быть
согласованы отдельно. Подключение этого ядра в справочные метаданные
мира само по себе не заменяет физику полёта.

## Независимая проверка

`tools/rebuild_source_gravity_native.py` выполняет настоящие извлечённые
инструкции F603, F1532 и арифметических помощников на host x86_64.
Он отдельно исполняет настоящую цепочку коэффициента F880 и полные
F1511/F1512. Подмена вспомогательных функций формулами Python не
используется. Исполняемые процедуры, адаптация ABI и исходные срезы
имеют хеши в `tests/fixtures/source_gravity_native.json`.

Для каждой проверки гравитации сравниваются все 338 байтов тела,
скорости, дробные части и отладочные слова; родительский банк и прочие
поля остаются неизменными. Эталон повторяется в свежих процессах и
обратном порядке с защитными участками памяти. Интегратор проверяется
одновременно через F1512 и прямой вызов F1511.

Текущий эталон содержит 1179 контекстов F603, 194 исходных подготовки
коэффициента F880 и 304 случая F1511/F1512. Включены настоящие исходные
записи, отрицательные шаги и позиции, перенос дробной скорости,
переполнения, нулевые родители/масса/расстояние, близкие и дальние
объекты. Отдельно сохранена особенность F1657: значение `−2^32`
с high-word `−1` и нулевым low-word даёт нулевой результат младшей
ветви поиска бита и последующий ранний выход F603. Исправлять этот
эталон на идеальную вещественную длину нельзя.

Промежуточные значения нормирования, степени, отношения, мантиссы
шага и коэффициента проверены отдельной наблюдаемой копией исходной
F603. Наблюдение сохраняет регистры и флаги; полные выходы совпадают
с нетронутой процедурой во всех контекстах. Сопоставление 180 инструкций
и переходов самой F603 также подтвердило совпадение с DOS из архива;
помощники и остальная физика имеют отдельную область доказательства.

Модульный тест: **20 205 проверок, 0 ошибок**. Эти числа относятся
к текущему тесту, не суммируются с историческими проверками орбит
и не означают проверку всего физического движка игры.

```sh
godot --headless --audio-driver Dummy --path . \
  --script tests/test_source_gravity.gd
```

Это доказательство указанного вычислительного ядра в raw-единицах,
без заявления о полном переносе FFE, исходных поверхностях или
производительности физического Android-устройства.
