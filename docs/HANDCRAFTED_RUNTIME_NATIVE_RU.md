# Независимый контроль преобразования исходных записей F878

`ffe_handcrafted_records.json` содержит шаблоны после F873/F874/F875,
а не готовые упакованные записи, принимаемые F880. В шаблоне обычного
тела масса хранится как исходное целое плюс 1, орбита — как целое,
а период ещё равен нулю. Например, в шаблоне Земли записано 599 и
4 458 427. Применять к этим словам декодирование упакованного числа
или считать их уже проверенными физическими величинами нельзя.

Новый `tools/rebuild_handcrafted_runtime_native.py` выполняет настоящий
суффикс F878 для заранее заданных систем: `JUMP_003650`–`JUMP_003657`.
Он получает шаблоны, превращает обычные записи в упакованные,
вычисляет период по уже преобразованной записи родителя и переносит
городские записи типа 35 целиком. Это недостающий переход между
проверенной инициализацией шаблонов и будущим созданием объектов мира.

## Точные границы

Контроль выполняет **реальные целочисленные инструкции** выбранного пути
и настоящие F1489/F1482/F1483/F1463 с их математическими помощниками.
Python создаёт входные пакеты и сравнивает повторения; ожидаемые поля
записи не вычисляются Python-копией нового GDScript.

Перед суффиксом стоит отдельный вход исследовательского host-кода.
Он задаёт ровно состояние указателей, индекса и счётчиков, которое
подготавливает исходная ветвь заранее заданных систем. Полный выбор
ветви F878, F871, процедурная генерация, F877/F897, имена F893/F791,
эпоха времени, эфемериды и преобразование в SI этим не проверяются.
Не выполняются изменения F879 или спорный вариант SAR3/SAR4.

Адаптации ограничены 64-битными слотами стека, синтаксисом GNU assembler
и эквивалентным копированием байтов C `memcpy`. Все указатели и стек
исследовательского ELF находятся ниже 2 GiB; исходные операции над
32-битными регистрами и переполнения байтов сохранены. Нативный ELF
нужен только для проверки на host-машине. Android-игра не исполняет
этот ELF, DOS-программу или x86-инструкции.

## Что именно делает исходный суффикс

- Для типа, отличного от 35: преобразует `mass_word - 1` через F1489
  и прибавляет 63 к слову показателя; орбиту преобразует через F1489
  и прибавляет 25 к слову показателя.
- Переносит исходные seed, родителя, тип, модель, фазу, эксцентриситет,
  наклон, температуру, отдельные флаги, байт вращения и ориентацию.
- Для дочернего обычного тела получает период настоящей цепочкой
  упакованного умножения, деления, корня и коэффициента `0x5edb`.
  У корня без родителя записывает период 0.
- Копирует строку до исходного NUL включительно. Остаток поля и прочие
  незаписываемые байты назначения не обнуляются сверх действий оригинала.
  В частности, обычная ветвь не пишет `0x18..0x1f`, байт `0x3f` и слово
  `0x40`. У типа 35 копируются все 68 байт, включая эти поля.
- После последней активной записи обнуляет только первые четыре байта
  следующего слота. Остальные 64 байта этого слота остаются прежними.

Счётчики — исходные байты с переполнением, а не новые физические категории.
`body_count_byte` увеличивается для всех не наземных записей, включая
орбитальные порты типов 32–34. `port_count_byte` включает типы 32–35;
`orbital_port_count_byte` — только 32–34. Поэтому у Sol получаются
53 записи, значения 43/18/8 и 10 наземных портов; число 43 не означает
43 планеты.

## Контракты fixture и безопасного вызова

В `tests/fixtures/handcrafted_runtime_native.json` каждый случай содержит:

- `templates_hex`: активные входные шаблоны по 68 байт;
- `destination_hex`: исходные 60 слотов назначения;
- `initial_counts`: три указанных байтовых счётчика;
- `expected`: все 60 результирующих записей, `count`, `next_index`
  и три конечных счётчика.

Для исходных окон также записаны `system_id` и `source_global_indices`.
Диагностическое окно Riedquat содержит три подлинных шаблона, но **не**
получает новый `system_id`: его связь с текущим реестром систем не
восстановлена. Эти случаи не добавляют систему в игру.

В контролируемом API допускаются 0–59 активных записей и 60 слотов
назначения: ещё один слот нужен для настоящего четырёхбайтового
терминатора. Оригинальный суффикс сам не проверяет ёмкость или дерево;
безопасная реализация проверяет их до начала работы. Нативные входы
заранее удовлетворяют этим условиям. В обычном полном F878 счётчики
сначала сбрасываются; ненулевые начальные значения в fixture проверяют
арифметику именно суффикса.

## Источники и результат

- Пользовательский `FIRSTENC.EXE`: SHA-256
  `d919566140abfc298bc9929bc9141d92526586821f017be1336253a04bca1e72`.
- Закреплённый JJFFE `ffe.asm`: SHA-256
  `d4f1b76aa78895d3634b182428e14f36ac57b304e56fedb67a89ee39b5f6873a`.
- Вход выбранной ветви подтверждён в EXE по `0x2a6b1`; конец после RET —
  `0x2a951`. SHA-256 этих байтов:
  `3f91319f1ee54c69c6b842ff4430723e8fb7629f91f6257bbe4051af748ab409`.
- SHA-256 исходного текстового суффикса:
  `d0e78100913eea774e28b6e93542c9ac6abd831f8690565ac8bf39467c41b36a`.

Проверены **122 нативных контекста**: 11 известных систем с 130
подлинными шаблонами, три отдельно отмеченных fallback-шаблона,
пустой ввод, заполненные ненулевым рисунком назначения, счётчики у
границ байта, родительские цепочки, границы 16/32-битных полей и
59 активных записей. Все 60 выходных слотов сравниваются целиком.

Каждый контекст повторён в обратном порядке в том же процессе;
три свежих процесса дали одинаковые байты. Отдельный повтор всего
генератора воспроизвёл JSON побайтно. Повторения не объявляются новыми
независимыми игровыми системами или контекстами.

Fixture занимает 2 162 366 байт, SHA-256:
`e09016da974e0e9e188bff12d463784bb2c1f2b23588bbe64632e137f8e486cd`.
SHA-256 полного прямого/обратного нативного вывода:
`fb5f105f9d7d4129dd05cc3b2f901f80a91d85d7b4b56769fa048b52c2302671`.

```sh
python3 tools/rebuild_handcrafted_runtime_native.py
```

Эти результаты проверяют преобразование записи. Подмена текущих
масштабов, часов или орбит числами из нового буфера без отдельного
подтверждения единиц и согласования координатных кадров недопустима.
Нативное вращение также должно быть общим для глобального отображения,
входа к поверхности, города и физики, а не отдельным эффектом рендера.
