# Каталог миров из действительного банка F878

`SourceWorldCatalogue` — отдельный адаптер для будущего режима v4. Он принимает
готовый результат `SourceSystemBuilder.build`, а не конструкторные параметры
`ffe_worlds.json`. Существующие режимы v1/v2/v3 и файлы `World`/`Main` этим
модулем не изменяются.

```gdscript
var catalogue = load("res://scripts/source_world_catalogue.gd").new()
var result = catalogue.build({"id": system_id}, generated)
```

При успехе возвращаются `ok`, `bodies`, `settlements`, `default_id`,
`record_count`, SHA полного исходного банка, SHA ресурса дескрипторов и
оригинальные байтовые счётчики. При ошибке возвращаются `ok=false`, причина и
версия адаптера; частичный каталог наружу не выходит. Входные словари и все
128 записей по 68 байт сохраняются.

## Представление записей и иерархия

Первые `record_count` записей должны быть активны, следующая должна содержать
нулевой DWORD-сентинел. Проверяется весь банк. Поддерживаются исходные типы
0–30 и 32–35: барицентры, естественные тела/звёзды, три типа орбитальных
портов и наземные поселения. Тип 31 не имеет восстановленного конструктора.
Каждая родительская ссылка проверяется; циклы, отсутствующие родители,
самоссылки и поселения в роли родителей отклоняются атомарно. Допускается
лес с несколькими корнями и расположение родителя после ребёнка в банке:
результат упорядочивается для последовательного вычисления координат.

`original_index` сохраняет исходный индекс, начиная с 1; `source_parent_index`
сохраняет исходную родительскую ссылку. Идентификаторы имеют вид `hcN` и
`siteN`, первый естественный объект получает `star`. Для действительных
именованных тел Sol сохраняются `earth`, `moon`, `mercury` и остальные
привычные идентификаторы. Если Земля присутствует в Sol, она выбирается по
умолчанию. Иначе выбирается первое тело с поддержанной исходной поверхностью,
затем первое видимое естественное тело. Учебные станции не добавляются.

У каждой строки есть точный `runtime_record_hex`, исходный UID, тип, модель,
фаза, наклон, температура, байты вращения и ориентации. Поля `record_hex`,
выдающего готовую запись за конструкторный шаблон, здесь нет.

Важная исходная особенность: F878 преобразует обычные и орбитальные записи
в упакованный числовой формат, но копирует наземный тип 35 целиком. Поэтому
домен обозначен `f878_runtime_bank_with_unconverted_type35_fields`. У наземных
записей масса/орбита не интерпретируются как упакованные физические числа;
углы `ground_phase_u16` и `ground_inclination_u16` берутся непосредственно
из слов по смещениям 0x12 и 0x22. Обратного восстановления якобы исходных
широты/долготы не выполняется.

## Числа, размеры и отображение

Радиус орбиты и период берутся из действительных упакованных полей 0x0e и 0x14
через `FFE_Math.real`; расстояние переводится через исходную калибровку
`16785/2^24` метров, период — из секунд в дни. Наклон — знаковое 16-битное
слово, фаза — беззнаковое. Поле температуры содержит исходное смещение 273.
`source_a4_packed` вычисляется восстановленным `SourceGravity.coefficient`.

`mass_solar` — явно подписанный адаптер отображения: отношение исходной
упакованной массы к упакованной массе Sol `0x005b5f5e`. Современные массы
Земли/Солнца в каталог не подставляются. Также явно подписан вывод
`rotation_hours`: показатель исходного сдвига F866 переводится через мост
elapsed-days; нулевой байт вращения означает неподвижный объект. Полные
исходные орбиты и матрицы вычисляются отдельными исходными модулями.
Нулевые Kepler-поля и `rings=false` — совместимые поля существующего
представления; они не заявляют восстановление исходной программы колец,
эллиптических элементов или геометрии модели.

Для моделей 117–133 опорный размер берётся из реальных статических осей
`ffe_terrain_query.json` и `mesh_zoom`. У 16 сферических моделей оси равны:
модель 129 даёт 7 049 700 м, модель 120 — 3 961 260 м. Это исходные опорные
радиусы, а не современные астрономические значения и не высота рельефа.
Несферическая модель 117 использует внешний опорный размер 125% наибольшей
оси с политикой `source_exterior_probe_125pct_axes_v1`; фактическая форма
должна запрашиваться через исходный terrain sampler. Можно передать
`radius_provider: Callable` с интерфейсом `record68 -> metres`, например
`SourceSurfaceTerrain.reference_radius`; это не создаёт циклической
зависимости модулей.

У моделей вне 117–133 исходный внешний дескрипторный bound используется
только как подписанный размер для отображения; `landable=false`. Это
касается звёзд, газовых гигантов и особых моделей вроде 112. У барицентров
радиус отображения равен 0. Исходные внешняя/внутренняя сферы и SHA
дескриптора сохраняются отдельно у всех объектов. Они никогда не объявляются
универсальным радиусом поверхности.

Исходные байты имени с NUL сохраняются в `source_name_bytes_hex`, вся запись
дополнительно сохраняет хвост после NUL. Для отображения применяется
существующий словарь русских названий. Неизвестные расширенные/управляющие
байты заменяются только в UI на U+FFFD с явным флагом: исходный шрифт не
выдаётся за UTF-8 или недоказанную DOS-кодировку. Полная локализация этого
набора имён относится к отдельному слою перевода.

## Происхождение дескрипторов и проверка

`tools/rebuild_runtime_model_descriptors.py` проверяет SHA оригинального
`FIRSTENC.EXE`, читает реальную таблицу указателей по смещению 0xba8fc и
извлекает 149 дескрипторов по 68 байт — слоты 0–148 до последней модели
звёздного конструктора. Сохранены указатель, смещения слота и дескриптора,
сырые байты, SHA, исходные масштабы/флаги/границы и указатель физического
описателя. Наличие слота не означает, что его модель появляется в каждом
банке. Ресурс не подменяет геометрию этих моделей.

SHA ресурса `ffe_runtime_model_descriptors.json`:
`cf9c673c2bba22f0c865e77e3a7ceed5497053cdb444b80f31d7439176446818`.
SHA исходных 596 байт таблицы указателей:
`2c5a58f2130a6820a47114eaa4e7ee3f8f988aec3df6b12ca1385b32c2b0e532`.

Тест использует 209 полных банков независимого нативного исполнения F878:
процедурные системы, 11 исходных ручных систем, 42 случая с действительными
заголовками F860, четыре явно исправленных вызывающей стороной заголовка
с исходным зависанием, особый Polaris и реальный fallback. Он
дополнительно проверяет 24 исходных варианта конвертирующего суффикса,
включая заполненный узором буфер назначения. Всего проверяются 4852 записи,
32 различных типа и случай 61 активного объекта. Сравниваются целые записи,
полный SHA банка, исходные поля/родительские ссылки, реальные результаты
`SourceSystemBuilder`, независимые числовые опоры Sol, целостность 149
дескрипторов и атомарное отклонение неправильных банков. Эталонные банки
получены исполнением исходных инструкций, а не этим адаптером.

```sh
python3 tools/rebuild_runtime_model_descriptors.py
godot --headless --path . --script tests/test_source_world_catalogue.gd
```

Проверка модуля не является проверкой производительности или запуска на
физическом Android-телефоне. Подключение нового режима в World/Main и
совместимость сохранений выполняются отдельно.
