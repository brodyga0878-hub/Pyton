# Ограниченный исходной тягой мобильный профиль Cobra

Профиль `source-cobra38-conservative-f601-mobile-v1` устраняет несогласование
нового исходного мира с прежними адаптированными 18 м/с² стартовой «Кобры».
На части исходных портов гравитация около 23 м/с²: старый предел контроллера
не позволял безопасно войти на такую поверхность. Вместо вымышленного
усилителя используется консервативный предел из настоящих данных Cobra Mk III.

Это узкий профиль текущего мобильного управления для новых миров v4.
Он не начинает полный перенос блока 9: остальные корабли, оборудование,
топливо, масса загрузки и оригинальный контроллер остаются отдельной работой.
Флаг выбора нового профиля выводится приложением из контекста нового мира;
прежние сохранения v1/v2/v3 должны сохранять прежнее ускорение.

## Исходные данные и контроль

В оригинальном EXE Cobra Mk III имеет индекс модели 38. Дескриптор расположен
по смещению `0x8da2c`, физическое описание — `0x8d9fc`. Его 24 байта:

```text
942a19f10201640050007c009600234001000400030c0200
```

SHA описания:
`b0f77d55db624b023accc8542f6b990d95515ab3e4c23bdd4e1d6e30c4cf2656`.

Основная тяга содержит знаковое слово 10900, обратная — −3815.
F1533 копирует обратное слово в отрицательные пределы по трём осям,
а его отрицание — в положительные боковой и вертикальный пределы.
Масса корпуса 100 т и внутренняя вместимость 80 т сохраняются в метаданных;
этот профиль не меняет существующий адаптированный трюм. В самом F601
деления этих слов на массу нет.

`tools/rebuild_source_cobra_control_native.py` проверяет SHA оригинального
EXE/ассемблера, извлекает описание по настоящим указателям и исполняет
исходный F601 для шести направлений при 8, 49700 и 49710 ticks. Подготовка
полей объекта повторяет просмотренные присваивания F1533; нативно в этом
контроле исполняется F601. Его код не заменяется Python-расчётом ускорений.
Три свежих процесса и обратный порядок дают идентичные результаты.
Защитные слова и все байты объекта вне скорости/дробных остатков сохраняются.

При единичной Q31-матрице и 49710 ticks результат вертикальной тяги:

- скорость `723 + 15032/65536` исходных единиц;
- совмещённое значение Q16: `47397560`;
- ускорение по принятому номинальному мосту: **70.25156725799762 м/с²**.

Для основной тяги получены `2066 + 24224/65536`, Q16 `135421600`,
**200.7187635942789 м/с²**. Противоположные направления проверяются с
настоящим знаковым переносом дробной части. Мост совпадает с текущим
`SourcePhysicsBridge`: `2^32/86400` ticks/с и `16785/172800` м/с на единицу
скорости. Это явная политика нового мира, а не подмена частоты JJFFE 49700.

SHA независимого нативного набора:
`80edd5969bbc728bce27a3cd676f06641adf75f89155cb8afced844baa2d02da`.

## Граница профиля

`SourceShipControlProfile.acceleration("cobra")` возвращает минимум модулей
всех шести исходных направлений: 70.25156725799762 м/с². Мобильный контроллер
остаётся изотропным и ограниченным более слабой вертикальной/обратной тягой.
Основная тяга 200.7 м/с² не назначается всем направлениям. Множитель
адаптированного оборудования `engine` к этому исходному пределу не применяется.
Для других идентификаторов помощник возвращает 0, чтобы вызывающая сторона
могла сохранить их прежние адаптированные профили.

Расчёт использует точный малый шаг F601 при фиксированной единичной матрице.
Он не заявляет совпадение всех повёрнутых кадров, больших шагов или
покадровой динамики исходной игры. Контроль при 8 ticks показывает исходное
нулевое усечение; поэтому непрерывный мобильный предел явно называется
адаптером выбранного номинального образца.

Вызов `describe()` возвращает исходные слова, все шесть образцов, SHA,
параметры времени и явную политику. Возвращаемые словари — независимые копии.
При отсутствии или несовпадении исходного описания значение не выдумывается.

```sh
python3 tools/rebuild_source_cobra_control_native.py
godot --headless --path . --script tests/test_source_ship_control_profile.gd
```

Успех этого теста доказывает профиль и его происхождение. Проверки живых
посадки, взлёта, сохранения и восстановления выполняются отдельно в Main.
