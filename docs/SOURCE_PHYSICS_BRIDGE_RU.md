# Исходная F603 в номинальном SI-контроллере

`source_physics_bridge.gd` задаёт явный контракт
`sampled-f603-nominal-day-si-v1`. Он получает исходную запись родителя,
относительную позицию и воспроизводит один исходный импульс F603 из
нулевой скорости. Затем переводит этот импульс в ускорение для
существующего контроллера корабля в метрах и секундах.

Это отдельный мост управления. Он сохраняет исходный закон F603,
включая усечения и асимметрии, но не заменяет весь исходный выбор кадров,
накопитель времени и пошаговый интегратор FFE. Сохранённые семейства
миров v1/v2/v3 должны продолжать выбирать прежнюю физику; включение
этого контракта требует новой версии мира.

## Выбранные единицы

Политика согласована с существующим мостом навигационных суток:

```
ticks_per_second = 2^32 / 86400
metres_per_raw = 16785 / 2^24
velocity_unit_mps = metres_per_raw * ticks_per_second / 512
                  = 16785 / 172800
                  = 373 / 3840
```

Последний коэффициент равен примерно `0.09713541666666667` м/с на
единицу исходной целой скорости. Независимый native-контроль F1511
подтверждает, что единичная скорость за 512 тиков даёт ровно одну
исходную единицу положения. Для других шагов сохраняется исходное
квантование интегратора: например, 49710 тиков при скорости 1 дают
97 исходных единиц, а не идеальные `49710/512`.

При нормальном режиме таймер закреплённой JJFFE даёт 49700 тиков
за реальную секунду, HUD использует делитель 49710, а выбранная здесь
номинальная секунда содержит `2^32/86400` тиков. Эти три значения
не отождествляются. Смена политики требует нового контракта.

## Как получается ускорение

По умолчанию применяется **49710 исходных тиков**. Длительность этого
интервала в выбранных номинальных секундах равна
`49710 / ticks_per_second = 0.9999945759773254`, а не ровно одной секунде.
Число 50000 вместо него не подставляется.

Для каждого запроса:

1. F880 вычисляет исходный packed `a4` из 68-байтовой записи после F878.
2. Создаются отдельные 338-байтовые объекты. Скорость, её три дробные
   части и остальные поля равны нулю; задаются только относительная
   позиция, ненулевой индекс родителя и исходный `a4`.
3. Выполняется настоящая восстановленная F603 с выбранным шагом.
4. Целая скорость и положительная дробная часть объединяются как
   `velocity_q16 = signed32_velocity * 65536 + unsigned16_fraction`.
5. Полученное изменение скорости переводится в м/с и делится на
   явную длительность эталонного интервала.

Формально определение моста выглядит так:

```
a_reference = delta_v_F603(record, relative_raw, 49710)
              / (49710 / ticks_per_second)
```

Знак целой части существенен. Например, целое `−1` с дробной частью
65535 означает `−1/65536` единицы скорости, а не `−1.999984…`.

Все расчёты единиц сохраняются в скалярной двойной точности. `Vector3`
создаётся только для передачи результата игровому контроллеру. Скаляр
`gravity_mps2` вычисляется из тех же компонентов до этого преобразования.
Если поверхности нужна проекция на локальную вертикаль, вызывающий
код получает её из этого же вектора, а не из отдельной формулы GM.

## API и координатный договор

```gdscript
var sample = Bridge.sample_acceleration(runtime_record68, relative_raw_i64)
var cached = Bridge.sample_prepared(source_a4_u32, relative_raw_i64)
var ground = Bridge.surface_gravity(runtime_record68, surface_point_raw_i64)
```

`relative_raw_i64` — три точных знаковых целых исходной геометрии.
Модуль не поворачивает оси, не выбирает родителя и не складывает силы
разных тел. Вызывающий код задаёт эту политику явно. В новом мировом
кадре ускорение в полёте и проверка тяги на поверхности должны получать
одинаковое направление в одинаковой системе отсчёта на одну дату.
Например, при выборе невращающихся XYZ тела фиксированную к планете
точку F879 предварительно переводят тем же вращением, что и мировой
контроллер. Исходный выбор кадров F606 этим модулем не объявляется
перенесённым.

Подготовленный `a4` можно кэшировать для тела, чтобы не декодировать
запись повторно. Он остаётся исходным packed-коэффициентом, а не
килограммами или единым ньютоновским параметром. Внутри нет подгонки GM,
устранения асимметрии, скрытого ограничения силы или сглаживания.

Результат содержит точные слова скорости и дробей, signed48/Q16
импульс, изменение скорости в SI, ускорение в двойной точности,
`Vector3`, модуль ускорения, длительность и разбор исходной ветви.
Все массивы независимы. Некорректные размеры, типы, шаг и переполнение
при переводе метров в signed64 отклоняются без изменения входов.
Начальная скорость не хранится между запросами.

## Почему это не полная динамика оригинала

В оригинале F603 вызывается с фактическим квантованным шагом кадра
и существующими дробными остатками скорости. Здесь постоянный образец
пересчитывается в ускорение, которое SI-контроллер применяет на своём
шаге. Из-за округлений результат не обязан совпасть с вызовом F603 на
каждом кадре и последующим F1511. Оба поведения различены в API и
проверках. Поле `original_per_frame_dynamics` всегда ложно.

Особенности исходного F603 намеренно сохраняются. На некоторых
противоположных направлениях и границах нормализации импульс различен.
Для относительной координаты `−2^32` вдоль X исходный поиск масштаба
может дать нулевой импульс, тогда как `+2^32` даёт ненулевой. Это
проверено настоящими исходными инструкциями, а не введено мостом.
Нулевая дистанция также сохраняет исходный ранний выход.

В испытанных точках 21 исходного порта модуль ускорения в body-fixed
направлениях лежит примерно между 0.223 и 23.083 м/с². Это свойства
данного исходного расчёта и выбранной политики единиц; достаточность
тяги конкретного корабля проверяется отдельно. Значения не обрезаются
под возможности трёх прежних адаптированных лётных профилей.

## Независимые проверки

`tools/rebuild_physics_bridge_native.py` выполняет реальные извлечённые
инструкции F880/F603 и F1511/F1512. Ожидаемые импульсы не берутся из
GDScript. Точный перевод в SI выполняется независимой рациональной
арифметикой Python `Fraction` над полученными целыми словами.

Fixture включает:

- 134 различные исходные записи F878, включая нулевой завершающий контроль;
- 3350 образцов силы: противоположные оси, косые направления, разные
  масштабы, нулевые расстояния, границы нормализации и реальные точки F879;
- 12 отдельных нативных проверок исходного интегратора положения.

Проверяются три свежих процесса, обратный порядок, защитные участки,
неизменность банка родителей и всех нецелевых байтов. Контроль F603
также закрепляет ранее выполненное сопоставление всех 180 инструкций
с пользовательским DOS EXE. Отдельно проверены атомарные отказы,
неизменность входов, дробные отрицательные скорости и граница `Vector3`.

Текущий результат: **37 002 проверки, 0 ошибок**.

```sh
godot --headless --audio-driver Dummy --path . \
  --script tests/test_source_physics_bridge.gd
```

Эта проверка подтверждает выбранный вычислительный контракт. Она не
является измерением FPS телефона, полнотой исходных корабельных кадров
или доказательством готовности всей игры к выпуску.
