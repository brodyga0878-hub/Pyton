# Сферическая проверка и диагностика контакта — 0.20.0

Опубликованная сборка **0.20.0-spherical-contact-alpha1 / Android code 45** переносит
целую DOS F577 и проверяет ограниченную чистую композицию с исходным
заголовком F575 и прежним ответом игрока. В Main подключается только
чтение `source_spherical_probe` для журналов и отчётов. Новая физическая
ветка столкновений этим выпуском не вводится. Финальные функциональные
проверки, настоящие кадры Main и строгая техническая проверка APK
завершены. Точный ZIP проверен свежим импортом и настоящим Main;
неизменяемые HTTPS-ссылки проверены полным скачиванием.
Предыдущие проверенные артефакты — в [0.19.0](RELEASE_0_19_0_RU.md).

## Полная F577 и смысл результата

`source_spherical_contact.gd` содержит **целую DOS F577: 363 байта /
128 инструкций**. Вместе с шестью доказанными вспомогательными областями —
**917 байт / 367 инструкций в семи областях**. Это отдельная проверка
сырых объектов и относительного вектора; поиск банков объектов, выбор
кадра и физический ответ в эту функцию не входят.

В ветви неположительного сдвига исходный DOS складывает **внутренний
радиус корабля `+0x140` с внешним радиусом родителя `+0x138`**.
Поздний JJFFE использует внутренний радиус родителя `+0x140` и даёт
другое поведение. В положительной ветви DOS складывает два внешних
64-битных радиуса. Каноническая реализация сохраняет исходный DOS;
один контрфактический JJFFE-контроль учитывается отдельно.

Возврат `0` означает кандидата внутри проверенной сферы. Возврат `−1`
охватывает внешнюю область и равенство на границе. Во внешней ветви
исходник устанавливает флаг `0x02`, при соответствующих радиусах —
также `0x01`, и пишет DATA8703/8704. Несмотря на историческое имя
`altitude`, это восстановленное расстояние от центра, **не высота над
землёй AGL**. Флаг `0x02` сам по себе не означает удар или посадку.
Внутренний результат F577 ничего не пишет в эти глобальные поля:
не задаёт вид коллизии, прежнюю высоту, урон или состояние посадки.

## Таблица исходных маршрутов

`ffe_spherical_contact.json` содержит **149 строк** исходных дескрипторов,
префиксов потока коллизий и признаков начальной маршрутизации F1533.
Нулевой поток есть у 19 дескрипторов, включая модель 0. Однако F1533
для модели 0 пропускает инициализацию: её фактические начальные флаги
и пригодность для простой сферической ветви обозначены NULL.
**Инициализированных простых моделей — 18**, а не 19.

Это свойства начальных записей, а не текущий живой банк объектов.
Все природные модели **117..148** выбирают иерархический путь F576,
который ещё не перенесён. Поэтому наличие сферического помощника
не заменяет поверхность планеты, посадку, рельеф или нынешний учёт HP.

## Проверенная чистая композиция

`source_spherical_contact_pipeline.gd` связывает исходные абсолютные
компоненты и грубый тест заголовка F575 с полной F577. Только для
простого выбранного родителя и игрока внутренний кандидат передаётся
прежнему неизменённому ответу F575 с `kind=2`.

Проверены **2400 условий / 0 ошибок**. Нативный набор содержит **207
поддерживаемых случаев** и отдельно **шесть контролей перехвата запрещённых
F576/F578 с атомарным откатом**. Последние проверяют границу адаптера,
а не исполнение ещё не перенесённых исходных движков. Запросы F953
наблюдаются, но HP/RNG в этой чистой композиции не изменяются.

Нативное доказательство охватывает 25 областей инструкций, включая
байтовую область полной F575 на 2005 байт / 635 инструкций. Контрольные
исполнения ограничены ветвями игрока и простого родителя; полнота
байтовой привязки не доказывает полный перенос поведения F575.
Банки мира, автоматический выбор кадра F569/F570, иерархия F576,
ответ других пар F578 и глобальный диспетчер остаются отдельной работой.
[Чистая композиция](../validation/spherical-2026-11-08/source-spherical-pipeline.json),
[нативное доказательство](../validation/spherical-2026-11-08/nativeproof/source-spherical-contact-pipeline-native-proof.json).

## Диагностическая проба в игре

`source_spherical_contact_probe.gd` читает настоящий World, исходные
границы модели и фактический **авторский центр корабля**. Скалярные
64-битные координаты согласуются с текущим поверхностным или космическим
кадром. К центру не добавляется клиренс или смещение к земле из пути
посадки 0.19; рельеф для пробы не запрашивается.

Поле `source_spherical_probe` в журнале и отчёте явно содержит
`envelope_only=true`, `response_applied=false`,
`source_object_bank_present=false`. Оно показывает геометрический
конверт даже для моделей, чья настоящая маршрутизация требует F576;
такой просмотр не означает пригодность к простому исходному диспетчеру.

Проба не применяет ответ, повреждения, время или топливо, не меняет
живые кеши World и вращение. Если нужен расчёт положения, используется
изолированный контекст эфемерид. Чистая композиция существует отдельно
от этого живого потребителя; Main не запускает по ней новую физику.
Поверхность, HP, управление, классическая нижняя консоль и графика
сохраняют поведение предыдущего блока.
