# Исходная поверхность и размещение наземного порта

`source_ground_surface.gd` вычисляет исходную точку наземного порта
через два запроса высоты. Это исполняемый расчёт по исходным моделям,
UID и таблицам рельефа. Готовые координаты из тестовых fixtures
в рабочем модуле не используются.

## Исходник и вариант

Вариант `jjffe-7e54034-ground-surface` закреплён за JJFFE commit
`7e540341d4e09aa3c92877b87d49e7f2c143ad8d` и пользовательским EXE
SHA-256 `d919566140abfc298bc9929bc9141d92526586821f017be1336253a04bca1e72`.

Все 227 существенных инструкций F879 сопоставлены с DOS-образом.
226 совпадают; одна намеренно отличается: первый запас высоты в JJFFE
вычисляется через `sar 3`, в DOS — через `sar 4`. Три выравнивающих NOP
не считаются алгоритмическими инструкциями. Поэтому этот модуль
не обозначается как побитово идентичный DOS во всём размещении портов.

Реальные исходные инструкции исполнялись отдельным исследовательским
инструментом на host x86_64. Игра использует GDScript/Godot ARM64;
ELF oracle и x86-исполнение не нужны Android-приложению.

## Состав модулей и ресурсов

- `source_terrain_math.gd`: исходный hash32 и целочисленные возмущения.
- `source_terrain_query.gd`: исходная F1876, feature maps, подразделение
  треугольников и запрос пересечения.
- `source_terrain_point.gd`: природная ветвь F581 в локальных целых
  координатах модели, включая построение исходного кадра запроса.
- `source_ground_surface.gd`: инициализация F1533 для дескрипторов
  без физического specification-блока, F879, природный путь F574/F575,
  F579/F582 и достигнутые контактные нормализации.
- `ffe_ground_collision.json`: 28 исходных дескрипторов — 17 природных
  моделей 117–133 и 11 моделей портов 81–90/96. Для природных моделей
  включены полные terrain collision streams с завершающей командой;
  для портов — используемые префиксы, нулевой предшествующий child marker
  и явно ограниченное окно исходных байтов.

Модельные дескрипторы, вершины, feature payload и таблицы не заменяются
современными астрономическими радиусами. Поля `outer_radius_raw`
и `inner_radius_raw` описывают исходные границы разных проверок;
они не объявляются универсальным радиусом рельефа.

Вершины и таблицы рельефа берутся из уже проверенного
`ffe_terrain_query.json`. Повторная загрузка модели не меняет исходные
массивы; публичный `model_resources()` возвращает отдельную копию.

## Размещение настоящего исходного порта

```gdscript
const GroundSurface = preload("res://scripts/source_ground_surface.gd")
var surface = GroundSurface.new()
var placed = surface.place_records(port_record68, parent_record68, port_local_index)
```

Обе записи должны находиться в домене времени исполнения после F878.
Исходные constructor templates не следует подавать вместо них.
Из записи порта читаются модель, родитель и два u16 угла. Из записи
родителя читаются модель и исходный UID рельефа.

`place_records()` явно создаёт изолированный геометрический контекст:
нулевые 338-байтовые объекты, исходные идентификаторы родства,
body-fixed признак порта, UID родителя и единичная Q31-ориентация
родителя. Затем выполняются проверенная F1533 и расчёт F879.
Это не распределение объектов F927 и не весь конструктор F880.
Политика помечена `isolated_source_geometry_v1`.

Результат содержит:

- `port` и `parent`: полные отдельные 338-байтовые объекты после расчёта;
- `position_raw`: три signed64 компоненты относительной точки порта;
- `matrix_q31` и `matrix_initial_q31`: окончательную и начальную матрицы;
- `passes`: две точки запроса, высоты и исходные глобальные слова;
- `height_calls` и `terrain_query_calls`: фактические числа операций;
- `initialized_port` и `initialized_parent`: геометрическое состояние
  после F1533 до размещения.

Сначала F1674 строит матрицу по исходной таблице синуса. Затем F879
берёт `descriptor.outer - 1`, умножает на радиальное направление
с исходными signed64-сдвигами, вызывает F574, оставляет исходный запас
`height - (height >> 3)`, пересоздаёт точку и выполняет второй F574.
Окончательная поправка вычитается без первого запаса. Переполнения,
знаковые мантиссы, отдельные ветви экспоненты и Q31-округления сохранены.

Для уже подготовленных объектов доступны:

```gdscript
var initialized = GroundSurface.initialize_model(object338, model_index)
var placed = surface.place_raw(port338, parent338, phase_u16, inclination_u16)
```

Инициализатор поддерживает только извлечённые дескрипторы без физического
specification-блока. Входы не изменяются; результат возвращается отдельно.
Неверные размеры, диапазоны и неподдержанные контексты дают `{}`.

## Прямой запрос высоты

```gdscript
var sampled = surface.height_raw(probe338, parent338, point_signed64, 1)
```

Это природный, неигровой контекст F574 с исходными родительскими
границами и нулевой внутренней границей пробного объекта.
Проверены broad phase, F579, F581/F1876 и достигнутые неигровые
контактные нормализации F575. Интерактивные player/damage callbacks,
заселённые объекты с другими specification-блоками и вся исходная
политика столкновений корабля не объявляются перенесёнными.

Высота возвращается в `height_s32`. `globals` содержит флаги
столкновения и объёма, индекс цели, primitive flags, текущую/предыдущую
64-битную высоту и вид контакта. F574 сбрасывает не все исходные слова:
старшая высота и previous-contact поля переносятся через явный контекст
`initial_globals`. Диапазоны такого контекста проверяются до работы.

Исходная F575 меняет переданный point buffer через Vec64Abs.
Чистый API сохраняет вход и возвращает это изменение отдельно как
`point_after_raw`. Изменённые копии объектов находятся в `probe/parent`.

## Непрерывное направление для будущего mesh/collision sampler

```gdscript
var sampled = surface.sample_record_radial(parent_record68, radial_q31, 1, 84)
```

Это отдельная явная политика `source_radial_probe_v1`:
реальная модель пробного объекта 84 с нулевой внутренней границей,
body-fixed кадр, заданный уровень детализации и два исходных запроса
с арифметикой F879. `radial_q31` имеет три signed32 компоненты и задаётся
вызывающей геометрией. Само направление не округляется до constructor
u16 углов: их шаг слишком велик для небольших треугольников около корабля.

При направлениях настоящей F1674 этот sampler совпадает с независимыми
F879-контролями. Для произвольного направления он является явно
обозначенным адаптером вызова исходного ядра, а не утверждением о новом
исходном constructor API.

Исходный запрос зависит от положения наблюдателя и детализации.
Живые mesh и столкновения должны использовать один выбранный sampler,
probe/detail policy и источник UID. Менять физическую высоту вместе
с пользовательским качеством текстур нельзя. Большие mesh-патчи требуют
кэша и подготовки вне основного игрового кадра.

## Неправильная сфера модели 117

Источник содержит эллипсоидальную модель 117 с неравными статическими
осями 14/23/71. Её исходная внешняя граница не охватывает длинную ось.
Синтетические F879-контексты для неё реально входят в контактную ветвь,
иногда возвращают нулевую высоту или `-1`. Полные выходные объекты и
матрицы этих ветвей совпадают с неизменёнными исходными инструкциями.

Это не доказательство наличия одной сферической посадочной поверхности.
`sample_record_radial()` с исходной F879-границей нельзя использовать
для превращения модели 117 в обычный шар. Её живая геометрия требует
отдельной несферической политики и, если исправляются исходные границы,
раздельного хранения оригинальной и исправленной физической величины.

У всех 21 настоящих наземных портов в текущем каталоге обе высоты
положительны, а обе query-ветви проходят исходный outside-terrain путь.
Модель 117 среди этих родителей не встречается.

## Независимые проверки

Текущий тест: **30 476 проверок, 0 ошибок**.

- 387 полных F879: 189 контекстов настоящих 21 портов и 198 явно
  синтетических контекстов дополнительных природных моделей/UID.
- 377 прямых F574, включая дальний отказ broad phase и исходные
  контактные случаи модели 117.
- 336 raw F1876 и 630 F581-контролей прежнего независимого leaf-эталона,
  применённых к нынешним, а не историческим модулям.

Ожидания получены настоящими инструкциями и не вычислены проверяемым
GDScript. Сопоставляются полные 338 байт объектов, signed64 координаты,
матрицы, обе точки/высоты и все 11 глобальных полей. Оригинальные и
наблюдаемые копии функций дают одинаковые выходные объекты. Три свежих
процесса, обратный порядок, полный родительский банк и защитные байты
проходят проверку. Host-адаптация стека отдельно описывает расширение
локальных кадров F582/F1495/F1669 для 64-битных push/pop.
