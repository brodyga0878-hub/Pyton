# Запись параметров и жизненный цикл задач оригинала — версия 0.31

Блок переносит смену модели F36, запись параметров F37 и управление задачами F38/F47/F52/F53 из загруженного `FIRSTENC.EXE`. Целевая версия — **0.31.0-tasks-alpha1 / Android code 56**. Это продолжение [ресурсов миссий и выражений 0.30](SOURCE_MISSION_EXPRESSIONS_RU.md). Локальный замороженный прогон подтверждён: **57 наборов / 287815 проверок / 0 ошибок**. APK, чистое восстановление и публикация требуют самостоятельных подтверждений; статус комплекта на момент исходного коммита — **PREPUB**.

## Каталог моделей и F36

Исходный каталог содержит **466** указателей: **465** ненулевых описаний и один нулевой элемент с индексом **149**. Начало таблицы `0x4d0cfc` независимо привязано к операнду F1538, конец `0x4d1444` — к операнду соседней таблицы строк F1345. Размер не выведен из удобного подмножества кораблей. Сохранены 68 байт каждого описания, первый байт связанного ресурса столкновений, **84** записи физических параметров по 24 байта и 15 слов масс приводов. [Каталог](../data/ffe_mission_models.json) воспроизводится из [1016 исходных диапазонов, 36025 байт](../validation/mission-tasks-2026-11-19/model-resources/original-spans.json).

F36 изменяет существующую 338-байтовую запись объекта. Он записывает индекс модели, пересчитывает два радиуса через исходные F1495/F1341, обновляет флаги и, если связана физическая спецификация, параметры тяги, оборудования и вместимости. Отсутствие физической спецификации сохраняет прежние соответствующие поля. Это отдельная процедура; создание объекта F1533 не подменяет её. Нулевой элемент 149 остаётся нулевой ссылкой каталога, а попытка разыменовать его при замене модели явно отклоняется ограниченным API.

Экстрактор сохраняет точные ресурсы, необходимые этим процедурам. Полный каталог описаний не означает переноса всех полигонов, текстур и мировых служб, на которые могут ссылаться другие слова описания. Этот блок сам по себе не меняет изображение кораблей в игре.

## F37: записи и события

Проверены полное тело F37, **67 байтов** таблицы селекторов и **18 DWORD** таблицы переходов. Неиспользуемые селекторы и значения выше 66 сохраняют исходный маршрут возврата. Записи различают общие слова модуля, локальные слова задачи, регистры событий, поля Root, запись объекта и рыночный буфер; произвольное присваивание словарю не заменяет эти адресные правила.

После записи общих слов F37 передаёт в F48 событие 3 с идентичностью описания программы; после записи локальных слов — событие 4 с физической задачей. Массивы по Root+`0x50e0`, Root+`0x50f8` и Root+`0x184` имеют свои события и исходные signed-проверки индекса. Изменение оборудования сохраняет последовательность F392/F390/F391, а изменение груза — 16-битную запись количества при 32-битном учёте занятой вместимости. Смена модели вызывает действительную F36.

В селекторе **62** загруженная DOS-версия безусловно записывает младший байт в объект+`0xff` и вызывает F48(23,0,индекс объекта). Дополнительная проверка физической спецификации модели появляется только в позднем JJFFE. Она не переносится в этот DOS-профиль.

## F38/F47/F52/F53: задачи, курсоры и поколения

| Процедура | Подтверждённое поведение DOS |
| --- | --- |
| F38 | По младшим 16 битам handle выбирает слот, сравнивает полное слово handle, снимает регистрацию активного блока и переводит задачу в состояние 5 либо увеличивает 16-битное поколение и задаёт состояние 6. Отдельного фильтра состояний 1..4 нет. |
| F47 | При состоянии 1 читает указатель условия текущего блока, выполняет F31, затем при истинном результате F41 с продвинутой позиции. В состояние 1 возвращает только задачу, оставшуюся в состоянии 2. Проверки объявленного числа условий нет. |
| F52 | Получает физический слот через F51, вычисляет аргументы F31 в вызывающей задаче и записывает их F37 в новой задаче. Два потока команд и две идентичности задач различны. Возвращает handle из задачи+4. |
| F53 | Снимает старые регистрации, исполняет начальный поток F41 из первого слова блока, обходит условия F31/F41, заново читает изменяемый блок и регистрирует итоговый блок через F33/F44. После сработавшего условия исходный цикл продолжает повторный обход с условия 1. |

Физический слот, упакованный handle, идентификатор локального окружения, описание программы и позиция команд различаются. Нулевой handle может быть допустим после оборота поколения; он не обозначает неудачу выделения F51. Полная арена приводит F52 к разыменованию NULL в оригинале, поэтому ограниченный перенос возвращает явный отказ, не выдумывая успешный результат 0.

Ссылки ресурсов сохраняют исходную идентичность и преобразуются в проверенные смещения. Вызывающий курсор F52, курсор аргументов новой задачи и локальные курсоры F47/F53 принадлежат своим кадрам вызова. Их нельзя свести к одному полю позиции либо к фиксированной выбранной задаче.

## Составление процедур и границы

Новые отдельные ядра проверяют точный порядок внешних вызовов и их состояния до/после. [Общий runtime](../scripts/source_mission_runtime.gd) связывает действительные прежние ядра F31/F22/F34/F33/F44/F45/F48/F51, новое F37 и F36. Его постоянный контекст содержит **18 полей** с единственными владельцами Root, банка, арены, общих слов, регистров и локальных окружений. Выбранная задача, её descriptor/локальные слова и позиции команд проецируются отдельно для каждого вызова. Постоянных дубликатов выбранной задачи и IP нет. Для полного оригинального образа выбор задачи дополнительно проверяет соответствие module index, descriptor и точного размера локального окружения.

При вызове событий новый закрытый адаптер наследует прежние тела дерева, диспетчера и планировщика. Он отдельно проверяет монотонные идентификаторы выделений и повторяет действительные действия F44/F45/F50 из журнала; повтор переноса не учитывается вторым исполнением в порядке вызовов. Это позволяет настоящим F51 и планировщику выделять и освобождать локальные окружения во вложенных вызовах. Рыночные записи хранятся в одной map; временный 308-байтовый буфер F37 привязывается к записи только успешным F649. F649 выражений получает проверяемый снимок для чтения.

Ограничение композиции задаётся явно: если планировщик вложенного события освобождает локальное окружение внешнего F31/F37, восстановить его временное представление нельзя, и runtime отклоняет весь переход. Смена выбранного descriptor или привязки общих слов может аналогично нарушить неизменяемые правила внешнего представления. Это ограничения текущего профиля, а не утверждения об ошибке DOS: последнему вызову F48 в оригинале иногда не требуется последующее чтение этих данных. Ссылки и байты освобождённого окружения не восстанавливаются искусственно. Вызовы верхнего уровня Tasks/Events допускают законное изменение арены и освобождение.

[Владелец состояния](../scripts/source_mission_runtime_state.gd) разделяет prepare и commit, проверяет ревизию/результат перехода и воспроизводит последний переход при холодном restore. JSON-декодирование нормализует числовые поля к тем же владельцам, что и рабочий контекст. Прежний сервисный контекст 0.30 остаётся отдельным историческим модулем; его проверки не выдаются за доказательство нового runtime. Итоговые показатели подтверждены замороженным прогоном ниже.

**F41 остаётся явным продолжением**, пока полное тело интерпретатора команд и его службы не перенесены. Внешние мировые службы, не закрытые исполненными ядрами, требуют типизированного ответа с точным контекстом. Универсальное «успешно» на внешней границе недопустимо. Ограничения памяти, числа шагов и fault-областей явно отклоняют вход и не публикуют частичное состояние.

В [новом аудите](../validation/mission-tasks-2026-11-19/AUDIT_RU.md) уточнены три DOS/JJFFE-различия. Предварительные предположения о фильтрах F38 и F47 в историческом плане блока 0.30 заменены этими байтовыми доказательствами; старые файлы сохранены как история.

## Проверка и комплект восстановления

Индивидуальные доказательства: [F36 и каталог](../validation/mission-tasks-2026-11-19/model-native-proof/instruction-proof.json), [F37](../validation/mission-tasks-2026-11-19/store-native-proof/instruction-proof.json), [жизненный цикл](../validation/mission-tasks-2026-11-19/task-native-proof/instruction-proof.json). Исполнение исследовательского native-адаптера и Godot, повторы ресурсов, проверка ZIP и проверка APK учитываются отдельными категориями. Суммы берутся из замороженных отчётов.

Набор runtime с окончательным native-банком проходит **1180 проверок / 0 ошибок**. Его **31 композиционный сценарий** содержит 106 измеренных результатов верхнего уровня и дочерних вызовов, 75 зависимостей, 16 явных ответов мира и четыре перехода с зависимыми рыночными данными. Доказательство объединяет 42 исполняемых исходных тела / 2690 инструкций; десять инструкций F1345 остаются отдельным якорем таблицы. Одно подтверждение NULL-разыменования F52 повторяет уже известную fault-область жизненного цикла и не увеличивает число уникальных fault-областей.

Четыре новых функциональных набора содержат **19 534** проверки: модели 4872, записи 9651, задачи 3831, runtime 1180. Полный [замороженный прогон](../validation/mission-tasks-2026-11-19/final-regression/summary.json) содержит **57 уникальных наборов / 287815 проверок / 0 ошибок**. Все прежние 53 набора сохранены; 51 подробный отчёт содержит текущие хеши зависимостей. Дополнительный [независимый контроль владельцев](../validation/mission-tasks-2026-11-19/independent-runtime-audit/README.md) хранит собственные 24 проверки / 0 ошибок и хеши; он не прибавляется к функциональной сумме. Native-банки моделей, записей и задач содержат соответственно 566, 467 и 260 сценариев; эти категории также не прибавляются к Godot-сумме.

[Runtime-freeze](../validation/mission-tasks-2026-11-19/runtime-freeze.json) содержит **585** входов. Из предыдущих **574** входов версии 0.30 изменены только строки версии в BuildInfo и Android export preset; остальные **572** входа и **473** остальных входа опубликованной игры совпали побайтно. `Main` сохранён.
