# Следующий модуль: классификация природного контакта F576

Это план по чтению закреплённого исходного текста и существующих модулей.
Новый код, нативные исполнения и тесты при подготовке документа не создавались.
Документ добавляется после замороженного source-коммита 0.20
`47903dae5b1688bac688a2568424ce3779489549` и не входит в его ZIP.

Следующая конкретная работа — положительный внутренний радиус корабля
в цепочке **F576 → F579 → F582 → F581 → F1876**, затем её соединение
с уже проверенным ответом игрока F575. F577 из 0.20 не заменяет эту ветвь:
природные модели 117..148 имеют непустой collision stream и исходный
признак `object+0x14C & 0x80`.

## Что подтверждено чтением

Закреплённый `ffe.asm`:

| Участок | Строка | Назначение в прочитанном исходнике |
|---|---:|---|
| F576 | 37052 | Передаёт внутренний радиус игрока в F579; переносит flags/primitive/collider; при внешнем результате может обойти дополнительные смещённые дочерние объёмы самого корабля. |
| F579 | 37656 | Truncate Vec64, минимум масштаба родителя, масштабирование радиуса-порога, условное преобразование через матрицу родителя и вызов F582. |
| F580 | 37753 | Переход к вложенной модели: смещение по исходной вершине, знаки/перестановка осей и рекурсивный вызов F582. |
| F581 | 37939 | Природная поверхность: четыре вершины, outer/inner bounds с порогом, построение query frame, F1876, altitude/previous-altitude/kind. |
| F582 | 38524 | Интерпретатор collision stream: условия по словам объекта, terrain record `0xFF`, плоскости F583, вложенные модели F580, flags и ранние возвраты. |
| F583 | 38803 | Signed plane test из исходных вершин/нормалей с масштабированием и радиусом-порогом. |

В F581 сравнение внешней границы — `(distance − outer) >= threshold`,
внутренней — `(distance − inner) <= threshold`. После F1876 сравнение
`(threshold >> 16) > query_result` определяет solid-контакт; равенство
не следует заменять произвольным epsilon. `DATA_008703/4` и
`DATA_008705/6` имеют разные обязанности: предыдущая высота нужна
последующему ответу F575. Сентинел и перенос старших слов нельзя
обнулять при каждом запросе.

Наличие либо отсутствие комментариев `FIX` не доказывает совпадения
с DOS. Для F576/F579/F580/F581/F582/F583 в этом разборе не установлено
новой байтово доказанной DOS/JJFFE-разницы. Перед переносом следует
отдельно сопоставить каждую нужную область с загруженным FIRSTENC.EXE.
Известные различия F577 и F578 из 0.19/0.20 нельзя переносить на соседние
функции по аналогии.

## Что уже есть и чего это не доказывает

- `scripts/source_ground_surface.gd:38` воспроизводит выбранную ветвь
  F1533 для моделей без physical-spec pointer. `height_raw:210` объединяет
  существующий природный height path и ограниченный non-player response.
  Он явно требует **нулевой** `probe+0x140` и нулевой child-marker перед
  collision stream. Это не готовый классификатор для трёх кораблей игрока.
- `scripts/source_terrain_point.gd:86` строит исходный query frame;
  `query_point_raw:126` уже принимает `threshold_raw`, сравнивает его после
  F1876 и возвращает исходные высоты/статус. Полный F576 и F582 этим не
  реализованы.
- `scripts/source_terrain_query.gd:195` содержит существующий terrain-query
  kernel, таблицы, feature tree и обход треугольников. Его прежние fixture
  проверки — база для повторного использования, а не новые проверки
  положительного player radius.
- `scripts/source_fuel_contact.gd:69` покрывает gas/star field 134..148
  через модель 84 с нулевым inner radius. Она read-only и не предоставляет
  полный player collision engine.
- `scripts/source_surface_contact.gd` уже принимает подготовленный kind1
  и предыдущую raw-высоту. `source_surface_contact_bridge.gd` в 0.19/0.20
  получает факт касания из опубликованного телефонного рельефа/CCD.
  Полной исходной классификацией этот поставщик не объявляется.

Исторические fixture содержат, например, 336 raw terrain controls,
630 F581 caller controls и 387 записей ground-placement/height набора;
их scope записан в самих fixture. Эти числа не являются новым выполнением
и не складываются с результатами 0.20. Нового native-proof F576 с
положительным радиусом игрока пока нет.

## Почему недостаточно убрать проверку нулевого радиуса

Исходные внутренние радиусы из дескрипторов: Cobra Mk III (модель 38) —
9600 raw, Eagle (24) — 5200 raw, Shuttle (15) — 1920 raw. Они должны
проходить исходное масштабирование F579, а не SI-клиренс телефона.

При отрицательном результате первой F579 функция F576 проверяет
collision stream **самого игрока** и читает перед ним дополнительные
записи смещения. Прочитанные из DOS дескрипторные окна:

| Корабль | Collision pointer | File offset | Первый signed child-word перед stream |
|---|---|---|---:|
| Eagle 24 | `0x4A06AA` | `0x8A2AA` | 0 |
| Cobra 38 | `0x4A3C9E` | `0x8D89E` | 13200 |
| Shuttle 15 | `0x49F1F0` | `0x88DF0` | 16000 |

Внешний запрос Eagle позволяет первым проверить полный bounded player
path без дополнительных child-offset записей. Для Cobra и Shuttle нужен
их действительный предшествующий поток и исходный цикл смещений;
подмена его нулевым маркером либо одним центром потеряет часть объёма.
F580/F583 также понадобятся при расширении с природного record на
общие вложенные модели и городские/станционные плоскости.

## Первый конкретный контракт и доказательство

Предлагаемый новый чистый `classify_natural_player(body338,parent338,
relative_vec64,context)` принимает actual descriptors/stream/vertices,
все необходимые исходные globals, Q31-позы и settings F1876. Возвращает
копии кандидатов globals, signed return F576, kind, primitive flags,
collider identity и точные altitude/previous-altitude. HP и живую сцену
сам классификатор не меняет; поддерживаемый F575 caller решает,
передавать ли результат старому kind1 response.

Первый набор native oracle: original F576/F579/F582/F581/F1876 и нужные
математические helpers, Eagle с его actual positive inner radius,
природные 117..133, затем отдельно 134..148. Нужны outside/inside-bound/
terrain/no-intersection, equality, оба scale path, оба режима `+0x56/57`,
сохранение previous/high words, все значимые flags и полный 338-byte
body/parent guard. После этого — полный реальный child-offset цикл
Cobra/Shuttle. Expected arithmetic должна поступать из исполнения
сопоставленных DOS-инструкций; неподдерживаемые F578/dispatcher ветви
следует перехватывать отдельно, а не заменять успешным ответом.

Интеграция Surface — отдельный шаг после raw proof: сохранить source
frame/body-origin/clearance adapter явно; проверить опубликованный и
saved contact patch, двойной city-floor/terrain hit, HP/RNG/fuel once,
ошибку/retry/save/menu и повторный взлёт. Одна радиальная высота не
доказывает универсальный CCD, выбор родителя F569/F570, станционные
коллизии, астероиды или кометы. Модель 117 в существующих данных отмечена
несферической; её caller correction нельзя распространять на остальные
тела как универсальный радиус.
