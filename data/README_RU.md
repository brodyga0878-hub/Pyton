# Повторно извлечённые данные FFE

Эти JSON **заново получены из исходного архива пользователя**, а не найдены как готовые файлы пропавшей облачной среды. Сохранившиеся экстракторы находятся в `recovered-history/`; новые инструменты восстановления — в `tools/rebuild_*.py` и `tools/data_validate_terrain.py`. Новые игровые настройки `ships.json` и перевод `world_names_ru.json` имеют отдельное происхождение.

## Исходные материалы

- `Frontier_First_Encounters.rar`: SHA256 `8495ca9a5c7714816c62255810bb88b878dab8f33b09090ef5e57a3ffafcd7fd`.
- `FIRSTENC/FIRSTENC.EXE`: 2 097 152 байта, SHA256 `d919566140abfc298bc9929bc9141d92526586821f017be1336253a04bca1e72`.
- Для чтения solid-RAR собран UnRAR из `https://github.com/pmachapman/unrar`, commit `160dcb5c9c1babbbdd3f0f1fc78cf48a7f8150cf`; CRC архива проверен. EXE извлечён через stdout и проверен до дальнейшего чтения. Оригинальная DOS-программа не запускалась.
- Исследовательский ассемблер: `https://github.com/videogamepreservation/jjffe`, commit `7e540341d4e09aa3c92877b87d49e7f2c143ad8d`. Проверяются полные SHA256 `ffe.asm`, `ffedat.asm`, `ffebmp.asm`; значения находятся в `ffe_data_provenance.json` и драйвере. Файлы исходного архива и собранные исследовательские ELF остаются вне каталога проекта.

Это совместимый исследовательский исходник, а не доказанная копия каждой инструкции загруженного EXE. Известное различие F879: `SAR 3` в JJFFE против `SAR 4` в EXE. F875 и проверенные terrain/ground процедуры эту функцию не вызывают. Непосредственно извлекаемые таблицы и модели проверяются по EXE.

## Независимая проверка

Новый host-native контроль исполняет настоящие процедуры F872/F873/F874/F875 с ABI-адаптацией стека 32 → 64 бита; данные и алгоритм конструктора не подменены. Все **133 записи** совпали побайтово, включая **147 слотов с 14 нулевыми** и конечные RNG-слова `[53157, 58170]`. Три свежих процесса дали одинаковый результат. Полный буфер слотов имеет SHA256 `900b5b0a321400cfc599b9ea4e13b570eef1eb8423a00a1982cbc167fe7c5fbf`. Также совпали четыре сохранившиеся старые native-записи: London, New Moscow, New San Francisco и Epping Newtown. Проверяемый fixture: `tests/fixtures/rebuild_handcrafted_native_reference.json`.

Реальные ground-контроли: **675** случаев F874/F1674 и **5832** случаев F650. На сохранённых исходных GDScript-модулях в отдельном validation-проекте Godot 4.6.3 пройдены **42 167** проверок площадок и **45** проверок city runtime, без ошибок. Это проверки восстановленных модулей, не полная старая тестовая база и не испытание телефона.

Terrain-контроли: **336** исходных F1876 запросов с пустым feature-list, **120** исходных F581 → F1876 запросов моделей 119/125/129/133 и **новая отдельная выборка из 510** настоящих native-запросов всех 17 моделей 117–133. Выборки повторены в обратном порядке в одном процессе и во втором свежем процессе. Сохранившиеся TerrainQuery/TerrainSurfacePoint и точная новая FFE Math прошли **9285 проверок, 0 ошибок** на Godot 4.6.3.

Новая выборка 510 не выдается за старый утраченный fixture из 608 случаев. Native-обёртка F581 использует широкие диагностические broad-phase bounds для входа в terrain-ветвь; высота и матрица вычисляются исходными процедурами. SetJmp использует начальный нулевой путь; недостижимые render/feature-ветви и LongJmp аварийно завершаются вместо выдачи поддельного результата.

Проверка integer terrain-цепочки ещё не подтверждает исходную географию, F879, метры, вращение планеты или Android-интеграцию исходного рельефа. Процедурный генератор всех заселённых систем не восстановлен.

## Воспроизведение

Нужны Python 3, GNU binutils (`as`, `ld`, `nm`), x86_64 Linux для исследовательских native-контролей и Godot 4.6.3 для проверки модулей. Игра на Android не исполняет эти исследовательские обёртки и не использует эмулятор DOS.

Расположив проверенные EXE и JJFFE за пределами проекта:

```sh
python3 tools/rebuild_handcrafted_native.py --source /workspace/ffe-upstream/jjffe/ffe.asm --executable /workspace/ffe-original/FIRSTENC.EXE --output /workspace/ffe-reference-controls
python3 tools/rebuild_original_data.py /workspace/ffe-original/FIRSTENC.EXE --source /workspace/ffe-upstream/jjffe/ffe.asm --native-ground-controls --native-terrain-controls
python3 tools/data_validate_terrain.py
```

Первый инструмент воспроизводит native F875 JSON и сырой буфер за пределами проекта. Драйвер сравнивает вновь извлечённые записи с сохранённым независимым fixture, пересоздаёт ресурсы и при указанных флагах ground/terrain fixtures. Последний инструмент создаёт временный Godot-проект; файлы игровых `scripts/` не заменяются. Драйвер отклоняет другой EXE или другую версию исследовательских исходников по хешу. Для отсутствующего исторического `extract_galaxy` предоставляется только известная константа `EXPECTED`; алгоритм галактики не имитируется.
