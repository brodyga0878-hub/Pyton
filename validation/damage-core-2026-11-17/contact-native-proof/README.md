# Actual original collision response through damage

This supplemental cohort joins the independently DOS-checked original F575,
F577/F578 classifier kernel to the whole original F953 damage kernel and its
actual event-register, dispatch, broadcast and shared RNG procedures. Python
transports their observed return records; it does not calculate expected
collision, shield, hull, damage or random arithmetic.

There are 40 contacts: 32 F578 pair routes with two sequential F953 calls,
plus eight original sphere/player/NPC response routes. The kernels execute
72 whole F953 calls and 54 F1530 calls. Both pair calls share the exact
preceding raw Root, flags, event registers, module entries and module count.
The second call receives the amount and attacker measured after original
F578 resumes the first full damage reply. This checks its source read order.

The former classifier observer could return only single-byte XOR mutations.
This composed ELF64 observer extends that explicit F953 boundary to return
the actual full 338-byte body and collider records. All original classifier
instructions remain unchanged. Native F575 resumes after each complete
damage result, including any later changes it makes to basis or velocity.

Root+C0 is explicitly bound to the classifier player-index word initially and
after each damage continuation. One audio reply changes this word; the native
classifier resumes with the measured owner value. The other twelve collision
words cannot be changed through this bounded damage context. The Root words
at +24/+28 remain the single RNG owner and carry between sequential calls.

Explicit authored providers cover negative filtered amounts, audio changes to
hull/flags/RNG, module limits and future flags. Original F144 executes its
captured null/non-null registry dispatch; actual non-null handlers, F48 event
work, audio, equipment effects and fatal response remain exact matched external
observations. They are not claimed as complete world effects. The five model
descriptors used here are immutable captured original records.

Every native kernel call repeats in three fresh processes and in reverse
order. Full raw body/collider/caller/global output and all damage callback
owner snapshots are retained. The SHA256-keyed zlib buffer pool preserves
raw bytes with declared length and hash verification while avoiding repeated
16KB Root and model-descriptor copies.

Replay uses captured source and adapters, including with missing original
paths and an independently copied proof directory:

```sh
python3 tools/rebuild_source_damage_contact_native.py --output /tmp/contact.json \
  --exe /absent/FIRSTENC.EXE --asm /absent/ffe.asm --data /absent/ffedat.asm
```

This cohort remains separate from primary independent native-bank counts.
It does not establish live Main integration, a new APK or phone performance.
