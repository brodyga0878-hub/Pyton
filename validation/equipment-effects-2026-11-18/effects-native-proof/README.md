# Original F953 → F952 / F942 composition

The research adapter resumes the whole original F953 procedure with measured
results from the whole original equipment or destruction kernels. Every
underlying kernel is independently compared with archived DOS instruction
bytes before compilation. Python routes input and return packets; it does
not calculate expected shields, hull, inventory, cargo, random numbers,
rewards, allocations, attitudes or positions.

The36 cases include16 real equipment calls,16 real destruction calls and4
shield-only controls. Original F951 actually selects cargo in two cases;
F1514 performs six original displacement calculations. Two cases have active
new model153 cargo records in the measured final bank. Thus a call that merely
attempts and fails cargo allocation is not reported as successful creation.
The cohort also covers explosion allocation failure, recyclable slots,
source/destination aliasing and reward-message paths.

## Native transport

Original F953's existing explicit F952/F942 observer seam gains a reviewed
full-owner reply buffer. The17,293 measured bytes contain its body, Root,
flags, event registers, module entries and module count. The original source
instructions are unchanged. This avoids inventing a numerical damage result
or approximating a changed record by a few byte patches. The complete bank
and Root from F942/F926/F927 are then retained outside the narrow F953 caller;
its final target and shared words are copied back in source order.

All196 damage,35 equipment and47 destruction transport invocations run in
three fresh native processes, then the complete invocation streams run in
reverse order. These are discovery/replay invocation counts, not extra
functional checks or independent case totals. The actual native control
bank contains36 unique complete composed cases.

Three assembly adapters and the destruction C support are archived here.
The corresponding SHA256 values and all underlying source/proof dependencies
are pinned in `composition-proof.json` and the fixture. Host execution uses
the reviewed ELF64 ABI adapters, not an unchanged IA32 binary; this is not an
Android emulator. Runtime evaluation remains native Godot arithmetic.

## Reproduce

```sh
python3 tools/rebuild_source_damage_effects_native.py
godot --headless --path . --script res://tests/test_source_damage_effects.gd
```

The default path uses only the archived source/proof/data dependencies and
GNU/Python tools. A copied-proof replay with all original EXE/ASM/data paths
deliberately absent reproduced the exact fixture and all five generated proof
inputs. `rebuild-verification.json` records that result. Buffers use lossless
SHA256-keyed zlib/base64 encoding; byte count and SHA must match after decoding.
`raw_row(fixture,row)` exposes the corresponding raw hexadecimal inputs,
observations and expected states for further native composition.

The caller's initial targets use original ship models0..148. Newly created
model153/155 records are real native outputs. Applying a later F953 hit to
those effect records remains outside the bounded old F953 model-read profile
and must reject atomically; no model-token substitution is used for that path.

Event-VM, handler, message UI, audio and string-expansion bodies remain
explicit typed providers. No live Main integration, new APK, complete event
world or physical-device/FPS claim follows from this source checkpoint.
