# Аудит исходного оборудования и последствий уничтожения

Проверены листинги `F933`, `F943..F952`, `F942`, `F926`, `F1675`, таблицы исходных ресурсов и прежние владельцы Root/банка. Исходный `FIRSTENC.EXE` имеет SHA256 `d919566140abfc298bc9929bc9141d92526586821f017be1336253a04bca1e72`. Независимое сопоставление DOS-инструкций и переносимость конкретных ядер подтверждаются их отдельными native-доказательствами; этот аудит сам по себе не заменяет эти проверки.

## Единственное состояние и алиасы

Корень начинается по DOS-адресу `0x64213c`; прежний профиль хранит целое окно 16 КиБ. Эти поля уже находятся внутри него:

| Исходное поле | Смещение Root / DOS VA | Использование |
| --- | --- | --- |
| D8818 / D8820 | `0x24` / `0x642160`, `0x28` / `0x642164` | Общие слова F1530/F922 |
| D8834 | `0x70` / `0x6421ac` | Счётчик временных слотов |
| D8857 | `0xc0` / `0x6421fc` | Индекс игрока |
| D8861 | `0xc8` / `0x642204` | Указатель игрока; в переносимом профиле логическая ссылка |
| D8888 | `0x114` / `0x642250` | Изменяемое слово награды |
| D8889 | `0x118` / `0x642254` | Слово, сравниваемое с выборкой F952 |
| D8891 | `0x120` / `0x64225c` | Граница выбора F951 |
| D8904 | `0x170` / `0x6422ac` | WORD, изменяемый F946/F951; одновременно элемент 30 грузового вектора |
| D8906 | `0x17e` / `0x6422ba` | Последний WORD грузового вектора, элемент 37 |
| D8911 | `0x19c` / `0x6422d8` | Счётчик, изменяемый на signed WORD физического описания |
| D8935..D8940 | `0x214..0x228` | Шесть DWORD конфигурации креплений |

Грузовой вектор F951 состоит из 38 WORD по смещениям `0x134..0x17e`. Его элемент 30 — то же слово Root+`0x170`, а не отдельный независимый счётчик. При выборе этого элемента исходные DEC и следующий INC обращаются к одной памяти и взаимно отменяются. F946 добавляет значение к этому WORD с 16-битным переполнением, а к Root+`0x120` и `0x118` — с 32-битным.

Банк занимает 38 986 байт: заголовок 116 байт и 115 записей по 338 байт. Флаги занимают только первые 115 байт заголовка; байт 115 необходимо сохранять отдельно как исходные непрочитанные данные. Отдельная копия флагов может существовать во временном контексте вызова, но сохраняемый владелец должен оставаться один.

## Выбор оборудования и сообщения

F933 один раз поворачивает исходное `body+0xc8` на 16 бит и сохраняет маску в локальной переменной. Он делает до 29 вызовов F922 с границей 29. Ненулевая маска с установленными только недоступными выбору битами 29..31 всё равно расходует 29 случайных шагов; ранняя оптимизация такой маски изменяет последующий поток игры. Выбранный бит записывается в текущие `body+0xc8`/`0xcc` по позиции `index XOR 16`.

Таблица D7211 физически содержит 30 DWORD кодов описаний, но F933 выбирает только индексы `0..28`. Таблица D7210 содержит 15 DWORD масс приводов. Это одна глобальная таблица, а не отдельные массы для каждой модели. Повторяющийся `drive_mass_table_u32` в ресурсах — форма транспорта; контекст общего мира должен требовать единые исходные значения `[0,4,10,25,45,80,150,250,400,600,6,12,24,36,0]`. Для знакового байта `body+0xd0` проверка допустимого индекса нужна только при фактическом чтении таблицы для игрока: непрочитанное значение NPC не следует отклонять лишь из-за старшего бита.

F944 проверяет селектор `body+0x118` до сообщения. Если он равен FF, выполняются F349, затем F148 даже тогда, когда обработчик сообщения уже изменил селектор. После этого F943 перечитывает селектор и может вызвать F148 ещё раз. Сообщение F944 определяет только слова пакета `+0x00=message`, `+0x04=argument`, `+0x18=0xffffffff`; остальные байты исходного стека не следует объявлять нулевыми или сохранять как игровые владельцы.

F148 передаёт обработчикам один изменяемый пакет action/value. Значения после первого обработчика должны попадать следующему; это локальные данные конкретного вызова и часть свидетельства, а не новая глобальная сохраняемая пара слов. Нулевые указатели исходной таблицы F144 возвращают управление без выдуманного вызова тела обработчика.

## Арифметика F946..F952

F947 читает знаковый индекс привода до очистки `body+0xd0` и DWORD `body+0x11e`. F948 при ненулевом прежнем индексе присваивает привод 1 и возвращает разницу исходной массы с 4. Обе ветви затем используют F944. Мутации из последующего сообщения или модульного обработчика не отменяются повторной очисткой.

F949 выбирает одно из шести креплений: обнуляет WORD `body+0xbc+2*i`, а для игрока также DWORD Root+`0x214+4*i`. F950 сравнивает результат F1530 как unsigned AX с порогами `0x0888`, `0x1c71`, `0x5555`.

F951 использует signed 32-битный курсор, unsigned WORD количества и исходное переполнение каждого вычитания. Обход идёт по индексам 37..0. Выбранный WORD уменьшается, Root+`0x170` увеличивается; Root+`0x118`/`0x120` здесь не уменьшаются. F952 получает signed WORD физического описания `+0x08`, передаёт его биты F922 и сравнивает результат с signed DWORD Root+`0x118`.

## Уничтожение F942 и порядок чтений

Условие награды проверяется по исходным attacker, Root+`0xc0`, селектору FB и ненулевому `body+0x11a`. Флаг игрока читается через Root+`0xc8`. Логическая ссылка 0 означает null; её нельзя автоматически превращать в запись банка 0 при фактическом разыменовании. Непрочитанное поле может оставаться непрозрачным.

После сообщения о награде F942 заново читает `body+0x11a` и выполняет 32-битное прибавление десятикратного значения. Отрицательные значения и переполнение не насыщаются. Прибавление счётчика уничтожений использует signed WORD физического описания `+0x16`; сообщение возникает при различии signed SAR16 прежнего и нового счётчика.

Сообщение награды определяет `+0x00=0x8635`, `+0x0c=bounty`, `+0x18=0xffffffff`. Сообщение изменения ранга определяет `+0x00=0x98cf` и `+0x18=0xffffffff`. Это разные наборы определённых слов; нельзя применять форму F944 `argument+0x04` ко всем сообщениям.

После звука создаётся эффект через F928/model155/flags9. Источник может совпасть с выбранным переиспользуемым слотом. Тогда модель исходной записи меняется на 155, и последующие чтения через исходный указатель обязаны видеть этот результат. Хранение отдельного неизменяемого тела цели нарушает это поведение.

Углы D8802/D8803 находятся перед Root (`Root-8/-4`), получаются заново и не являются холодными счётчиками. F1675 уже выражен в прежнем `BodyRotation.matrix_yzt`: исходная таблица Sin32, зеркальный индекс 16383 и Q31-умножение/отрицание. Использование этой функции требует отдельного подтверждения композиции; произвольный Float-поворот не эквивалентен.

После звука sample31 исходные описания моделей перечитываются перед расчётом масштаба. Локальная масса, уже использованная для порога 400, не заменяется новым значением из обработчика.

Первый цикл F926 использует `F922(6)-2`, проверяет `>0` до входа и выполняет от нуля до трёх вызовов. Второй читает текущий WORD `body+0x116`, делит на два и ограничивает четырьмя. После `F922(capacity)-2` значение 0 выполняет один вызов, а 1 — два: условие продолжения включительное. Тип груза использует свежий F1530 и первые 32 байта D7212; физическая таблица содержит 40 байт. Возврат F926 в F942 не используется.

F926 теперь выполняется как исходный расчёт, а не ответ-заглушка. Его F927 сохраняет слоты 0..19: свободный слот ниже 20 не используется; вместо него ищется переиспользуемый слот с битом 20 в диапазоне 114..20. Это отличается от F928, который допускает слоты 1..114. Груз создаётся с моделью 153 и флагами 15. Исходный FF-код преобразуется в WORD `body+0x9e` прибавлением `0x7200` только к младшим 16 битам.

Форматирование имени F1344 остаётся отдельным явным продолжением. После него F926 присваивает селектор FA, тип 11, код FF=21 и таймер 6, затем выполняет два шага F1530. Компоненты берутся из signed DWORD Root+`0x24`, Root+`0x24`, Root+`0x28` с SAR22. Они прибавляются к скорости; F1514 добавляет те же signed 32-битные значения к 64-битным координатам с исходным переносом и знаковым расширением.

F924 освобождает индекс, захваченный из `body+0x86`; он может отличаться от физического слота переданного указателя. Обнуление всей записи или замена захваченного индекса изменённым после callback значением не соответствуют оригиналу. F942 после F924 всегда возвращает 0.

## Дополнительные модели и область доказательства

Слот таблицы моделей 149 имеет исходный null. Дополнительно захватываются только подтверждённые модели 153 и 155; это не доказательство произвольного непрерывного каталога до 178. Модель 153 имеет физическое описание, модель 155 — нет.

В F1533 ненулевой токен модели используется до замены регистра указателем описания. Поэтому адаптер прежнего параметрического инициализатора с фактическим описанием и окончательным восстановлением токена может быть эквивалентным; это подтверждается полными native-результатами с настоящими токенами 153/155, включая copy/in-place и алиасные записи. Само извлечение ресурса не означает переноса всех визуальных эффектов уничтожения или расширения прежнего ограниченного F953 на все специальные модели.

F349, F1344, воспроизведение звука F1907, реальные тела модульных обработчиков и другие объявленные внешние продолжения остаются отдельными зависимостями. Контекст уничтожения содержит Root, банк и модульное окно; внешние продолжения этого профиля не получают владельца 71 регистра событий. Поэтому перенос не утверждает, что произвольный исходный обработчик может менять любые мировые данные. Сверенные DOS-инструкции выполняются в исследовательском ELF64 ABI-адаптере; это не запуск неизменённого IA32-файла на Android. Подключение Main, новая APK и физическая проверка S23 Ultra этим аудитом не утверждаются.

## Контрольные описи текущего блока

Оборудование: 503 native-сценария, 16 процедур/389 инструкций, 4562 функциональные проверки; отдельный владелец повторяет 64 выбранных native-сценария и имеет 782 проверки. Дополнительный F1533: 616 native-сценариев, четыре процедуры/214 инструкций, 4532 проверки. Уничтожение: 170 native-сценариев, 16 процедур/872 инструкции, 2486 проверок. Составная F953-композиция содержит 36 native-сценариев и 674 функциональных проверок.

Общая функциональная сумма — 43 набора / 249 807 проверок / 0 ошибок; пять новых наборов содержат 13 036 проверок. Native-категории полного пакета: 30 команд (23 первичных, 7 дополнительных), 11 448 первичных DOS-контролей, 16 отдельных диагностик JJFFE, 258 отдельных составных сценариев и один ресурсный повтор. Подмножества и повторы не суммируются повторно как независимые функциональные проверки.

Независимо выведена опись 551 runtime-входа: прежние 538 и опубликованные игровые 475 совпадают побайтно. Окончательные ZIP, чистое восстановление и HTTPS-публикация здесь ещё не подтверждаются; они остаются PREPUB до отдельных фактических проверок.
