# Native signed-field roots and positive-player classification

This new evidence leaves the published 0.21 993-case fixture, generator and source modules unchanged. Run `python validation/alignment-2026-11-13/native-root-proof/rebuild_source_contact_field_native.py` to rebuild the archived original assemblies in a temporary directory and reproduce the new fixture. Input candidate records and points are archived here; native outcomes are never calculated by a Python height or collision formula.

The new fixture `tests/fixtures/source_contact_field_native.json` contains51 anchors (17 supported landable source models, each at the reproducer direction, sourceX axis and sourceZ axis),153 signed geometry cases and306 canonical player classifications. Every geometry bank and classifier bank runs in three fresh native processes plus reverse-order repeats, with the original wrapper's object, parent, relative-vector and output canaries. Witness-selection probes only choose inputs; all selected inputs are rerun in the complete independent native bank.

Geometry runs full original F576→F579→bounded natural F582→F581→F1876 with the actual positive-radius Eagle24 and its actual zero-child marker. The new F581 wrapper only observes the real scale, shifted local point, F581 status, depth and vertex count; original instructions, registers and flags are preserved. This avoids a host approximation of F579 scaling, frame construction or terrain height. The existing67-procedure DOS instruction proofs and immutable original resources provide the execution provenance.

For each anchor the native kernel confirms the candidate's final signed residual. There are39 exact zeroes and12 outward sign boundaries with adjacent integer ray radii, width1raw. Each final point also has a separately native-confirmed strict negative inner witness and positive outer witness. Exact-zero witnesses can be wider than one integer step; that does not weaken the independently confirmed zero and does not assert uniqueness or monotonicity of the entire ray. The fixture records every witness radius and actual signed result.

Two model117 anchors, sourceX and sourceZ, are geometry-only exclusions under the original descriptor bounds: one is inside the original inner gate and the other outside the original outer gate. Only their geometry queries use explicit zero-inner/positive enlarged-outer parent bounds to admit the original F581 terrain branch. This is an experimental caller context and never enters the canonical player bank. All306 player cases retain the actual original parent descriptor bounds, positive initialized ship radii, actual backwards child streams and supplied raw upright body matrices. The player bank checks all three ships at each final point and again after an outward ray offset equal to that ship's original inner radius. It does not assume either point must report hit or no-hit: child collision volumes and original coarse gates remain authoritative.

The original player inner radii are5200raw (Eagle24),9600raw (Cobra38), and1920raw (Shuttle15). Display conversion is exactly `16785/16777216` metres per raw unit, as pinned by `scripts/source_units.gd`, rather than a rounded0.001. These radii are approximately5.202413m,9.604454m and1.920891m. Canonical source comparisons remain signed integers; SI conversion never participates in certification.

The unchanged placement seed follows pinned JJFFE F879's documented SAR3 step, while uploaded DOS F879 has SAR4. Seed provenance is explicitly included for every anchor. Native certification depends on the final point's actual original DOS F581/F1876 result, independently of that seed. This is a new bounded modern field caller, not a claim that the original game used a radial root solver.

This evidence establishes point and witness conformance only. It does not certify a linearly interpolated render triangle, a global unique terrain root, live landing integration, F575 response composition, device performance or a complete original-game clone. In particular the strict source predicate can return no-hit at an exact zero or at ship clearance, and Cobra/Shuttle child volumes can report contact when the initial central volume does not. Accepted landed-state holding and triangle-visible alignment need their own explicit checks.
