# Аудит записи параметров и жизненного цикла задач — 19 ноября 2026

Область версии **0.31.0-tasks-alpha1 / Android code 56** — F36, F37 и F38/F47/F52/F53 с точными ресурсами и владельцами состояния. Локальный freeze подтверждён: **57 наборов / 287815 проверок / 0 ошибок**. В замороженной исходной копии статус комплекта был PREPUB. Последующие проверки APK, пары ZIP и HTTPS-публикации завершены и зафиксированы отдельно ниже; исходные архивы не переписывались.

## Оригинал и независимая сверка

Авторитетный `FIRSTENC.EXE` имеет SHA256 `d919566140abfc298bc9929bc9141d92526586821f017be1336253a04bca1e72`. Идентичности вспомогательных листингов сохранены в proof JSON и ресурсной capture. Поздний JJFFE используется для именования и сопоставления, но его отличия не заменяют байты загруженной DOS-версии.

Независимое чтение EXE заново разобрало заголовок PE, ImageBase и таблицу секций без класса Image экстракторов. Все **15** диапазонов кода и таблиц трёх proof-пакетов побайтно совпали с их capture и SHA256: пять у моделей, шесть у F37, четыре у задач. Отдельно совпали все **1016** ресурсных диапазонов моделей, суммарно **36025** байт. Вручную проверенные DOS-инструкции повторно дизассемблированы `objdump` из отдельно вырезанных исходных байтов.

Такая сверка подтверждает происхождение capture и привязки памяти; она не подменяет native-выполнение, тесты Godot или проверку runtime-составления. Исследовательский ELF64-адаптер переносит ABI и логические ссылки; он не является запуском IA32 DOS-программы либо Android-эмулятором. Необходимо сохранять исходные разрядности, signed-сравнения, порядок обращений к памяти и изменения курсоров.

## Полная граница каталога моделей

F1538 обращается к таблице по VA `0x4d0cfc`; независимо проверенный операнд F1345 обращается к следующей таблице строк по VA `0x4d1444`. Разность **1864** байта даёт ровно **466 DWORD**. Элемент 149 равен NULL, остальные 465 ссылаются на описания. Начальная и конечная привязки проверяются по целым исходным инструкциям, а не по близости меток листинга.

Для всех 465 элементов независимо прочитаны 68 байт описания и его поля ссылок `+0x34/+0x38`; первый байт столкновений и все 84 присутствующие физические спецификации по 24 байта совпали с JSON. Таблица масс приводов содержит 15 точных DWORD. Сохранение описаний не означает извлечения всех геометрических, текстурных и мировых ресурсов, на которые ссылаются прочие поля.

Основное арифметическое доказательство содержит целые F36/F1538/F1495/F1341 — **4 процедуры / 185 инструкций**. F1345 проверена отдельно как якорь границы ресурсов и не прибавляется к этим четырём. F36 работает с существующей записью объекта 338 байт; F1533 не используется как замена. Полное сравнение записи должно учитывать неизменённые байты при отсутствии physical spec, 16-битное сложение показателей, знаковое старшее слово радиуса, исходный 64-битный сдвиг и signed-индекс привода.

Нулевой индекс 149 является определённым результатом lookup. F36 затем разыменовывает модель: ограниченный API явно отклоняет эту fault-область. Успешная пустая замена либо подстановка другой модели были бы новым поведением.

## F37 и встроенные таблицы

Доказательство [store-native-proof](store-native-proof/instruction-proof.json) охватывает целые F20/F37/F1532: **3 процедуры / 351 инструкция**, включая **314** инструкций F37. Два исполняемых участка F37 разделены встроенными данными. Отдельно проверены все **67 байтов** DATA3 и **18 DWORD** DATA4, их настоящие DOS-адреса назначения и границы исходных инструкций.

DATA3 находится по `0x4126a2`, DATA4 — по `0x4126e5`. Повторяющиеся назначения возврата и неиспользуемые селекторы нельзя заменять предположением о непрерывном наборе команд. Селекторы 0..255 проверяются с реальной таблицей, включая исходный путь для значений выше 66.

Запись в общие слова использует указатель текущего описания программы и событие 3; запись в локальные слова использует физическую задачу и событие 4. Эти ключи различны. Количества оборудования изменяются исходной последовательностью F392/F390/F391 с остановкой при ошибке, а не прямым присваиванием. Рыночное слово записывается только при ненулевом результате F649 и допустимом индексе товара; после него следует событие 24.

F37 не имеет определённого скалярного результата. Значение EAX после void-вызова не становится возвращаемой игровой величиной. Границы F31/F22/F34/F36/F48 и мировых процедур фиксируют полное состояние до/после и точный порядок; runtime обязан закрывать доступные тела настоящими ядрами.

## Три реальных DOS/JJFFE-различия

1. **F37, селектор 62.** По `0x412a18` оригинал читает младший байт значения, по `0x412a1b` пишет объект+`0xff`, затем без проверки physical spec вызывает F48(23,0,индекс) по `0x412a26`. Поздний JJFFE добавляет F1538 и проверку ненулевого `model+0x38`. В DOS-профиле это условие отсутствует.
2. **F38.** Целые **97 байт / 33 инструкции**, начало `0x412ab0`, SHA256 `8d818eef25007752e7f2498b71e553773b6d0ef2d5042abbf07a2adfd61ea5b9`. После вычисления слота оригинал сравнивает полное слово handle по `0x412acd`; при совпадении сразу проверяет активный блок по `0x412ad2`. Фильтра состояний 1..4 нет. Он добавлен в JJFFE.
3. **F47.** Целые **77 байт / 31 инструкция**, начало `0x413ff4`, SHA256 `9315238ba26157c2d89800bfdb50eddd63879906c4a1026d60565abad176fe73`. После state==1 оригинал по `0x414007` читает `[block+clause*4+8]`, не сравнивая индекс с объявленным числом условий. Такой фильтр присутствует в JJFFE.

Эти факты уточняют предварительные JJFFE-предположения исторического [плана 0.30](../mission-expressions-2026-11-18/NEXT_BLOCK_PLAN.md). Историческая копия не редактируется. Для DOS нельзя утверждать, что всякая неактивная задача с совпавшим handle является no-op либо что F47 всегда отбрасывает индекс за объявленным количеством условий. Ограниченный профиль вправе явно отклонять недопустимое адресное обращение, но не выдавать этот отказ за исходную дополнительную проверку.

## Жизненный цикл и независимые кадры вызовов

Доказательство [task-native-proof](task-native-proof/instruction-proof.json) содержит целые F38/F47/F52/F53 — **4 процедуры / 177 инструкций**. F38 получает packed handle; F47 и F53 — физическую задачу. Арена содержит 150 записей по 36 байт. Выход low16 handle за 149 является явной неподдерживаемой областью исходного неограниченного доступа.

F38 сначала сравнивает полное слово поколения/слота, при несовпадении возвращает управление. Ненулевой активный блок снимается через F33/F45, затем задача+8 очищается, задача+`0xc` получает -1. Неотрицательное cleanup-поле описания даёт состояние 5 без увеличения поколения; отрицательное — 16-битное увеличение поколения и состояние 6. Повторный вызов с совпавшим handle при отсутствии DOS-фильтра состояний должен сохранять этот исходный порядок.

F47 владеет локальным курсором условия, а не меняет поле текущего блока задачи. Истинный F31 переводит задачу в состояние 2 и передаёт F41 уже продвинутую позицию. После F41 сбрасывается в 1 только состояние, оставшееся равным 2; callback может выбрать иное состояние.

F52 получает физический слот через F51, а возвращает packed handle задачи+4. Нулевой handle допустим после оборота поколения; NULL результата F51 — другая сущность. При полной арене оригинал далее разыменовывает NULL; перенос должен явно отклонять этот путь до публикации состояния. Аргументы вычисляются F31 в вызывающей задаче с вызывающим курсором, затем записываются F37 в новой задаче с отдельным курсором lvalue-потока. Перед возвратом новой задаче задаются блок 0 в `+0x10` и индекс 0 в `+0x14`. Нельзя повторно вычислять аргументы в новой задаче либо принимать адрес выделенного слота за handle.

F53 ставит состояние 3, снимает прежние регистрации, очищает активный блок и индекс, затем исполняет F41 по первому слову нового блока. Это поток команд, не условие. После каждого F31 истинное условие продолжает F41 с его конечного курсора. Исходные `xor esi,esi` и общий `inc esi` означают возобновление повторного обхода с **условия 1**, не 0. Текущий блок и состояние читаются заново после callback. Итоговый блок и индекс копируются в активные поля, F33/F44 регистрирует его условия, затем ставится состояние 1.

## Составление runtime и владелец состояния

Изолированные ядра используют точные типизированные наблюдения внешних служб. Новое runtime-составление связывает действительные F31/F22/F34/F33/F44/F45/F48/F51 и новые F36/F37 с одним владельцем Root/хвоста/банка, арены, общих слов, регистров, scratch и локальных окружений. Постоянный Core содержит **18 полей**. Доступ к задаче и её переменным — временная проекция; вызывающий и вызываемый кадры имеют самостоятельные task ID и IP. Отдельные постоянные selected task/IP и копия локального буфера не вводятся.

Контекст 0.30 с фиксированными descriptor/vars ID не является доказательством переключения задач в новом runtime. Для нового контекста отдельно проверены создание через F52, запись аргументов F37 в callee, независимость caller IP и закрытые событийные регистрации. Полный исходный образ проверяет выбранный module index, соответствующий descriptor и точное число байтов локального окружения. Такая проверка выполняется при проекции выбранного кадра: неактивные записи арены сохраняют законные устаревшие токены после освобождения.

Новый частный класс событий наследует прежние тела дерева, выделения задач, dispatch и планировщика. Только транспорт callback расширен проверкой монотонного выделения/удаления локальных окружений. Для дерева обязателен журнал настоящих F44/F45/F50: повтор действий должен воспроизвести root, map узлов и счётчик следующего идентификатора. Порядок вызовов принадлежит действительному вложенному исполнению; транспортный повтор журнала не дублирует F44 в отчёте. Прежнее тело Events не редактируется.

Рыночные записи хранятся в map Core по логической идентичности. Временный буфер Store создаётся только как представление найденной записи; нулевой транспортный буфер до успешного F649 не сохраняется как рыночные данные. F649 выражений использует снимок для чтения и не подменяет существующего владельца.

При исчезновении локального окружения внешнего Expr/Store во вложенном планировщике профиль возвращает `dangling_outer_projection_outside_composition_profile`. Смена выбранного descriptor/global binding также может быть отклонена сохранёнными правилами внешнего Expr/Store-представления даже без последующего исходного чтения. Это ограничения композиции, **не доказанные DOS fault-области**: оригинальному последнему F48 может не требоваться новое обращение к этим данным. Освобождённый идентификатор не переиспользуется и байты не восстанавливаются. Вызовы верхнего уровня Tasks/Events допускают законные изменения арены и настоящее освобождение.

F41 остаётся явным внешним продолжением; полный интерпретатор команд и все мировые службы в этом блоке не заявлены. Внешний обработчик должен предоставить проверяемые состояние, аргументы и позиции, а не безусловный ответ «успешно». Отсутствующий ответ, неверный task ID/IP, несовпавшая программа, лишний ответ или превышение допустимого профиля дают отказ. При отказе живые владельцы не меняются.

Подготовка, commit и restore состояния должны проверять форму входов до глубокого копирования/хеша, ограничивать циклические либо чрезмерно большие данные и допускать снимок каждого принятого candidate. Итоговое восстановление не должно вводить вторую копию арены, банка либо локального окружения.

Независимый [воспроизводимый Godot-контроль](independent-runtime-audit/README.md) проверил **24 условия / 0 ошибок** вне функциональной суммы freeze. [Отчёт с хешами](independent-runtime-audit/verification.json) фиксирует входы до/после проверки. Контроль охватил фактический полный образ, отклонение неверных module/descriptor и размера локальных слов, warm/cold-продолжение F53→F41, изоляцию prepare, подменённый receipt, устаревший commit, replay restore и отказ циклических/глубоких входов до копирования/хеша. Отдельный маршрут F54→F53→F41→F31(false)→F33/F32→F44 подтвердил действительные зависимости и единственный F44 в порядке вызовов. Действительные F51/F54 проверены на допустимом handle0 после оборота поколения и освобождении ровно одного владельца без повторного использования ID. Аудит выявил и проверил исправления привязки выбранного кадра и нормализации JSON-чисел. Эти проверки не заменяют замороженный набор runtime либо native-композиционное доказательство.

Набор runtime с окончательным fixture содержит **1180 проверок / 0 ошибок**, 31 native-сценарий и шесть последовательных шагов с одним владельцем. `native_fixture_pending` равно false. SHA256 окончательного fixture — `3a2523e896e8d3cbdc3b7e149a9a591fbca2a68485e9ecdfc05cd9d41b6b7421`. Четыре новых функциональных набора содержат **19534** проверки: модели 4872, записи 9651, задачи 3831 и runtime 1180. [Общий замороженный прогон](final-regression/summary.json) содержит **57 уникальных наборов / 287815 проверок / 0 ошибок**. Все прежние 53 набора сохранены; 51 подробный отчёт содержит текущие хеши зависимостей.

## Native-составление и отдельные категории

[Композиционное доказательство](runtime-native-proof/README.md) исполняет 31 сценарий с одним Core18: **106** измерений верхнего уровня и дочерних переходов, **75** вложенных вызовов, **16** явных ответов мира и **4** зависимых рыночных перехода. Шесть исходных proof-пакетов подтверждают **42 составляющих тела процедур / 2690 инструкций**. Число составляющих не объявляется числом уникальных игровых функций; повторные F20/F1532 в разных proof-пакетах не увеличивают число реализованных возможностей. Дополнительно F1345 даёт десять инструкций исключительно для привязки границы таблицы моделей. 43 capture-процедуры / 2700 инструкций вместе с этим якорем не объявляются 43 исполняемыми зависимостями.

Оригинальные тела событий и assembly не изменены. Новый исследовательский callback-адаптер переносит измеренные выделения/освобождения логических окружений и реальные F44/F45/F50-действия в приостановленный родительский процесс, сохраняя исходные адреса его дерева и снимка callbacks. Перед побайтовым переносом арены descriptor/variable pointers преобразуются в логические токены и обратно; частичное изменение младшего байта не используется как перенос хостового указателя.

Исследовательский native-профиль допускает последовательные сохранившиеся новые выделения и измеренные освобождения. Временная последовательность allocate/free с пропусками монотонных ID не покрыта этим транспортом. Это ограничение native-корпуса, а не утверждение о полном покрытии всех корректных ответов F41/мира.

Одно подтверждение полной арены F52 даёт SIGSEGV в трёх исследовательских повторах. Оно подтверждает уже известную NULL-fault-область F52 из отдельного task-банка и не добавляет ещё одну уникальную fault-область. Нет выдуманного полного after-state; runtime отклоняет этот путь до публикации живых владельцев. Все 31 обычных сценария учитываются отдельно от fault-повторов.

Новые основные native-банки моделей/записей/задач содержат соответственно **566 / 467 / 260** сценариев; новый дополнительный композиционный банк — **31**.
