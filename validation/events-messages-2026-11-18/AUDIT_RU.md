# Аудит исходных событий, задач и сообщений

Аудит выполнен по исходному листингу, структурам данных и полным сверкам выбранных тел с `FIRSTENC.EXE`. SHA256 исходного EXE: `d919566140abfc298bc9929bc9141d92526586821f017be1336253a04bca1e72`. Доказательства [событий](events-native-proof/instruction-proof.json), [сообщений](messages-native-proof/instruction-proof.json) и [игрока](player-events-native-proof/instruction-proof.json) охватывают соответственно 12/5/4 полные процедуры и 541/278/104 инструкции: всего 21 процедура и 923 инструкции. Эти числа не являются числом функциональных тестов или сценариев native-корпуса.

## Дерево событий F42..F50

F44 выделяет узел 32 байта: левый/правый указатели, три слова ключа, callback, два аргумента. Сравнение F42 читает шесть слов полезной части в порядке смещений `0,4,8,0x10,0x14,0x0c`: callback сравнивается последним, после аргументов. Каждая разность — исходный signed результат 32-битного SUB с переполнением. Это не обычный лексикографический порядок 64-битных чисел.

При полном равенстве F44 всё равно вставляет новый узел справа. F45 удаляет первый узел, найденный исходным поиском. Для двух потомков берётся правый край левого поддерева. Предшественник сначала исключается из своего прежнего места, затем получает потомков удаляемого узла. Если он был непосредственным левым ребёнком, обратный порядок создаёт ошибочную петлю.

F48 ищет по трём словам через F43. После первого совпадения F46 обходит только найденное поддерево в порядке left/node/right и строит отдельный связный список 16-байтовых записей callback/arg1/arg2. Вся выборка сделана до первого вызова. Добавление либо удаление регистрации из обработчика не меняет уже полученный список.

Поиск по дереву нельзя заменять просмотром всех регистраций: при крайних значениях переполняемого сравнения порядок может быть нетранзитивным, и область исходного найденного поддерева имеет значение. После исполнения списка его временные записи освобождаются, затем вызывается F54. При отсутствии совпадения F48 не вызывает F54 вообще.

Числовое слово callback участвует в сравнении, поэтому логический токен обязан сохранять объявленную исходную числовую семантику. Нативный адрес хост-процесса не является переносимым сохраняемым идентификатором.

## Арена задач и поколения

D8561 по подтверждённому DOS-адресу `0x60bf50` содержит 150 записей по 36 байт. Указатель дерева D8564 находится по адресу `0x60d468`, сразу после арены. Поля записи: state DWORD `+0`, индекс WORD `+4`, поколение WORD `+6`, подписанный узел `+8`, курсор `+0xc`, текущий узел `+0x10`, позиция операнда `+0x14`, индекс программы `+0x18`, описание программы `+0x1c`, окружение `+0x20`.

F51 выбирает первый state=0, присваивает state=4, записывает индекс и увеличивает 16-битное поколение с переполнением. В окружение помещаются DWORD упакованного index/generation и исходный аргумент. F52 возвращает этот упакованный DWORD `task+4`, а не указатель записи. F47 получает именно физический указатель записи задачи; его нельзя незаметно заменить защищённым поколением клиентским handle.

При индексе 0 и переходе поколения FFFF→0000 упакованный handle равен 0, хотя F51 успешно вернул ненулевой указатель задачи. Ошибка выделения и нулевое значение упакованного результата различаются. После освобождения F54 меняет state на 0, но не очищает старый указатель окружения и остальные поля записи; непрочитанные неактивные значения сохраняются, а не превращаются автоматически в null.

API F51 отдельно объявляет определённый указательный результат и логический слот, без сохранения адреса процесса. Успех выделения определяется наличием слота, а не ненулевым упакованным handle; семантика скалярного возврата void-процедур к этому указателю не применяется.

Размер окружения берётся из описания программы `+0x10`, умножается на четыре, после чего оригинал безусловно записывает первые два DWORD. Для независимого профиля нужны минимум два слова, проверенный верхний предел и явное отклонение неохваченных ошибок выделения. При заполнении всех 150 слотов F51 возвращает null; F52 после такого результата в оригинале обращается к null. Успешный запуск новой задачи в этом случае был бы выдуманным поведением.

F54 каждый раз заново сканирует всю арену и выбирает максимальное signed state. При равенстве побеждает меньший индекс, поскольку сравнение строгое. State 4 вызывает F53; state 5 сначала становится 6 и вызывает F41; state 6 освобождает окружение и становится 0. Обработчик F41 может изменить состояние, поэтому освобождение после ветви 5 не должно выполняться без нового сканирования. При максимуме не больше 3 цикл заканчивается. Значение больше 6 в исходном коде приводит к повторному сканированию без прогресса; ограниченный перенос не должен объявлять эту ветвь успешно завершающейся.

F48 — диспетчер, а не вся VM. F41 содержит большой интерпретатор с обращениями к мировым операциям. Явное продолжение F41/F31 не доказывает исполнение всех исходных скриптов, команд мира и ресурсов программ.

F44/F45/F46/F48/F49/F50/F53/F54 не определяют устойчивый скалярный результат EAX. Хостовый остаточный указатель или возврат free нельзя выдавать за переносимый исходный ноль. Диагностические логические идентификаторы относятся к API переноса; сравнения F42/F43, указатель F51 и упакованный handle F52 имеют отдельную определённую семантику.

## Регистры и временный индекс удаления

71 DWORD D8548 занимает 284 байта по адресам `0x60be08..0x60bf23`. **F55 не обнуляет регистры 2..9.** Он обнуляет восемь других DWORD D8550..D8557 в отдельном 32-байтовом окне `0x60bf24..0x60bf43`. Это подтверждено полным сопоставлением процедуры и независимым чтением восьми абсолютных записей A3 в оригинальном EXE с файлового смещения `0x51a3`. Хостовое переназначение этих символов внутрь регистров дало бы ложный паритет native/Godot при неверной модели памяти; правильный профиль имеет отдельный владелец `scratch_words`.

Привязка оригинальных DOS-инструкций подтверждает D8560 по адресу `0x60bf4c`, со смещением `0x144` относительно D8548; это не элемент допустимого вектора `0..70`. D8558/D8559 (`0x60bf44`/`0x60bf48`) — ещё два отдельных поля текстового буфера, не входящие ни в 71 регистр, ни в окно F55. F61 записывает signed индекс удаляемого объекта в D8560, вызывает F48(22,0,index), затем обнуляет поле. Во время вызова F31 содержит выражение, сравнивающее результат с D8560. Нужен один отдельный временный владелец либо явно связанное представление этого поля; расширение массива регистров до индекса 81 не соответствует прежнему контракту.

## Поля игрока и обработчики event11

Для индекса из F1103 определён младший байт: исходная передача может сохранять неопределённые старшие биты регистра. F1102 использует BL либо MOVSX BL. В ветви повреждения signed индекс сравнивается с Root+`0xc0` (`0x6421fc`); при совпадении устанавливается DWORD D8886 / Root+`0x10e = 30` (`0x64224a`).

В ветви удаления сначала очищается совпавшая байтовая ссылка D8887 / Root+`0x112` (`0x64224e`). Следующая проверка относится к D8877, который в оригинальном DOS F1102 находится по адресу `0x4eed84` вне Root. Вывод Root+`0xef` из позднего JJFFE-layout для этой переменной оказался неверным и не применяется к переносу. Нужен один отдельный владелец `watched_index_u8`; Root+`0xef` сохраняется как непрочитанное поле. При совпадении watched_index он обнуляется; при Root+`0xea = 5` обнуляется и это поле, затем идут F262/F991. В этой ветви F1101/F1104 не вызываются. В другой ветви они вызываются с signed индексом. Root+`0xe8` — экран/режим D8870, Root+`0xea` — другое поле D8872 (`0x642226`); их нельзя объединять.

Привязки символов определяются по исходному EXE, а не только суммированием resb из позднего листинга; пример D8877 показывает различие размещения. F1101 работает с signed ссылками Root+`0xec`/`0xed` и собственными повторными проверками. Более глубокие эффекты UI, автопилота и завершения игры остаются отдельными зависимостями, если их тела не выполнены.

Перенос обработчиков игрока исполняет F1103/F1102/F1101 и F61. Это не вся таблица event11: связанные обработчики других модулей F779/F256 и их продолжения не становятся исполненными от наличия общего F144. Дальнейшая интеграция должна различать действительное тело выбранного обработчика и записанное внешнее наблюдение.

## Сообщения F349/F350/F351

DOS-привязка D8870 подтверждена как `0x642224 = Root+0xe8`. F349 вызывает F217, когда исходный Root+`0xe8` не равен 4. Затем F351 заново читает режим и ничего не ставит в очередь при `0x2c`. Если флаги пакета `+0x18` неотрицательны, вызывается F1906/sample22, затем F350. Изменение режима между этими вызовами учитывается по месту исходного чтения.

48-байтовый пакет F350 не полностью инициализируется всеми вызывающими функциями. Equipment/F944 задаёт только `+0=message`, `+4=argument`, `+0x18=-1`; награда F942 задаёт `+0=0x8635`, `+0xc=bounty`, `+0x18=-1`; сообщение ранга — `+0=0x98cf`, `+0x18=-1`.

При отрицательных флагах F350 переносит в пять аргументов форматирования слова `+4,+8,+0xc,+0x24,+0x2c`. Часть из них в перечисленных вызовах не определена. Заполнение их нулями не доказывает исходные значения. Связка частичного пакета должна сохранять маску определённых слов и проверять реально потребляемые аргументы шаблона либо оставлять форматирование явным продолжением с объявленной областью чтения.

Порядок пяти аргументов форматирования при неотрицательных чётных флагах — `+0,+8,+0xc,+0x2c,имя`; имя берётся по указателю `+0x1c + 0x124`, либо используется строка D9148 при null. При нечётных порядок — `+4,+8,+0xc,+0x24,+0x2c`. Слова, содержащие ссылки, нельзя переносить как адреса Android-процесса.

F350 выбирает цвет `0x11` для отрицательных флагов и `0x5f` для остальных. Липкость очереди определяется вторым аргументом F350: только ноль даёт F271 flags=1. F351 передаёт 1, поэтому обычные F349/F351 сообщения нелипкие независимо от отрицательных флагов исходного пакета.

## Кольцевая очередь F271

Десять записей по 1038 байт: day DWORD `+0`, low DWORD `+4`, цвет BYTE `+8`, строка на 1025 байт `+9`, flags DWORD `+1034`. Это 10 380 байт вне Root, начало D8678 подтверждено по адресу `0x631430` (D8679=`0x631434`, цвет=`0x631438`, строка=`0x631439`). Индекс записи D5099 находится по адресу `0x4d4968`. UI-время D8799 также отдельно от игровых слов времени Root+0/+4.

F271 копирует входную C-строку в локальный буфер 1024 байта, вызывает F1398 с шириной 120 и считает только CR `0x0d` в изменённом локальном буфере. В очередь копируется исходная, а не перенесённая строка, включая NUL и без очистки оставшегося хвоста. Ограничение строки по ёмкости очереди не устраняет переполнение меньшего локального буфера: поддерживаемый профиль должен ограничивать и исходный, и перенесённый результаты.

Пустая ненулевая C-строка и null-указатель различаются. Пустая строка всё ещё записывает время, цвет и флаги и выполняет обычные изменения очереди; только null выбирает ветвь снятия липкого сообщения.

Нелипкое сообщение увеличивает индекс записи по модулю 10. Липкое оставляет его на месте. Null-текст снимает сообщение только при установленном бите 0 текущего flags: уменьшается индекс последнего сообщения с переходом −1→9, пересчитывается следующий индекс, обнуляются flags и первый байт текста. Сам индекс записи и старый хвост строки остаются прежними.

Высота, абсолютная разность и направление прокрутки используют исходные signed 32-битные операции. Их нельзя пересчитывать по числу LF либо хранить как производные Float-значения при проверке точного состояния.

## Границы текущего блока

В [SourceEvents](../../scripts/source_events.gd) реализованы F42/F43/F44/F45/F46/F48/F49/F50/F51/F54/F55/F56. F49 — внутренний путь освобождения, а F47/F52/F53 и F41 остаются отдельными продолжениями. Логические узлы ограничены 512 последовательными идентификаторами без повторного использования; их транспортное generation=1 не выдаётся за дополнительное поле исходного 32-байтового узла. Окружение ограничено 2..256 DWORD; дополнительные байты получают явно объявленную native-политику A5, а не вымышленную исходную инициализацию malloc.

[SourceEventServices](../../scripts/source_event_services.gd) проецирует единственный Root/банк в Events, Messages и Player. Во вложенном Player→F48 возвращаются все записи банка, а локальные владельцы дерева/арены/очереди сохраняются отдельно. Пакет F349 должен быть явным 48-байтовым witness: binder сверяет только доказанные слова вызывающего места и помечает прочие как opaque. Прежний Effects-контекст сейчас используется для проверки общего состояния; это не доказательство подключения всей цепочки повреждений. В [State](../../scripts/source_event_services_state.gd) конфигурация и последующие состояния имеют один канонический JSON-вид; фиксация проверяет экземпляр владельца, ревизию, поколение и повторное исполнение холодного witness.

Signed индекс F61 передаётся во вложенный F48 как исходное 32-битное слово (`index & 0xffffffff`); отрицательное представление аргумента в Player не меняет ключ события. Обратная запись наблюдения сохраняет исходный контракт Player, включая обнуление временного индекса после возвращения.

Полная F41 VM, интерпретация всех FF-шаблонов, графический UI и остальные объявленные обработчики не следуют автоматически из переноса диспетчера и очереди. Расширение Root за нынешние 16 КиБ и таблицы миссий требуют отдельной привязки к DOS-ресурсам. Изменение идентичности переиспользованного слота должно проходить через один банк и объявленную политику поколений.

Нативные эталоны выполняют сверенные исходные инструкции через исследовательский ELF64 ABI-адаптер. Это не запуск неизменённого IA32-файла на Android. Метаданные предполагаемой сборки 0.29/code54 и фактическое изготовление APK подтверждаются отдельно; они не являются доказательством подключения всех новых ядер к Main.
